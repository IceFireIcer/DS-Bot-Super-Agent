# Super-agent v2.1 实施票与功能层级

2026-11-03 用户在审计及功能父票方案后明确将决定交给代理；据此采用修订并发布。

状态：v2.1 的 14 个功能父票和 55 个原始实施票已发布并从 GitHub 回读核验；2026-11-12 在 T55 下派生 T56–T58 三个验收前置子票，并新增 T59–T60 两个产品接线条目。完整可点击索引见 [实施入口](tickets.md)，原始发布证据见 [publication.json](publication.json)；T59–T60 尚未发布到 GitHub。

## 公共完成条件

- 每票交付一种可演示或可由公开命令/查询验证的行为；相应持久事实、接口、最小用户入口和测试随行为交付。基础票先扩展独立新核心入口，正式切换留到迁移票；不会在前期同时消费旧核心的生产输入。
- T01 是必要的最小装配与扩展前置，交付可查询的持久接单回执；T02 形成第一条真实 DSH mock 模型闭环，T03 增加实际本地工具执行。不会先建完数据库层、再建完整服务层、最后补全部界面。
- 每票按一个新上下文内的一项行为限定范围。验收只扩展本票行为及已有依赖，不要求提前完成后继票；跨阶段场景拆成各票的可验证部分，最终由 T55 汇合。发现实际范围超出时先拆票，不能用未实现后继作为完成理由。
- 前置仅列直接阻塞；发布时使用总规格 → 功能父票 → 实施子票的原生层级，T54/T55 直接属于总规格，使用 GitHub 原生 blocked-by，发布顺序为拓扑顺序。所有实施票使用 ready-for-agent，规格仅通过已授权的审计补充修订为 v2.1；拆票阶段不再修改或关闭父规格。
- D/A 编号引用父规格的实施决定与验收场景，用户故事编号引用其 User Stories。覆盖表示计划承担相应部分，不表示现有实现或运行验收已经通过。
- 公共完成条件适用于每票：只用 DSH 公开 API；不读取或写入用户自有 DSH 数据进行测试；使用 mock 模型及隔离数据、空闲端口，停止本轮服务；移植兼容许可代码时记录来源与 NOTICE；产品文案源语言为英文。
- 各票通过公开 Engine 行为及适用的来源/存储/Session/执行契约验证；完成必要的单测、类型检查、生成一致性、lint 和适用的 host smoke。界面行为同时提供真实界面证据；原生/真实模型/外部信道/第二设备验收分别报告。未经验证的工具组合明确拒绝。
- 初始公共存储合约支持显式异步 Tx、稳定 ID 和后端替换；每次 schema 或命令扩展同步维护已经实现的后端及契约，不能把后续行为遗留为仅 SQLite 可用。T42/T43 无需等全部业务票完成才开始。
- 网络账号、真实模型、第二设备和托管环境是对应验收的运行前提，在实施相应票时收集授权与配置。协议替身可用于开发，不能据此关闭要求真实环境证据的验收项。
- 超时、重试、容量及资源预算在对应票的声明负载下实测并记录，不能无限重试，也不能照搬文章或早期实验数字；T54 汇总比较，不能替代各票当时的预算验收。
- 每张实施票只有一个功能父票；父票完成需全功能验收，子票可引用其他功能的具体前置。不把整个功能父票作为子票阻塞方；跨功能 group 可能有双向引用，不能转成整组串行。

## 实施票

### T01 建立隔离实例的持久接单与查询闭环

- 父票：G01。
- 前置：无。
- 交付：在独立新核心实例提交一个明确请求，获得可重查的接单回执和 pending 工作，旧核心继续保持原有运行入口。
- 决定：D01、D02、D03、D04、D06、D10、D13、D18。
- 场景：A01、A02、A11、A18、A32。
- 用户故事：13、18、71、72、74、75、76。
- 验收：
  - [ ] 通过公开插件装配的 TypeScript 核心与 SQLite 异步 Tx，受信桌面来源形成带 Instance 身份的 Trigger、Decision、Mandate、Ticket 和待执行意图；本票尚不启动 Worker。
  - [ ] 同命令/同事件重试返回原回执，同 ID 异文拒绝；提交前故障无接单事实或执行，重开进程可查询已提交回执。
  - [ ] 提供最小提交与查询入口，展示来源、授权范围与 pending 原因；不同实例不可互查。先固定明确请求和本地环境，未实现能力不开放。
  - [ ] 建立隔离 mock 运行命令、兼容性/许可记录和本票负载基线；保留现有测试入口，独立数据不触及旧调度或用户资料。

### T02 通过原生 Router 与 Worker 返回首个结果

- 父票：G01。
- 前置：T01。
- 交付：在统一对话提出一个无需外部工具的请求，由真实 DSH Router/Worker Session 执行并返回确认与结果。
- 决定：D01、D02、D07、D10、D12、D17。
- 场景：A01、A13、A27。
- 用户故事：1、3、64。
- 验收：
  - [ ] 只通过 DSH 公开创建/运行接口，Router 使用有限工具，Worker 读取原始请求；mock 模型贯穿真实 loop，不自造模型运行时。
  - [ ] Ticket 只有一个有效 Assignment，Session/报告独立保存；持久意图在提交后启动，最小 Outbox 将确认和有 ready 依据的结果送回原消息位置。
  - [ ] 统一聊天入口能看见 pending、running、ready 和结果依据；idle 不被当作完成，未完成内容不得当 result。
  - [ ] 重复入站不会产生第二个 Worker 或重复交付；本票只验正常路径，更完整的恢复窗口分别由 T15—T20 承担。

### T03 在绑定的本地工作目录完成实际工具任务

- 父票：G01。
- 前置：T02。
- 交付：用户授权一个本地任务，Worker 在该任务目录完成文件读写、搜索和命令，并返回可核查产物。
- 决定：D01、D06、D14、D17、D19。
- 场景：A19、A27、A33、A36、A43。
- 用户故事：29、30、34、77、79、107。
- 验收：
  - [ ] Assignment 显式绑定本机 Environment，fs/subprocess/search 使用配套 scope，模型服务地址独立配置。
  - [ ] 读写、glob/grep 与命令观察同一份文件和目录；目录约束、已有权限和凭据保护映射到 Instance/角色/Environment。
  - [ ] 任务结果带产物和工具验证事实；两个隔离目录不混写，未支持工具组合明确拒绝，不使用全局 currentEnvironment。
  - [ ] Windows 隔离目录上完成一次实际命令与取消正常路径；失败状态不暴露凭据，不承诺异步作业或远端进程树语义。
  - [ ] 准备目录在同一执行环境检查，失败保留输出且不无限自动重试；setup/权限未通过不执行，显式重试不混入其他目录。

### T04 正确接收来源版本、删除与身份冲突

- 父票：G01。
- 前置：T01。
- 交付：两个来源实例出现同编号消息、编辑、删除或乱序事件时，用户仍能查询正确历史与当前内容。
- 决定：D02、D03、D04、D17。
- 场景：A01、A18。
- 用户故事：32、33、73。
- 验收：
  - [ ] 受信接收路径确定来源元组、Actor、Thread 和原生版本；正文伪造身份或越过接收范围被拒绝并留下原因。
  - [ ] 不可变事件与当前投影分开；较旧编辑不覆盖较新事实，同版本异文/不可比版本形成可查询冲突或 unknown。
  - [ ] 有证据删除形成 tombstone，迟到编辑不复活；删除内容不再供新接单或关联，也不自动撤销旧 Mandate。
  - [ ] 两来源实例同编号/同原生用户不串对象、订阅或准入权限，跨实例查询与历史标识歧义保持隔离。

### T05 对新请求进行有依据的批量研判

- 父票：G01。
- 前置：T02、T04。
- 交付：混合人类请求、噪声和机器人事件后，系统批量处理有授权的新工作，并解释拒绝或暂不可用的原因。
- 决定：D03、D04、D06。
- 场景：A02、A18、A37、A39。
- 用户故事：37、61、101。
- 验收：
  - [ ] 每 Thread 最多一个 Eval，期间到达候选进入下一批；不同 Thread 不被硬合并。
  - [ ] Gate 拒绝的新工作不调用语义层；批次逐项保存授权来源，背景消息不能借用更强请求取得权限。
  - [ ] Router 批量处理候选并保持响应；机器人与 CI 只能按推断规则候选，来源自身消息不循环接单。
  - [ ] 从实际交付 Router 时计超时，有界重排后显示 unavailable 并可重评；声明批次规模、超时与尝试预算。
  - [ ] 准入组合覆盖 receiving scope、名单、mention/direct、机器人与每条启用规则的判定；批量路由逐项拒绝不阻塞其他项，Router 忙时通知合并至后续 step。

### T06 跟进原工作并恢复自然结束的任务

- 父票：G02。
- 前置：T05。
- 交付：用户在自有讨论继续修改要求，原 Worker 采用新方向；自然结束后仍能在同一工作继续。
- 决定：D05、D06、D07、D09。
- 场景：A03、A05。
- 用户故事：5、17、62。
- 验收：
  - [ ] 已订阅事件先 fan-out，人类跟进成为稳定 Input，方向版本递增，正常情况下复用 Ticket/Assignment/Session。
  - [ ] Router 不能对仍有拥有者的事件重复 accept/attach/ignore/requeue，原 Mandate 不因跟进扩大。
  - [ ] 无交付 Thread 的 ready 可自然结束；自有 Thread 的合法人类跟进可恢复同一 Ticket，恢复前重验当前授权。
  - [ ] 人工 stop、等待人工等约束不会被自然恢复路径解除；每步可查询 Input 归属和方向版本。

### T07 处理多订阅、只读上下文与越界交回

- 父票：G02。
- 前置：T06。
- 交付：一条讨论服务多项工作时，各 Worker 可处理或交回消息，系统只在全部拥有者交回后重新分派。
- 决定：D03、D05、D06。
- 场景：A04、A38、A39。
- 用户故事：6、65、66、102。
- 验收：
  - [ ] 保存事件接收时的 fanout/owner 依据，后加订阅不追授所有权；显式 attach 有新决定记录。
  - [ ] 全部拥有者 handback 前不重新 Eval；交回携原因，不立即 attach 回刚交回的同一 Ticket。
  - [ ] context-only 只提供背景，不能取得消息归属、接单权限或恢复 ended Ticket。
  - [ ] 公开查询解释每个拥有者与交回状态；机器人上下文和新候选分别处理，不产生重复工作。
  - [ ] 提供人工退订/重评与 Worker 无关附加 Thread 操作，保护原始/绑定 Thread，退订不清已接收 ownership；受限跨任务 note 只传事实不授新权。

- 前置：T06。
- 交付：Worker 提出结构化问题，用户在对应消息处回答后继续，其他工作照常推进。
- 决定：D06、D07、D10、D17。
- 场景：A05、A09、A13。
- 用户故事：10、11、12、45、89。
- 验收：
  - [ ] Attention 关联当前问题与触发消息，UI 显示 waiting-human、下一步责任人和可操作回答入口。
  - [ ] 只有相应权限者的有效回答解除等待；重复/过期回答不唤醒错误工作或覆盖更新问题。

  - [ ] 问题回对应消息，否则回发起处；无关工作能独立运行，普通 progress 不外发。

### T09 持久停止本地工作并显式恢复

- 父票：G02。
- 前置：T03、T08。
- 交付：用户停止一项工作后它保持停止，明确恢复且重新核验授权后才继续。
- 决定：D06、D07、D09、D14。
- 场景：A05、A30。
- 用户故事：8、91。
- 验收：
  - [ ] stop 先持久撤销继续执行授权，阻止新副作用，结束当前执行安排并请求取消原本地执行。
  - [ ] 业务 stopped 与 stopping/实际取消确认分开显示，未核查本地执行范围静止不显示 cancelled。
  - [ ] CI、普通跟进与重启不解除 stop；明确 resume 重验授权后创建新代 Assignment，保留 Ticket/历史/目录。
  - [ ] 等待人工或未知本地副作用未解决时不能靠 resume 重做；迟到回调不恢复已停止任务。

### T10 调整策略和暂停处理而不丢失输入

- 父票：G02。
- 前置：T09。
- 交付：操作者修改准入规则、主动模式或暂停处理后，系统按新规则恢复且保留等待和停止约束。
- 决定：D04、D06、D12、D15。
- 场景：A05、A06、A17、A23、A37、A42。
- 用户故事：38、42、43、44、45、101。
- 验收：
  - [ ] 提供版本化 Policy 的 off/observe/auto 与准入配置；明确请求各模式均按原授权处理，observe 只记录 would-accept。
  - [ ] 规则变化使在途 Eval 失效重排，仅通知受影响 live Ticket；ended 恢复前重验，不强制取消全部工作。
  - [ ] 暂停继续接收记录，但暂停新 Eval、派发、Input 投递与外发；已有 turn 不自动中断，恢复修正超时。
  - [ ] UI 区分全局暂停、waiting-human 和 Ticket stop，来源正文不能改硬授权，不新增动作分级设置体系。
  - [ ] 准入表与名单同步配置纳入 Policy 版本；匹配规则流程/沟通条款不越硬授权，异步检查或同步后再次核验 revision，旧结果不覆盖人工新保存。

- 交付：两项独立任务并行，槽满时用户仍能修正已有工作并得到及时响应。
- 决定：D01、D08。
- 场景：A07、A39。
- 用户故事：2、52、103。

  - [ ] 在声明负载下记录并发数、受理/响应延迟与公平性预算，超限行为可重复验证。
  - [ ] 状态请求走受限命令，只对适用等待状态排队；Router 忙时突发报告/跟进在后续 step 合并，不能逐条重复模型调用或绕过人工停止。

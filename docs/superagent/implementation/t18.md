## 交付行为

Outbox 现在有独立的交付账本和可注入信道。确认、回答、结果与人工问题在入队时保存用途、依据、目标和 Effect 身份；`engine.getTicketDeliveries(ticketId)` 返回每条消息的 `pending`、`sent` 或 `dropped` 状态、尝试次数和原因。入队后的确认在派发前即可查到，不再把“已写本地记录”冒充平台已收到。

每条外发在派发前重新核查：

- acknowledgement 必须对应已接受的原始请求，并回到原事件与原 Thread。
- answer 必须对应本来源当前可信的人类问题，保存问题正文与明确 Worker fact，回到该问题所在消息。
- result 必须对应当前 ready report；停止或等待人工的 Ticket 不交付结果。
- attention 必须仍是当前 waiting-human 问题，并回到引发它的消息；已回答或已替代的问题记为 stale/dropped。

普通 progress 没有外发入口。重复提交继续依附同一确认身，不产生第二条消息。一个 Ticket 的 Outbox 按 lane 顺序执行，因此确认先于结果；不同 Ticket 使用独立 lane，局部失败不阻塞其他工作。

`DeliveryChannel` 是可注入契约：适配器返回 `success`、`transient`、`permanent` 或 `unknown`。临时关闭保持 pending 并保留原因；永久不可达记为 dropped；未知结果要求使用原幂等键 reconcile，没有 reconcile 时不盲目重发。本地预览默认使用 `localDeliveryChannel`，把隔离存储中的记录作为回执。

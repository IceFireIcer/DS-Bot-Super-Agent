## 行为

Thread 订阅区分 `worker` 与 `context`。worker 订阅让授权人类 direct/mention 消息成为 Worker Input；context 订阅只留下可查询背景，不取得 ownership、不增加方向版本，也不能恢复 ended Ticket。接收时 fan-out 的快照固定；后来新增的订阅只作用于后续事件，既有消息只能通过显式 `attachSourceEvent` 形成新 ownership 决定。

同一 Thread 可服务多个 Ticket。每个 Worker ownership 单独保存来源、Input、订阅、状态、原因和时间；Worker 可使用 `handback_input` 交回越界跟进。只要任一 owner 仍为 `owned`，人工 `requeueSourceEvent` 就返回 `OWNERSHIP_ACTIVE`；全部 handback 后，requeue 记录按 `pending → claimed → consumed` 生命周期推进，并创建新的 Trigger/Decision/Ticket 历史，不自动 attach 回旧 Ticket。Eval 崩溃恢复会释放没有 receipt 的 claimed requeue；已有 receipt 则消费并保留。

人工管理命令按 source instance + actor 隔离命令身份。`addThreadSubscription` 和 `removeThreadSubscription` 保存理由与退订决定；原始/来源绑定 Thread 不可删除，退订不清已接收 ownership。Worker 只能新增非必需订阅，并且只能移除同一 Assignment 添加的订阅；同一 Assignment 已经移除的 Thread 不能在同一执行期内反复重建。`addTicketNote` 只追加有序事实，不增加方向版本、ownership、Mandate 或执行意图。

`getTicketDirection(ticketId)` 公开订阅、Input、全部 fan-out、当前 ownership/handback、note、退订和 requeue 历史。`dismissEvaluation` 只能处理 `unavailable` Eval，按命令与 actor 去重，并追加不可覆盖的 dismissal 事实。管理记录、所有权与相关历史均声明 1,000 条查询预算。

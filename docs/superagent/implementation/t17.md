## 交付行为

接单现在同事务保存工作事实、notice、acknowledgement Outbox 和原命令回执。未配置适配器的意图保留 pending。公开 `engine.effects.list(cursor?)`、`receipt(id, generation)` 和 CLI `effects [--after <cursor>]` 提供可查依据。

`AsyncTx` 增加实例身份、更新、删除及按 ID 的有界游标扫描；`Storage.reconnect()` 创建独立连接。未知 COMMIT 通过新连接的写事务先取得 SQLite 写锁，再按原 command ID 和版本化指纹查回执；回执不存在才在同锁下重算。锁或连接不可用时保留 COMMIT_UNKNOWN。确认回滚的序列化失败/死锁最多重跑整个数据库事务三次；锁超时不会宣称已经接单。

Effect 使用稳定逻辑键、不可复用行 ID、payload generation 和单次 claim token。更新保留排队位置；成功、失败、延期都核对这些身份。完成键保留去重依据，显式取消后重建取得新身份。瞬时失败有界退避，永久失败和重试耗尽保留可查原因。relay、notice、outbox 各自按 scope 排序；unknown 只阻塞所属 lane。执行、结果查证均在事务外，超时或异常不盲目重发。平台适配器获得稳定幂等键与取消信号，必须支持相应幂等/查询能力；数据库不保证跨平台 exactly-once。

启动扫描与周期扫描补齐丢失 wake。默认容量 1000（硬上限），三次尝试（最多十次），1 秒起始退避、60 秒封顶，10 秒适配器超时，1 秒扫描周期。扫描枚举最多十页，每页 100 条；每次 claim 在自己的写锁中按同一 1000 条预算复查更早的活动操作。failed 仍占用容量直至显式取消。未配置的适配器保留 pending。

SQLite schema v2 保留既有 records 格式，接受空数据库与 v1 升级，拒绝不支持版本、异常表结构和非空未版本化库。升级前用 SQLite backup 保存一致副本并验证完整性和版本，版本变更在写事务中提交。恢复备份不撤销外部动作；Session 备份由对应后继票交付。

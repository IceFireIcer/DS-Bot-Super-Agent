## 行为

来源事件携带受信 `authorId`、`authorKind` 和 `addressing`。可选 `IntakePolicy` 固定接收规则、名单、proactive 模式、批次大小、每 Thread 队列、超时和尝试预算。每条候选先执行 Gate：来源 scope、作者名单、self-message、启用规则和 explicit/inferred 强度都留下 `ruleResults`、`matchedRules`、拒绝原因及 `semanticCalled`。Gate 拒绝项不调用语义 assessor。

明确的人类 direct 请求按 explicit 规则直接创建带 policyVersion 的 Mandate；机器人/CI 的 mention 候选在 `auto` 模式才进入 assessor。`off` 与 `observe` 保留拒绝或 would-accept 事实，不调用 assessor。assessor 返回逐项 accept/reject、reason 和 evidence；缺失、重复、越权 event 或超出预算的结果按 unavailable 处理。

每个 Thread 同时只有一个 running Eval；同 Thread 的后续批次持久为 queued，另一个 Thread 可独立运行。Router Session 由 DSH `NativeSessions` 持久化并串行调用；忙时连续排队的 notice 会合并到下一次 Router turn，每个 Router burst 最多合并 7 项并受 100 KB 输入预算限制，同时保留每个候选的独立工具闭包。没有被 Router 调用的通知保持 transient 并由 durable effect 重试。超时从 `onDelivered` 屏障启动，按有界 attempts 重试，耗尽为 unavailable。进程重启后过期或未交付的 running head 会恢复为 unavailable，显式重评可以重跑；策略版本变化同样允许重评。当前 source projection 在每项接单事务前再次核对，删除、冲突、unknown 或过期版本不能被批量接单。每候选接单各自事务化，单项队列/接纳失败不会提交半套授权或阻塞同批其他候选。持久 Eval 预检预留逐项最大 reason、evidence、item receipt 和聚合 receipt 列表的空间，超出 SQLite 单记录预算的批次会在分配和语义调用前拒绝；assessor 异常文本也按 UTF-8 字节上限收敛。

## 边界

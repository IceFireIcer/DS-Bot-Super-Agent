# T23：按版本配置角色、模型、提示词与技能

- Issue：[T23 / #51](https://github.com/IceFireIcer/DS-SuperAgent/issues/51)。依据：规格 v2.1 D01、D06、D12、D17，A17、A40、A42。
- 固定实施基线：`867091b`。

## 交付行为

新增 `engine.getRoleConfig()` 与 `engine.updateRoleConfig({ commandId, expectedRevision, roles })`。配置包含 Router 与 Worker 两个角色；每个角色可设置名称、provider/model 路由、指令和技能列表。默认配置在首次读取时按 revision 1 持久化，后续更新写入 revision 历史。

保存使用 command ID 去重与 `expectedRevision` CAS：

- 过期 revision 返回 `CONFIG_REVISION_CONFLICT`，不覆盖较新保存；调用方保留自己的草稿。
- 同一 command ID 重放返回原 revision。
- 未知键、未知占位符、重复/保留技能名、超长名称或指令均拒绝，不静默截断。

模型路由在每次真实请求前应用：Router 与 Worker 的下一回合使用当前 revision 的 provider/model；已启动的回合保留自己的 AgentOptions。每次 Worker 与 Router 请求写入 `role-config-use`，记录 Session、角色、revision 和两条模型路由；`engine.getRoleConfigUses(sessionId)` 可回看该 Session 实际使用的版本。配置变更不会改变 Gate、Mandate、工具、Environment 或设备权限。
`updateRoleConfig` 支持可选的异步 `verify` 回调；检查完成后仍以提交事务内的 `expectedRevision` CAS 决定是否保存，因此验证期间发生的较新保存不会被旧检查结果覆盖。

允许的提示词占位符是 `{{goal}}`、`{{constraints}}`、`{{evidence}}`；渲染时分别替换为当前请求目标、Ticket 约束事实和证据卡片说明。技能名只进入角色提示，不会自动增加工具；未授权工具仍不可用。

## 验证与范围

2026-11-09，Windows x64 / Node 25.4.0：新核心全量通过，typecheck、build、lint 通过。

新增回归覆盖：

- 默认 revision 1；更新到 revision 2；重放、冲突、未知配置字段、非法占位符、保留/重复技能名和超长内容。
- 新 Engine 从同一存储读回 revision 2。
- 真实 mock 请求使用新的 Router/Worker 模型名，系统提示包含渲染后的指令与技能列表；Worker Session 的 use 记录关联 revision 2。
- 延迟验证与并发较新保存相遇时，旧保存返回 `CONFIG_REVISION_CONFLICT`，存储保持较新 revision。
- 提示词恶意声明不能增加 Worker 工具（工具集合由 Execution 决定）。

本票没有实现界面表单（T24 负责监督/设置入口）或异步模型/账号检查；没有真实模型质量或凭据回看验收。

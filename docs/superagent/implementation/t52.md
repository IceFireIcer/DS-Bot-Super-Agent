## 已交付

### 1. 原子 activation manifest

- 新增公开 `ds-superagent/activation`：`Activation.activate`、`releasePending`、`status`、`listReleases`、`gate`。
- `activate` 先执行 T51 `Switchover.recheck`，要求 `quiesced`、blockers 为空、两次 checkpoint digest 相同、stop/restart/entry 证据齐全，并由当前进程持有 gap intake；随后重新读取已发布 archive 与 source/mapping digest。
- `newEpoch` 必须在 `host-lease` 中仍是当前、未释放、未过期，且 owner 是当前进程；旧 home 锁仍不能替代。
- 一个 `commandTransaction` 同事务写入 `activation` manifest、`activation-command` 回执、`activation-history`、每个 gap input 的 `activation-gap` release 意图，并把 `switchover` 记录切到 `active`、解除 entry isolation。未达 quiesced、archive 变化、Host epoch 变化或 buffer 在最终 recheck 后变化都不能激活。
- manifest 保存 activation ID、batch、epoch、`currentCore: ds-superagent`、switchover ID、archive digest/state revision、最终两个 checkpoint digest、gap 计数、旧 review 项和旧 intake entry。
- 同一 activation 再次提交按原 `activation-command` 对账；同 batch/epoch 的新 command ID 也写入回执；不同 batch/epoch 是 `ACTIVATION_CONFLICT`。COMMIT 应答未知由 `commandTransaction` 按原命令重读。

### 2. 仅当前入口可写接受与 Effect

- `Engine.setActivationGate` 安装 `Activation.gate()`；插件配置 `activationGate` 会在 `apply` 时自动安装。
- gate 在每次命令事务中读取 activation manifest 与 Host lease，要求 `active`、epoch 相同、lease owner 是当前进程、未释放且未过期。
- `Engine.receiveSource`、`assessSourceBatch`、所有 `accept` 路径与 `Effects.enqueue` 都经过 gate；未激活时返回 `CORE_NOT_ACTIVE`，不会留下接受回执或 Effect 意图。已存在 command receipt 的 replay 仍可读取原结果。
- `Effects` gate 同时阻止未激活时派发，保留原有 payload canonical 快照语义（先快照，再等待 gate）。

### 3. gap buffer 按原 ID 释放

- 激活事务为每个 gap input 创建 `activation-gap`：
  - `held` → `pending`；
  - `legacy-accepted` → `skipped/OLD_ACCEPTED`；
  - `quarantined` → `skipped/QUARANTINED`。
- `releasePending` 只处理 pending/unknown；稳定 release command 为 `release:<activationId>:<gapId>`，外部接受适配器必须按该 ID 幂等。旧已接受和 quarantine 不会被当作新工作。
- 成功释放后同时更新 `activation-gap` 与 T51 `switchover-gap-input`：后者变为 `released`、`dispatch: released-to-current-entry`；`Switchover.status.buffer` 增加 `released` 计数。
- 一次调用对每个 ledger 至多尝试一次；`releasing` 在下次启动先按“结果未知”重置；未知/失败保留 attempts/reason，达到上限转 `failed`，不会无限重试。
- 激活成功后 T51 gap intake 记录为 `active`，`ingestGapInput` 返回 `CORE_NOT_ACTIVE`；同一 host 进程会 detach listener。

### 4. 真实退出与隔离应用演练

- `activation.test.mjs`：
  - 激活前 `submit`/`receiveSource`/Effect 全部被 gate 拒绝；激活后 held 输入经原 gap ID 变成工作，legacy-accepted/quarantine 只 skipped；
  - 未 quiesced 拒绝；
  - release 丢应答后按原 release command 重试，Ticket 仍只有 1 个；
  - activation COMMIT 丢应答按原 command 对账；
  - 隔离目录上旧 `work:old` 仍可读，activation 后新 work 创建 Session，人工 stop 持久；

- `activation-process.test.mjs` + `activation-crash.mjs`：真实旧 launcher/receiver 与真实 activation 子进程；旧进程停止、launcher 改名、T51 quiesce、activation 提交、外部接受写 marker 后子进程直接退出。父进程看到唯一 active manifest、release ledger `releasing`、marker 仅 1 条；非 lease owner 的 `releasePending` 被拒绝，证明不会由第二进程重复派活。

## 使用方式

```js
import { Activation } from 'ds-superagent/activation'

const activation = new Activation(storage, instanceId, switchover)
engine.setActivationGate(activation.gate())

await activation.activate({
  batchId,
  commandId: 'activation-2026-11-11',
  newEpoch: (await engine.acquireHost()).epoch,
  legacy: oldCoreAdapter,
  release: {
    release: async (input, context) => {
      const receipt = await engine.submit({
        commandId: context.commandId,
        eventId: input.id,
        text: input.text ?? 'Buffered gap input.',
      })
      return { ticketId: receipt.ticketId, receiptId: receipt.acceptedCommandId }
    },
  },
})
```

## 边界

- **activation 与 T51 holder 同进程。** `activate` 要求 `switchover.status.isolation === held-by-this-process`；跨进程接管 gap entry、真实旧核心服务重启和逆向交接属于 T53/T55。
- **不迁移用户数据。** 测试只读虚构 archive 和隔离临时目录；没有读取或写入用户 DSH/应用数据。真实用户数据迁移仍需单独授权。
- **真实应用范围。** 使用隔离目录、真实旧 receiver/launcher 进程、SQLite、mock 模型新 Session；没有运行 Electron 安装包、真实产品旧团队或真实外部信道。
- **release 适配器由当前核心提供。** `ActivationRelease` 必须按稳定 release command 幂等；生产接入 Engine 或其它入口时不能用新 ID 盲重试。
- **跨 epoch 的 activation 回退不在本票。** 新 Host epoch 改变后需先对账并逆向交接，属于 T53。

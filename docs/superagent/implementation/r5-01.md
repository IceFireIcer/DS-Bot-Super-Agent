## 交付行为

独立产品默认启动 `ds-superagent` profile，在独立 `DSH_HOME/core/state.sqlite` 保存业务事实。Host 按受信 Instance 配置创建一个 Engine 和 NativeSessions；窗口只附着，不根据 UI Session 创建核心。Main、Router 的逻辑身份和 Session 绑定持久化，同一 Instance 的多个窗口共享 Main 历史。

Main 使用单独模型 route 和公开 DSH Agent loop。主对话通过 Engine 的 `openMain`、`sendMainMessage`、`getMainConversation` 接口访问；输入身份、指纹、处理状态、回复身份和分页顺序均持久。重复异文拒绝，跨 Instance 读写和未授权 actor 拒绝，普通聊天不创建 Ticket。每个 Main 回合记录角色配置版本和三层 route。

业务库和 DSH Session 分别持久化。已完成的原生回合若尚未投影到业务历史，刷新按原输入身份读取原生历史并幂等补写回复，不再调用模型。中途退出但没有完成回合的队列恢复由 R5-08 继续；这里不宣称跨库 ACID。

新入口复用现有 `ChatRows`、聊天气泡、品牌、主题和输入模块，通过公开 UI slot 挂载产品数据。产品 API 为 `/api/product`。新入口不加载旧 roster、dispatcher、Bot 工具或 `/api/bot`，也不自动导入旧团队或用户 DSH。原生 Session 控制器通过公开 service isolation 与产品 Gateway 隔离，HTTP 路径先规范化再拒绝，Session 列表返回空投影；原生 WebSocket 读写同样不可访问，主对话使用产品查询。

Main 初始仅有 `delegate_work`、`query_work`，明确返回 `DELEGATION_UNAVAILABLE`。没有文件、Shell、浏览器或团队治理工具；真实工作委托由 R5-02 接通。模型未配置时显示不可用，不冒充模型回答。

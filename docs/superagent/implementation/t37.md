# T37：在远端保持附件、spill 与技能路径一致

- Issue：[T37 / #65](https://github.com/IceFireIcer/DS-Super-Agent/issues/65)。
- 实施基线：T36 提交 `cc06d40`；首个交付提交 `9881500`，双轴审查修复随后续提交记录。
- 规格：v2.1 D01、D11、D14；A16、A19、A33；用户故事 29、72。

## 已交付

- 新增环境资产引用 `EnvironmentAssetReference`：`attachment`、`artifact`、`spill`、`skill` 四类；引用携带 `environmentId`、环境 kind、环境 fingerprint、远端 `deviceId`/`deviceIncarnation`、稳定 ID、字节数、SHA-256、可选名称/相对路径。引用 ID 不是 Host 路径：文件类为 `file:sha256:<digest>`，spill 为 `spill:<jobId>:<stdout|stderr>`，技能为 `skill:<name>`。
- 本地与设备各有一个部署自有 verbatim 资产库（`assetsPath`），按 `Instance + Environment` 的哈希命名空间隔离。文件保存为内容寻址对象，最大 65536 字节；读取按字节窗口分页并校验完整对象摘要。两个 Environment 共用同一 assets 根也不能凭 digest 互读。
- 长输出 spill：本地子进程和设备作业都保留完整流（上限 1 MiB）；spill 引用记录当时的 durable 前缀长度与 SHA-256。读取按 1–65536 字节分页，先验证前缀摘要再返回窗口；超过预算或上游未保留完整流时明确返回 `SPILL_UNAVAILABLE`/`ENVIRONMENT_UNSUPPORTED`，不把 bounded tail 冒充全文。前台 `run_command` 在截断时也返回 `spills.stdout`/`spills.stderr`。
- artifact 引用：`PreparedEnvironment.artifact()` 在原有 `path/bytes/sha256` 之外返回环境绑定的 `reference`。读取时按相对路径 + 前缀摘要验证；路径内容被替换后返回 `REFERENCE_STALE`，不会读取同名 Host 文件。
- 技能：通过公开的 `@deepseek-ai/dsh-skill` 注册表与 `@deepseek-ai/dsh-skill-filesystem` provider 映射。本地环境在配置 `skillsPath` 时只扫描该自定义根（`includeDefaultRoots: false`，不读用户 `~/.dsh`/`~/.agents`）；设备 daemon 也挂载同一公开 provider，并通过协议提供 `skill.list`/`skill.get`。技能正文按名字加载、计算摘要、按字节分页。
- Worker 工具：`save_attachment`、`read_asset`、`list_skills`；`read_job_output`（仅父 Worker 的 job 工具）把后台作业的完整输出转为 spill 引用并读取第一页。子代理通过 `childTools` 继承同一 bound Environment 的 `save_attachment`/`read_asset`/`list_skills`，不继承 Router、交付或父作业工具。
- 不支持组合不启用：`save_attachment` 只在 attachments 可用时暴露，`list_skills` 只在技能根可用时暴露；`read_asset` 保留给 artifact 等无需资产库的读取路径，具体类型不可用时按类型列出缺口。缺口名称包括 `local-asset-store-unconfigured`、`device-asset-store-unconfigured`、`local-skill-store-unconfigured`、`device-skill-store-unconfigured`、`attachment-image-admission-not-implemented`、`spill-stream-unavailable`、`environment-offline`。
- 公开入口：`Engine.getEnvironmentCapabilities(environmentId)` 返回 attachments/spill/skills 的支持状态与缺口；`Engine.saveEnvironmentAttachment({ commandId, ... })` 以稳定 command ID 幂等保存；`Engine.readEnvironmentAsset({ environmentId, reference, offset?, maxBytes? })` 先重新 prepare/核验原 Environment，再按引用读取，断连后由原设备身份恢复。
- 远程协议在 v3 上增加 `file.readRange`、`asset.save/read`、`skill.list/get`、`command.spillInfo/spill`；pairing/status 同时声明 `assets` 与 `skills` 能力。设备状态文件不保存 Host 会话；资产与技能根都是部署目录，不能位于暴露的工作目录内（资产）或默认为空（技能）。

## 边界

- 附件只支持 verbatim 文件；图像规范化/限制仍属于未实现的 `dsh-attachment` 组合，读取图像字节会走 base64 而不是模型图像块。
- 技能发现遵循公开 filesystem provider 的一层规则：`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`；不递归、不读取用户 DSH/agents 根。技能删除后按名字读取返回 `NOT_FOUND`。
- 资产对象不自动回收；spill 在设备端超过 1 MiB 后丢弃并记录 `stdoutSpillDropped`/`stderrSpillDropped`。本地 spill 在作业结束后复制进 assets 根，运行中的本地作业只有 bounded tail 可读。
- `assetsPath` 与 `skillsPath` 是部署配置；设备没有资产库时附件/spill 明确不可用，没有技能根时技能明确不可用。远端 artifact 仍依赖同一绑定目录内的相对路径与摘要证据。
- 实时双写、双向交接、跨 Host 共享资产库和资产保留策略不在本票；分别留在 T39/T44/T45 及后续清理票。

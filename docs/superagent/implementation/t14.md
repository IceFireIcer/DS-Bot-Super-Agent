# T14：交付验收时释放执行槽并管理预览服务

- Issue：[T14 / #42](https://github.com/IceFireIcer/DS-SuperAgent/issues/42)。依据：规格 v2.1 D07/D08/D14，A09/A14，用户故事 15、70。
- 固定实施基线：`2636100`；实现提交：本票提交。
- 公开测试边界：`Engine.conversation`、`listSlots`、`listJobs`、`getJob`、`listPreviews`、`getPreview`、`cancelPreview`、`listSubagents`、`stopTicket`、`resumeTicket`，`Jobs` 与 `Previews` 契约，同源 chat 的 `/previews`、`/preview`、`/cancel-preview`，以及真实本地子进程、真实 DSH 子 Agent 与 mock 模型的原生集成。未使用真实模型、外部账号、第二设备或用户 DSH 数据。

## 行为

Worker 通过 `keep_preview` 显式把一个**本 Assignment、本代次正在运行的托管 job**保留为验收预览。工具要求 `jobId`、有界 `purpose` 和一个相对 `artifact` 路径；artifact 通过既有 `BoundLocalEnvironment.artifact` 读取，记录路径、字节数与 SHA-256。不是本 Ticket、不是当前 Assignment/generation、已结束或不是本进程持有的 job 都会被拒绝；工具在 `report_ready` 或 `ask_human` 后密封，不能把事后生成的进程冒充预览。每 Ticket 最多保留 `jobs.maxPerTicket` 个待处理预览（running/cancelling/unknown，默认 4），由独立的 `preview-pending` 索引在创建预览的同一事务内检查；预览从执行工作索引移除后可以继续启动新的托管 job，但待处理预览不会无限积累。终态预览仍是审计证据，查询有界为最新 100 条，不会因历史过长而让 `conversation`/`listPreviews` 失败。预览不另起进程系统，仍使用 T12 的 `start_command`、句柄、输出与取消路径。

ready 或 `waiting-human` 交接时，执行槽在同一事务里释放，普通后台 job 以 `assignment-ended` 取消，子 Agent 走 T13 的 `agent.cancel({ kind: 'parent' })` + `whenIdle()` 清理。预览从 `BackgroundWork` 的执行 job 索引中移除，并清除 T12 的 `waitMs` 定时器，因此不占槽、不占每 Ticket job 预算，也不受 30 分钟 job 等待限制。其他后台工作仍按原规则结束；预览的自然退出写成 `exited`，带退出码，只作为验收事实可查，不会排 relay 或唤醒 Worker。停止路径（`stopTicket`、停止跳过分支）把预览 job ID 一并纳入取消与确认集合。

`engine.listPreviews(ticketId)`、`engine.getPreview(ticketId, previewId)` 和 `conversation(ticketId).previews` 返回预览 ID、Ticket、Assignment、generation、Environment、`jobId`、命令、purpose、artifact、状态与 `holdsSlot: false`；`conversation.reports` 仍提供 ready 交付的完整 artifact 与 tool facts。`cancelPreview({ commandId, ticketId, previewId, reason })` 是受信 actor 的幂等取消命令，只终止本 Ticket 的托管预览句柄；同源 chat 提供 `GET /previews`、`GET /preview`、`POST /cancel-preview`、`POST /resolve-preview`。清理只在观察到进程范围静止后写 `cancelled`；观察不到、或 Host 重启后已无句柄时写 `unknown`、`pendingConfirmation: true`，不会伪报已停止。`resolvePreview({ commandId, ticketId, previewId, reason })` 只接受 `unknown`，由人确认后写 `resolved`；当前 Host 的 stop 若只因该预览而停在 `stopping`/无确认的 `stopped`，解析会补上 stop 确认。旧 Host 的 stop 不会被这次解析伪造成已确认，T09 的 `CANCELLATION_UNCONFIRMED` 屏障仍保留。

`conversation(ticketId)` 新增两个独立事实：`stage` 为 `idle`、`draft`、`ready`、`waiting-human`、`stopping`、`stopped`、`ended` 或 `pending`，`lifecycle` 为 Ticket 自己的 `open`/`ended`。当前 ready report 即使已投递并结束 Ticket，仍保持 `stage: ready`，因此 ready 与 Ticket 结束是两个可分别读取的事实；没有当前 ready/waiting 的已结束 Ticket 才显示 `stage: ended`。ready 本身不创建新的 Assignment、不重跑副作用，也不重复交付。重复查询 ready Ticket 只返回现有 report、message、job/subagent/preview 事实。

## 生命周期取舍

规格原型把预览描述为“可保留到 Assignment 结束”。本核心的既有实现已经在 ready/问题交接时把当前 Assignment 置为 `ended`；若在这里直接照搬“Assignment 结束即清理”，验收预览会在用户看到之前被终止。本票因此采用明确的最小适配：**预览是 Assignment 结束清理的显式例外**，其生命周期为显式 `cancelPreview`、Ticket stop、自然退出或 Host shutdown。普通 job 与子 Agent 的 Assignment 清理不变；预览仍带原 Assignment/generation/Environment 归属，因此进程来源可逐项查询，不会被别的 Ticket 或用户自有进程误杀。`resumeTicket` 在活动预览仍在时返回 `PREVIEW_ACTIVE`，要求先显式取消，避免恢复动作静默丢弃验收资源。该取舍记录在此，后续若引入独立的 review Assignment 状态，应迁移这项规则而不是隐式改变用户已看到的预览生命周期。

## 边界

本票只接受本核心通过 `start_command` 启动的托管 job，不枚举、发现或终止用户自有进程，也不实现远端预览、端口探测、健康检查或自动 URL 分配；预览是否真正提供可用页面仍由配置命令本身负责。它不替代 T15–T20 的真实来源/外部交付、T54 的性能比较或正式部署验收。真实模型、外部信道与第二设备仍待对应票；界面未改动，验收入口是公开 Engine 查询与同源 chat 路由，因此本票不附界面截图。

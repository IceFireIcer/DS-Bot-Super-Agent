# T43 双轴审查

- 基线：`1de4b86`；两个独立只读子代理分别完成 Standards 与 Spec 审查，主代理修复并复验。

## Standards

- **修复：** 新增本审查记录，消除实施索引中指向不存在文件的证据链接。
- **修复：** 重复的失败后租约释放与 writer 组装收敛为 `releasingOnFailure` 与 `writerFor`，create/open 不再各写一份。
- **修复：** `leasePid` 改名为 `leaseBackendPid`，注释说明本机 PID 在跨 Host 共享后端中没有意义。
- **修复：** PostgreSQL 测试夹具新增 `createDatabase()`；`newStorage` 与 Session 测试只创建数据库名，不再顺手打开未使用连接。
- **修复：** README 明确 PostgreSQL 事务回调抛出的 `CoreError`/领域错误原样透传，只有 SQLSTATE 服务器错误与连接失败才由存储层翻译。
- **修复：** `acquireWriterLease` 的 close 竞态用 `handedOff` 标记，避免已经归还的连接在 catch 中被二次 release。
- **保留判断：** `Storage.acquireWriterLease` 在 create/open 路径的分支是显式后端能力检查；再抽一个 writer-authority 对象只会增加一层转发。租约连接本身属于 `PostgresStorage` 的连接资源，保留在同一模块创建和回收，避免连接池生命周期被拆散。

## Spec

- **修复：** `append`/`flush` 收到 `COMMIT_UNKNOWN` 时保守标记已物化，`close` 不再删除可能已经提交的 header；新增 after-commit 代理测试，确认换直连后端仍能读回事件与 header。
- **修复：** 事务内 `assertWriter` 与 `closeOnce` 都重新检查租约 active；真实 `pg_terminate_backend` 后 append 与 close 都抛 `SessionOwnershipLostError`。
- **修复：** 新增真实 PostgreSQL 触发器让 `session-meta` 更新失败，覆盖 flush/close 的真实服务器故障、失败期间仍持有写权及移除故障后的继续写入。
- **修复：** 新增业务事务回滚测试，确认 `session-store` 日志与业务 Instance 命名空间互不影响。
- **修复：** 新增公开 DSH loop 的构造后缀持久失败测试，确认不广播 `session/created`，且 `stat`/`list` 无残留。
- **保留判断：** `PostgresStorage.transaction` 对非服务器错误的透传是 T43 的必要前置修正；否则 `SessionOwnershipLostError` 等 DSH 领域错误会被翻译成 `STORAGE_ERROR`，T15 契约无法实现。T42 的 PostgreSQL 业务测试与全量回归仍通过。

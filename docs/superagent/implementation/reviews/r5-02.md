# R5-02 双轴审查

- 基线：`b89b5114b3909340c93c1052ffd03c02724b7057`。
- 范围：Main 委托、本地 Router/Worker 执行、持久回执/更新/结果、主工作卡与 R5-02 验证。
- Spec：GitHub #94 与 `docs/superagent/spec-r5.md` 的 R5-D01—D06、D12—D13。

## Standards

复审确认首轮发现均已处理：有限状态统一为 `MainWorkStatus`；产品 Host 的初始化失败和关闭共用释放顺序；测试适配器命名反映三层角色；Main 更新按主回合忙碌状态 defer，并将取消信号传到 DSH Session。持久通知回合按原 ID 对账；没有终止事件时递增尝试并使用新消息 ID 恢复。无剩余标准问题。

## Spec

WorkBrief、Receipt、Update、Outcome 均版本化并持久保存；Main 只提交工作简报，Router 建立唯一 Ticket 并沿用同一 Router Session。Worker 的 ready 结果由当前 Assignment 报告和文件读回证据确认。Main 仅收到有界接单/结果更新，不读取 Worker transcript 或工具日志。成功更新写入产品主对话记录前，在同一业务事务内复核当前 Ticket、Assignment、ready report 与停止约束；工作卡始终投影 Ticket 当前状态，重试复用稳定委托身份。DSH Session 与业务状态分别持久化；若未来支持停止操作，Session 中已发送的历史更新不能跨库撤回，需由后续 R5-06 的停止通知表达新状态。本票不暴露停止写入口。

## Verification

本地验证和远端 CI 结果记入 R5-02 实施记录；该记录不把本票局部验收当作 R5 总体验收。

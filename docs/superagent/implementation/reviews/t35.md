# T35 双轴审查

- 审查基线：`5eb23d7`（T34）；T35 工作树增量。
- 规格：[T35 / #63](../issues/T35.md)，spec v2.1 D07/D09/D13/D14、A12/A20/A30/A33。
- 标准：[AGENTS.md](../../../../AGENTS.md)、[CONTRIBUTING.md](../../../../CONTRIBUTING.md)。

## Standards

首轮发现及处理：

- **离线 stop 无法在对账日志恢复后确认。** `reconcileRemoteStops` 只接受 `exited/cancelled`。已改为接受 `settled + recovery.rangeAlive = gone` 的范围静止证据，并新增真实 daemon 重启 stop 测试。
- **PID-only 恢复可能结束无关进程。** PID-only 不再标记 `live-process` 或 `signalable`；只观察存活，不发送信号，消失后记录 unknown 终态。Windows 覆盖该负例。
- **startup 远端扫描可能阻塞 Input recovery。** 新增独立 `remote-job` 索引，`remoteRecords` 只读远端记录；Input recovery 与远端对账分两个 try/catch，远端预算失败不会跳过输入恢复。
- **恢复的终态作业丢失 exit code。** `inspectRange` 暴露 exitCode/signal，Host 接管终态时写真实 exitCode；跨机验收覆盖退出码 0。
- **快照协议无版本标记。** 远程协议与 Host saved state 升为 v2；旧 v1 Host 状态明确拒绝。设备 job 文件仍接受 v1 记录并保留环境级访问兼容。
- **恢复记录/输出写入与快照存在竞态。** 输出先登记 durable write 再追加内存窗口；`inspect/cancel` 等 `writes` 和 `persisting` 后才返回快照。真实 Linux 重启验证 `started\n` 不丢。

复审修复：

- **v1 job 归属被伪装成 actor `''`。** 改为缺失 owner，不再对其他 actor 返回 `JOB_OWNER_MISMATCH`；Host 不把 `null` owner 当作“他人作业”，而是进入不可验证/提问路径。
- **空身份证据。** 不可观察记录的 device/incarnation/actor 从持久 remote 记录、已配置 Environment 和 trigger 补齐。
- **状态覆盖竞态。** `applyRemoteTerminal`/`markRemoteUnknown` 不再覆盖已确认的 `exited/cancelled`。

## Spec

首轮发现及处理：

- **后台 start 在 Host 记录前就发送请求，前台远端命令完全没有 JobRecord。** 已增加 `starting` intent：先提交稳定 job ID/owner/deadline，再开始设备命令；后台确认后运行，前台结束写终态。Host 崩溃窗口、离线 foreground stop 和原 ID 对账均有测试。
- **`statePath` 可选导致 incarnation/pairing 不持久。** 配置命令或 jobsPath 时强制要求 statePath；设备状态文件原子替换。
- **日志恢复的 stop 永不确认。** 与 Standards 同一修复；日志恢复的 exit code 仍保持 unknown，不伪报成功。
- **PID-only 误当原范围并可被杀。** 已改为不可验证、只观察，不 attach/不 signal。
- **当前来源授权未复核。** reconciliation 在附接前调用来源当前授权检查；失败保持 unknown 并提问，不自动回落 Host。
- **Host restart 测试复用了同一个在线 Environment 对象。** 测试使用 `RemoteEnvironment.restore()` 重建 Host 连接状态，验证跨 Host 对象接管。
- **真实第二设备证据缺失。** 已执行 Windows→Linux 跨机 26/26，记录 device ID、incarnation、公钥指纹、逐项行为和耗时；验收脚本已提交。

## 结果

- Standards：首轮 P1 已修复；剩余为 PID-only 平台证明边界和 unverifiable 记录清理策略，已明确记录。
- Spec：T35 四条 acceptance 均由公开 Engine/provider 行为及真实第二设备验收覆盖；没有自动回落 Host。
- 验证：Windows Node 25.4.0 `npm test` **295/296**（1 项 Windows-only skip），typecheck、lint 通过；Ubuntu Node 24.15.0 恢复测试 **8/8 + 1 skip**；Windows→Ubuntu 跨机验收 **26/26**。

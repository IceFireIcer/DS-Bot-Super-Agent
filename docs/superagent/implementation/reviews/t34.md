## Standards

首轮发现及处理：

- **硬性：注释声称不存在的 reattach。** `Engine.reconcileStop` / `reconcileRemoteStops` 实际只 inspect/cancel，不重新 attach。注释已改为“inspects and cancels by original ID”。
- **未使用抽象。** `attachRange` / `AttachedRange` 在改为 direct inspect/cancel 后没有调用者，已删除。
- **Windows PID 误判。** `tasklist` CSV 曾用子串匹配 PID，`123` 会匹配 `1234`；改为解析 CSV PID 字段。
- **PTY fingerprint 漏参数。** 同 job ID 使用不同 rows/cols/terminalType 曾可通过；fingerprint 已加入三项。
- **判断项：launchJob 位置参数。** terminal geometry 仍是位置参数；保留，因调用点只有一个且参数已命名。
- **判断项：终端校验重复。** 设备与 Host 各自校验尺寸/类型；保留两端独立防线。
- **判断项：测试 helper 重复。** 三个远端测试各自保留 loopback fixture；未抽共享 helper，避免把不同验收夹具耦合。

## Spec

首轮发现及处理：

- **pending stop 被伪确认。** `stopTicket` 和 skipped-worker 路径会在 `running=false` 时直接写 `stopped + cancellationConfirmedAt`，即使 remote range 仍 pending。两处都已加 `pendingDeviceConfirmation` 守卫；只有 remote range 证据确认后才清除。
- **resume 越过 pending。** `resumeTicket` 现在先拒绝 `pendingDeviceConfirmation`，再检查 `cancellationConfirmedAt`。
- **range 快照 jobId 未核对。** `inspectRange` 现在要求返回 jobId 与请求 ID 相同。
- **远端子代理未继承。** `delegate_subagent` 不再只限 local；远端 Worker 的子代理继承父 bound Environment 的远端工具，设备进程仍归属父 Assignment。测试工具列表已更新。
- **PTY provider 契约是受限子集。** `spawnTerminal` 只接受设备配置名和尺寸；不支持任意 argv/cwd/env/graceMs。已在记录中明确声明，不冒充完整 DSH runtime。
- **前台 run_command 无 JobRecord。** 断连 stop 时无法按 job ID 查前台范围；T34 记录明确留给 T35，不用本地回退或伪确认。
- **真实第二设备覆盖是部分的。** Linux 实测覆盖 PTY/进程组终止 2/2；断连 stop 与迟到结果由 loopback 测试覆盖，未在真实设备上重复演练，记录中如实标注。
- **复审：pending 仍可能被无范围证据清除。** `stopTicket` 的 `allStopped` 只看 ranges/children；已加入 `remoteJobIds` 证据集，只有每个远端 job range 均确认才允许 remote-confirmed `confirmStop`，前台/子代理结束不再算范围静止。
- **复审：PTY 输出绕过 sanitize、signalForeground 伪报前台。** live terminal 输出现在经过同一 sanitize；`signalForeground` 明确返回 `UNSUPPORTED_CAPABILITY`，设备不再接受未验证的 terminal signal。

- 验证：Windows Node 25.4.0 `npm test` **287/287**，typecheck、lint 通过；真实 Linux PTY/进程组 2/2。

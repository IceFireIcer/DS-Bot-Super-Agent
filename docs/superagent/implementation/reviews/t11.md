# T11 双轴审查

- 日期：2026-11-07。
- 固定基线：`b36e056`；审查目标：T11 提交前工作树，对应实现提交：本票提交。
- 范围：持久执行槽与 Assignment 归属、人工优先的有界额外槽、Effects 按 lane 并发派发与 `defer`、受限状态命令与状态事实、跨 runtime 账目清理、同源 chat 入口，以及声明负载实测。

## Standards

首轮指出六个具体缺陷：等待中的槽记录只清理 `holding`，旧 runtime 的 `waiting` 会永久阻塞后续启动；候槽后的回合若在提交后抛异常会泄漏槽；`runLane` 返回已在运行的 promise，使 pass 等它没启动的 lane 并重复计数；同一 Ticket 可能被两个 Assignment 并发执行；`listSlots` 在无 runtime 时静默返回 `undefined`；释放表达式重复五处。另指出状态回合仍带 `report_ready`、`worker()` 过大。

实现改为：`current()` 删除所有非本 runtime 记录并在跳过路径释放槽；回合主体包进单一 `try/finally` 与统一的 `releaseSlot`；活动 lane 直接返回 0 跳过，`drain()` 不再合并 pass；准入拒绝本进程已有活动回合的 Ticket；`listSlots` 抛 `WORKER_NOT_ENABLED`；提取 `releaseSlot`/`runTurn`，`worker()` 只负责跳过与准入。修复后全量 **130/130**、typecheck、lint 通过，`dev/slots.mjs` 可复跑。

## Spec

首轮确认 AC1/AC2/AC3 与 AC5 的 stop 隔离、通知合并已满足，但指出状态请求只改提示词：`conversation()` 前后无差异，且状态回合仍可调用 `report_ready` 伪造结果，与文档“不能凭空产生结果”矛盾；AC4 缺完成/响应延迟与公平性预算；删除旧 runtime 记录与注释“仅审计”不一致；T09 的 `recoverStaleStop`/`TURN_ACTIVE` 属于跨票改动。

实现把状态回合收窄为单一 `report_status` 事实工具（无交付工具），记录 `statusReport` 并在 `conversation` 暴露，同时保留“plain text 不构成事实、状态回合不结束 Ticket”的回归；`dev/slots.mjs` 增加每票完成延迟与 3600 ms 公平性预算断言；清理语义与文档统一为“删除”；`recoverStaleStop` 与 `TURN_ACTIVE` 在验收记录中列为跨票说明。

# T13 双轴审查

- 日期：2026-11-08。
- 固定基线：`68047eb`；审查目标：T13 提交前工作树，对应实现提交：本票提交。
- 范围：DSH 公开 `parentAgent` 子 Agent、Instance/Mandate/Environment 与工具 scope 继承、完成事件回原代次、按归属取消与核查、并发/期限/清理预算、后台工作账目共享，以及文档中的能力边界。

## Standards

首轮指出三处硬违规与一组正确性缺陷。硬违规：`superagent/README.md` 同时写"子代理继承本 Assignment 的 job 工具"与代码相反、漏记 `maxResultBytes` 与 100 条报告上限、`docs/superagent/implementation/README.md` 链接的 `reviews/t13.md` 尚不存在。

正确性：`start()` 提交记录后才在 `attach()` 登记归属，读取窗口会把正在创建的子代理判成 `unknown`；`expire()` 对仍在创建的子代理直接返回，声明期限丢失；`children` 只存 `Agent` 而非 `AgentHandle`，`finishStopped` 对未确认的子代理解除登记后再也无法取消或 dispose；`settle`/`fail` 在事务回调内触发 handler，回滚后会替一个未完成的子任务发唤醒；`stopChildren` 未清理超时定时器；`expire` 用全表扫描找记录；`sessionId` 用 `as never` 绕过品牌类型；子工具用自制注册而非 `defineTool`；`getSubagent` 手工重建视图且与 `viewOf` 的 `settled` 语义冲突；`allowed` 过滤条件恒真；scope 构建两次。

实现改为：`Subagents` 重写为"记录提交即登记归属（`claimed`）→ `attach` 启动 → 终止事实提交后才回调 handler"；`running` 同时保存 `AgentHandle`，`finishStopped`/`close`/`shutdown` 都在清理预算内 `dispose()`；`expire` 直接用 `running` 里保存的记录，不再全表扫描；`stopChildren` 用 `withTimeout` 绑定 `whenIdle()` 并清理定时器；子 Agent 用 `SessionId()` 与 `defineTool()` 创建；`getSubagent` 复用 `viewOf`；`settled` 统一为 completed/failed/cancelled；`allowed` 死代码删除，scope 只构建一次；`BackgroundWork` 抽出共享索引并保留 `job-active` 迁移，`Jobs.listIn` 补上按票前缀过滤（这是 T12 遗留的跨票查询缺陷）。

第二轮指出：`delegate_subagent` 继承 job 工具会把 Ticket 级闭包交给子代理（可查看/取消父任务 job，且子代理结束时不会清理），已改为只继承本地工作工具；`activation: 'job'` 与 `worker-jobs` 在子代理加入后语义不准，重命名为 `'background'` 与 `worker-background`（同步更新 T12 文档与测试）；`chat-server` 的路由三元链改为路由表。

## Spec

首轮确认 AC2/AC3 主干（工具白名单、两 Worker 隔离、代次检查、按归属取消）成立，但指出：AC1 的 Mandate 只被隐含继承、AC3 的完成事件正文不带原代次、AC4 记录的 `reviews/t13.md` 缺失且子 Session 未做 flush 持久化确认、"子代理的 jobs 随其结束"未满足；此外 `stopTicket` 判定 `running` 时漏掉子代理，导致只有子代理在跑时 stop 立刻写成 `stopped`（虽然子代理随后被取消，但确认被伪造），与 D14"只有确认实际静止后才报告 cancelled"冲突；`BackgroundWork` 改了索引键却没有迁移旧 `job-active`，升级后正在运行的 job 会从预算与持槽中消失。

实现改为：`SubagentRecord`/`SubagentView` 增加 `mandateId`，启动时的 `authorize` 与每次子工具调用都复核 Ticket 当前 Mandate；唤醒 payload 与事件正文都带 `generation`；子会话 flush 失败按失败处理；stop 的 `running` 改用 `hasBackgroundWork`（job + subagent），未确认的取消让 Ticket 保持 `stopping` 并阻止 resume；`Jobs` 读取前把旧 `job-active` 迁移进共享索引；新增测试覆盖"stop 无法确认时保持 stopping 且拒绝 resume"。

## 第二轮

第二轮复审指出：验收记录仍写"以及该 Assignment 已有的 job 工具"与"8 项"，与代码和 README 不一致；`shutdown` 变成 async 却没有被 await，README 的"先取消并释放所有子代理再停 Effects"不成立；`withTimeout` 胜出后不清理定时器；子代理创建期间被 stop 时 handle 尚未登记，导致子代理既未被取消也未被释放却记为 `unknown`；`migrateLegacyIndex` 只在部分读取路径执行，stop 的跳过分支可能漏迁移；`guard` 里引用了稍后才声明的 `id`；子工具复用父回合闭包，会消耗父的调用预算并可能替父满足 `VERIFY_REQUIRED`。

实现改为：验收记录按代码改写（5 项本地工具、不含 job 工具）；`Execution.shutdown`/`Engine.shutdown`/plugin 关闭链改为 await，`disposeBounded` 在清理预算内释放 handle；`withTimeout` 在 finally 清理定时器；`stopChildren` 先等正在创建的子代理拿到 handle 再取消，创建完成后若条目已被移除则直接 `disposeBounded`；`worker()` 跳过分支在取消后按确认结果落下 stop 事实（未全确认则保持 `stopping`）；子代理工具改为独立闭包，拥有自己的调用计数；`guard` 每次复核 Ticket 仍 open、Mandate 未变、Assignment 未结束。

## 第三轮

第三轮指出：`attach` 把整段 `drive` 当作"创建中"的等待对象，于是创建期间落地的 stop 会等子代理整个回合而不是等 handle 出现，超时后既没调用 `cancel` 又把记录写成 `unknown`；另外两条 live-turn 路径（abort 分支与 `runTurn` 的 `activeStop` 分支）仍会无条件落下 `stopped` + `cancellationConfirmedAt`，而此时后台工作尚未被确认静止。

实现改为：`running` 条目携带一个在 `agents.create` 返回后立即 resolve 的 `created` promise，`stopChildren` 只等这个 promise，随后立刻 `agent.cancel({ kind: 'parent' })` 并 `whenIdle()`；两条 live-turn 路径改为先检查 `hasBackgroundWork`，仍有活动后台工作时把确认交给 `stopTicket` 的后台清理路径；`stopTicket` 在全部 job 与子代理都确认后统一落下确认，不再以"是否有 live turn"作为跳过条件。

## 收尾复审（2026-11-08）

- 两条新发现：子回合以 `turn/end: error` 结束仍被记成 `completed`；“两 Worker 不串目录”的测试实际共用同一目录。另有基准指标误标：6 ms 是接单耗时，并发峰值累计了已结束的子代理。
- 修复：结果改为读取子 Session 自己的 `turn/end`（完成才算成功，失败/超限/阻塞/中断记 `failed`，父、人或宿主停止发起的取消记 `cancelled`）；隔离测试为两个 Worker 绑定不同 Environment 根并断言彼此产物不存在；基准改为测量接单到父回合交出控制的延迟与真实在跑峰值，并断言父 Ticket 仍持槽。
- 同时修正验收记录中不准确的“公开 API 缺口”表述：`@deepseek-ai/dsh-subagent` 在 0.2.1-rc.4 已发布；本票仍使用 `ctx.agents.create({ parentAgent })`，迁移到 `startActivation` 需另立票处理 `workingDirectory`、`sessionQuery` 与 preset 组合。

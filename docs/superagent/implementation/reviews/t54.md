## Standards

- 每模式独立临时目录、SQLite、DSH Context/NativeSessions、Router ID、模型调用计数和通知记录；完全清理后才启动下一模式，没有跨模式在途队列/历史/计数污染。
- 测试从公开 CLI JSON 验证 12 ID、6+6 分布、内容/流摘要、持久输入/输出/turn-end、边界、隔离、通知与重放，不依赖生产私有 helper 或直接查询数据库。
- 只用公开 Engine/Session/provider、native-mock 和隔离数据，不触及用户 DSH/凭据；没有修改生产 Engine 或其他任务文件。
- 5 s Session timeout、25 s 每模式等待截止、Effects 十页/Session 二十页限制、CLI 子进程 110 s timeout；取消可打断 mock 等待。cleanup 即使前一步失败仍释放其余资源并汇总错误。
- 判断项：measureMode 编排同一隔离运行的装配、计时、重放和报告；日志读取、收敛、观察与清理已提取具名 helper，没有为基准修改共享 harness 或生产接口。

自检无剩余硬性规范违规；不据此推断其他任务改动或完整项目类型/生成一致性通过。

## Spec

撤回旧审查的“相同 12 条流”结论：旧订阅模式实际只有 7 条，且旧 total 没等所有 Worker 完成。旧时间表不能证明等负载性能。

本轮核对：

1. canonical stream 冻结，event-01–12、六 Thread、六 initial/六 follow-up，各模式实际 Worker 正文完全匹配。人口摘要来自真实接收顺序；缺失、额外、改写、重复都失败。
2. 跟进保持原 Thread/Ticket/Session。routerWorker 明确作为开发对照，每条跟进增加一个公开受限 Router forward_event 步骤再进入同一 Engine；没有伪装十二个 Thread 或关闭生产订阅。因果差异和局限已写入文档。
3. 每事件测入口、准入、首个 delta 和持久 completed 回合，核对真实 user/message、assistant/message、turn/end 序号；total 在全部 Worker handle/槽/Effect 结算后采集。每模式 12 个 Worker 调用、12 个 completion 样本、0 在途回合。
4. raw Session flush 与 Engine 来源持久回执边界分开；完成是 turn，不是 Ticket ready/结果交付。串行到达和核验成本写明，不称并发吞吐或完整产品功能等价。
5. Router 模型请求、按 user-message 去重的回合、实际语义 batch 与 Gate evaluation 分栏。明确人类 direct 请求不调用语义研判，所以 batch=0，不能把 Gate 记录冒称模型批次。
6. 通知来自 mock channel 实际调用/幂等键与公开 sent ledger；全部 12 来源输入重放后计算执行/Ticket/通知增量。unknown 读实际 Effect/job，未制造故障不称对账验收；token 明确 unavailable。
7. 指定 Windows Node 24.22.2 实测 JSON 各模式 12/12、摘要相同；single/Router/订阅 total 为 799.15/1727.01/1622.33 ms。两种 Engine 模式重放无新增执行/Ticket/通知；数字不是 SLA。

自检：限定的同事件开发基准修复已覆盖。T54 总体仍缺真实模型/token、远端/托管、主动/监督/故障恢复和超限负载，本修复不关闭这些边界。T55 索引由父任务处置，本任务未改。

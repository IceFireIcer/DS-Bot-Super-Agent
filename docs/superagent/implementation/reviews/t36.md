## Standards

首轮发现及处理：

- **多个 Assignment 创建路径绕过 target。** follow-up relay 可在 Router 绑定前创建 Host-local Assignment；`retryTicket` 也可绕过 waiting。现在 `worker` 在无 Assignment 时先走同一绑定入口（不额外排队重复 relay），`retryTicket` 对 waiting Ticket 返回 `ENVIRONMENT_WAITING`。
- **retry command 丢失响应后不幂等。** 现在 command transaction 先持久 claimed/pending，完成后写 done；已完成的 command ID 不再 re-bind，pending 中断可安全重做同一个幂等绑定。
- **auto 信任未探测或未知证据。** static 不合格候选不再 probe；remote/local selection 必须有 probe；unknown capacity/version/fingerprint、目录不符、缺失能力或 probe 缺失都不可选。原因有长度和数量上限，每个 probe 有 5 秒信号。
- **status 扩展没有协议升级。** remote protocol 与 saved connection state 升为 v3；旧状态明确拒绝，status 的 version/fingerprint/capacity 在 prepare 与 probe 中一致校验。
- **selection 查询/retry 没有 source-instance 隔离。** Engine 通过 Ticket→Trigger 校验 source instance 和原 actor；Execution 绑定入口也拒绝外来 source。
- **auto 的 Mandate/Intent 被写成 local。** 接受的 target、target source 和解析后的 Intent kind 分开持久；auto Mandate 保持 auto，固定后只更新 Intent 的实际 local/remote。

复审修复：

- **固定 Environment 只比较字符串 ID/root。** 运行时重验 root/version/fingerprint，目录被替换返回 `ENVIRONMENT_CHANGED`。
- **answer-only 用原因文案做控制流。** selection 增加显式 `answerOnly`；无 Environment 的默认 local 兼容仅由该字段决定。
- **绑定可以重写运行中的无 Environment Assignment。** 只有 `pending` 的旧 Assignment 可补绑定；running/stopping/ended 返回 `ENVIRONMENT_BOUND`。

## Spec

- AC1：Instance 默认 local、Ticket override、allowlist/target 越权拒绝；Assignment 固定 selection 的完整位置证据。
- AC2：auto 的候选证据覆盖 allowlist、online、capability、directory、version/fingerprint、capacity；unknown/full/缺 probe 负例和实际双模式均执行。
- AC3：remote-only 无合格设备保持 `environment-waiting`，follow-up/retry 不绕过；策略变化不迁移 fixed Assignment，工具无 target 参数。
- AC4：本地选择使用活动 Host 的 LocalEnvironment probe（Host ID 与目录身份），远程使用设备 status；模型端点保持独立；unauthorized/offline/缺能力负例与真实 Local+Remote 闭环通过。

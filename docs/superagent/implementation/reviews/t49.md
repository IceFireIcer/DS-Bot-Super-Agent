# T49 双轴审查

- 基线：`afc791a`；主代理按 Standards 与 Spec 两轴并行复核，修复后重新运行定向、串行全量和 Session 验收。

## Standards

- **修复：** `updateBehaviorFromInstruction` 原先是一个约 85 行的校验/claim/解释/应用流程。提取 `prepareBehaviorInstruction`、`finishBehaviorInstruction` 和统一的分页扫描 helper；主流程仍保留一次完整生命周期，但状态转换和扫描不再重复。
- **修复：** `finishBehaviorInstruction` 的无用 `claimed` 参数已删除；`signal` 现在来自调用方的可选 `command.signal`，不再是一个永远无法取消的 controller。
- **修复：** `getBehaviorInstructions` 与 `listConfigDrafts` 原先重复 10 页扫描；现在共用 `scanBehaviorRecords`。
- **修复：** `createSessionConfigInterpreter` 原先记录构造时的 `routerRoute`，角色模型在线更新后会失真。现在记录 `sessions.getRoutes().router` 的实际当前路由；工具每指令最多记录一次，不再让后一次输出静默覆盖前一次。
- **修复：** 文档缺口已补：新增本记录、`reviews/t49.md`、`superagent/README.md` 的 Trusted behavior configuration 段，说明 `authoringActorIds`、`updateBehaviorFromInstruction`、`createSessionConfigInterpreter` 和硬限制。
- **保留判断：** `BehaviorInstructionRecord` 与 `ConfigDraft` 仍有重复的 request 字段。两者生命周期不同（一个随命令，一个随草稿），共享 request 子对象会增加嵌套而不减少校验；当前保留扁平记录。
- **保留判断：** `propose_behavior_change` 的 `roles`/`policy` 参数都是字符串，未使用 payload 时传空串。公开 `NativeTool.parameters` 只声明字符串参数，改成可选会扩散到 DSH 工具类型；空串哨兵由工具校验和文档明确。
- **保留判断：** 新模块仍需同步 `package.json`、`scripts/build.mjs` 和 `index.ts`。这是仓库现有导出方式；从 exports 推导 entryPoints 会改变所有模块的构建约定，不在本票扩大。

## Spec

- **修复（阻断）：** 原实现只检查 `updateBehaviorFromInstruction` 的 `authoringActorIds`，直接 `updateRoleConfig`/`updateIntakePolicy` 仍可绕过。配置了 `authoringActorIds` 时，两条直接 settings 路径现在也要求该 actor；`origin: 'sync'` 的系统同步例外。新增直接 settings 绕过负例。
- **修复（阻断）：** roles 原先可改角色名、provider/model、skills 和其它 RoleConfig 字段。现在只应用 prompt instructions/skills；角色名/model 路由必须保持原值，模型路由变更拒绝。policy 只允许 `mode` 和 `rules`，batch/attempt/timeout 预算与 allowlists/assessor 固定；恶意 tools/allowlists/budgets 负例均通过拒绝。
- **修复（阻断）：** 缺少模板占位符和总大小检查。现在 Router 必须保留 `{{goal}}`，Worker 必须保留 `{{goal}}`/`{{constraints}}`，roles JSON 不超过 64 KiB；仍复用 `validateRoleConfig` 的 16 KiB 单字段/技能/未知占位符校验。
- **修复：** revision 冲突原先只保角色草稿；新增 policy 冲突草稿测试。草稿 ID 固定为 instruction ID，重放/重试不会重复生成草稿；当前 role/policy revision 可查。
- **修复：** 解释完成到应用之间的崩溃会留下 `interpreting`。现在先把 validated change 写入 `applying`，重试沿用已存 change，不重新解释；动作派生 command ID 幂等，最终状态和 effective revision 仍可回查。
- **修复：** 同一 interpreter Session 原先可多次调用记录工具，最后一次静默覆盖。现在第二次调用直接拒绝；测试确认第一次 change 保留。
- **修复：** `createSessionConfigInterpreter` 记录实际 `getRoutes().router`，并带 prompt/config version；不再声称构造时路由就是实际生效路由。
- **修复：** 增加“Supervisor 无配置写入口”和“配置变更不清除人工 stop”的回归；恶意来源 actor 的 instruction 在 interpreter 前被拒。
- **保留（边界）：** 没有真实模型小样本。当前只有确定性/注入 interpreter、真实 DSH Agent loop + mock 模型和恶意输出负例；无 API key/模型端点，真实模型意图解析质量未报告。
- **保留（边界）：** 没有聊天/设置 UI 或远程 authoring API；公开 Engine 命令和 `authoringActorIds` 是入口，T45 client gateway 不暴露配置写路由，UI 留 T55。
- **保留（边界）：** `authoringActorIds` 未配置时直接 settings 方法保持既有 `allowedActorIds` 行为，以兼容 T23/T25；配置后强制维护者。迁移部署必须显式配置。
- **保留（边界）：** policy 在途 Eval/live 通知由 T25 的 `updateIntakePolicy` 承担；T49 复用同一入口，没有另造规则引擎，也没有重复 T25 的故障矩阵。
- **保留（边界）：** 草稿不会自动重放；维护者用新 revision 重新提交，避免自动覆盖较新配置。

# T14 双轴审查

- 日期：2026-11-08。
- 固定基线：`2636100`；审查目标：T14 提交前工作树，对应实现提交：本票提交。
- 范围：显式托管预览、ready/waiting-human 交接、执行槽释放、普通 job/子 Agent 按归属清理、预览自然退出与取消确认、未确认清理的人为解析、预览预算、阶段/生命周期投影、公开 Engine 与同源 chat 入口。

## Standards

首轮指出硬问题：预览在重启后仍可能读作 `running`；ready 已结束 Assignment 时 `stopTicket` 会把仍在跑的预览直接写成已确认 stopped；`cancelPreview` 对已有 `cancelling` 句柄不再尝试 `stopRanges`；等待定时器在事务内清理，回滚后 job 可能失去有界等待；普通 `cancelJob` 可以绕过 `cancelPreview` 终止预览；预览命令依赖有界 job 历史，可能为空；测试直接篡改 job 存储键。

实现改为：预览读取同时核对记录、job 和当前 Host 的 runtime token，并查询进程是否仍由本进程持有；stop/skip 的最终确认会把 running/cancelling/unknown 预览纳入 pending 集合；`cancelPreview` 对仍持有的 `cancelling` job 再次执行停止确认；wait timer 改为事务提交后的 scoped `clearPreviewWait`；Engine 与 Worker 的 `cancel_job` 都拒绝预览 job；命令写入 PreviewRecord；预览查询使用 `preview-history` 指针返回实际最新 100 条；未确认/跨 Host 的测试改用真实 Engine 重启与公开命令。

后续复审继续指出：预览没有人为解析路径；活动预览只按有界历史检查；自然退出不清理活动索引；预览历史仍按 key 顺序取样；旧记录在首次升级时可能被新指针覆盖。实现增加 `resolvePreview`、`preview-pending` 活跃索引、自然退出时同步预览状态、最新 100 条指针，以及首次写入指针时先从旧记录播种。最终相关审查未再发现硬违规。

## Spec

AC1：ready 与 waiting-human 在同一事务写入交接事实并释放槽；普通后台 job 以 `assignment-ended` 取消，子 Agent 走 T13 的停止/确认路径；预览保留原 Ticket/Assignment/generation/Environment/job 归属，artifact 与进程身份可通过公开查询读取。测试同时覆盖 ready、waiting-human、子 Agent 停止和普通 job 结束。

AC2：`keep_preview` 只接受本 Assignment、本代次、本进程持有的 `start_command` job。预览从执行工作索引移除，不占槽、不占 job 预算、不受 job wait 限制；自然退出只写 `exited` 事实，不发 relay、不唤醒 Worker。预览使用独立的 pending 预算，activity/liveness 不依赖有界历史。

AC3：取消与 stop 只处理本 Ticket 的托管预览；跨 Ticket 的普通工作继续运行。未确认清理显示 `unknown`、`pendingConfirmation: true`；同一 Host 的解析可以完成由该预览留下的 stop，但旧 Host 的 stop 不会被解析伪造，`CANCELLATION_UNCONFIRMED` 仍阻止 resume。预览历史与 activity 查询有界，旧终态记录保留为证据；首个指针写入会从旧记录播种，不隐藏迁移前记录。

AC4：`conversation` 分离 `stage`（idle/draft/ready/waiting-human/stopping/stopped/ended/pending）与 `lifecycle`（open/ended）。ready report 保持 `stage: ready`，Ticket 结束后 `lifecycle: ended`，二者不再挤进一个字段。重复查询 ready 不创建 Assignment、不重跑副作用、不重复交付；测试断言无新增 Worker 回合或 pending relay。

规格评审最终确认无剩余 spec gap。唯一设计取舍已在 `t14.md` 记录：ready 已结束 Assignment，而显式预览作为清理例外保留到取消、stop、退出或 Host shutdown；这是 D08/A09 明确保留预览的最小适配。

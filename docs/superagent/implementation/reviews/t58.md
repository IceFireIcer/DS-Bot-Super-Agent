## Standards

| 发现 | 处理 |
| --- | --- |
| `implementation/README.md` 引用了不存在的 `reviews/t58.md` | 已新增本审查文件。 |

| Host 启动失败时只写 failed status，不关闭已打开的 PostgreSQL/Context/网关 | 已提取幂等 `closeResources()`，启动失败、SIGINT/SIGTERM 和 Watchdog shutdown 共用。 |

| 清理和“全量回归”此前是自述 | 已补实际清理输出（`CLEANED`、PostgreSQL `inactive`、无残留 Host/device 进程）；全量测试交由推送后的 CI，不在本地重复跑既有长尾。 |
| `execution.ts` 修复只断言 `reportHistory` | helper 同时服务 retry/rollover 等前缀扫描；回归测试覆盖最容易跨 Ticket 的 reportHistory，文档已改正不再声称 delivery-history 被调用。 |

## Spec

| 发现 | 处理 |
| --- | --- |
| TLS 未配置 | **保留为部分验收。** 用户明确要求暂不配置 TLS；本轮用 SSH 本地转发保护 loopback 网关，不宣称生产 TLS。 |
| 没有 T56 production factory、T59 profile、T60 remote UI | **保留为未完成。** 当前 `t58-host` 直接使用公开 `Engine`；app/UI 没有远程 client-gateway 传输，T58 不把这条组合记成通过。 |
| Watchdog 替换的是空 Host，未证明原 Ticket 继续、旧回调隔离 | **保留为部分验收。** epoch 4→5 和 `recovered` 是真实 PostgreSQL 进程证据，但 Ticket continuation 未运行。 |
| Ubuntu 设备与 Host 共处一台服务器 | **保留为部分验收。** 这是用户指定的 Windows 主设备 / Ubuntu 第二设备拓扑；真实设备文件/命令和 daemon 重启通过，但不是独立物理设备。 |
| 离线 stop、同范围静止确认、显式 resume、双向交接未运行 | **保留为未完成。** 设备重连后的新 Ticket 成功，不等同于运行中作业的离线恢复。 |
| `execution.ts` 核心修改是否越界 | 该修改修复的是客户端 cursor 补读的跨 Ticket 污染，属于 T58 真实组合暴露的前置正确性问题；已加回归测试并在记录中说明，不扩展领域行为。 |
| 飞书 | 维护者已在 T57 明确暂缓；T58 不引用为通过。 |

## 结论

Standards 轴发现 8 项，已修复 7 项、保留 1 项现有构造器差异；Spec 轴发现 7 项，已修复 1 项并保留 6 项明确边界。T58 仍是部分验收，不能关闭；真实托管 Host、PostgreSQL、客户端断连/补读、撤销、设备执行和 Watchdog 替换有实际证据，但 T56/T59/T60 远程 UI、离线 stop/resume、双向交接和飞书仍未完成。

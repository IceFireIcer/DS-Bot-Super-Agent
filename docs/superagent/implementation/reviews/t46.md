# T46 双轴审查

- 基线：`5c6c3dd`；主代理按 Standards 与 Spec 两轴并行复核，修复后重新运行定向与全量检查。

## Standards

- **修复：** 设计文档“托盘菜单是『打开』和『退出』”与本票新增的状态行冲突。`docs/plans/2026-10-16-desktop-app.md` 的托盘一节改成“先是一行不可点击的 Host 状态，然后是打开和退出”，并补了休眠/唤醒、数据锁的变更记录。
- **修复：** `main.mjs` 里 `resumeWork` 的注释仍写着“新版本可能修复启动”，而函数实际做的是唤醒后重连/替换 Host。改名为 `resumeHost`，注释只说明唤醒后的两种结果；`relaunchHost(cause)` 现在真的使用 `cause` 记录替换原因，不再是死参数。
- **修复：** 启动 Host 的“设置锁、赋值、监听、启动、写锁、转 running”在首次启动和替换路径重复。提取 `launchHost(instance)`，两条路径共用，状态转换只剩一处。
- **修复：** `hostState` 的 `'running'`/`'starting'`/`'stopped'`/`'failed'` 原文散落在 main、shell 和测试中。main 侧收进 `HOST_STATE` 常量；shell 只消费状态键并映射文案。
- **修复：** 状态行让 `trayMenu()[2]`、`menu[2]` 散落在多个测试文件。`app-harness` 新增 `trayOpen()`/`trayQuit()`，shell/tray 测试改成按标签查找，再加一行不会再改一批索引。
- **修复：** `app-harness` 里“Open、线、Quit”的菜单注释已过期，改为“状态、Open、Quit，中间有分隔线”。
- **修复：** `fail` 同时做更新检查、错误框、重试和退出。重试对话框提取为 `askTryAgain(error, next)`；更新检查仍留在 `fail`，因为更新路径也要复用同一个失败入口。
- **保留判断：** `fail` 仍是启动失败的总入口，更新、重试和退出在同一函数里。更新路径要决定“先开更新页/先下载再退出”，与重试按钮共享同一个错误事实；再拆一层只会把分支搬到两个函数。
- **保留判断：** `check-resident.mjs` 自带一份小型 CDP 客户端，与 `shot.mjs` 形状相近。两个脚本各自独立运行、生命周期不同，本票不先抽共享模块；后续做更完整的桌面验收脚本时可合并。
- **保留判断：** `HOST_STATE` 只是四个字符串常量，没有新建类型。shell 只需要一个可映射的键；为四个值引入公共类型会把 app 的两个小模块绑在一起。

## Spec

- **修复（阻断）：** 复审发现 `suspended` 只在 `onSuspend` 置真，`resumeWork` 从未清回。一次休眠后，之后所有 Host 死亡都会被静默存进 `deferredFailure`，托盘仍显示 `Host running`，正好违反 A36“休眠/关机期间不宣称持续执行”。`resumeHost` 现在先清 `suspended`；新增 `main-after-sleep.test.mjs`：唤醒后 Host 再死亡必须弹 `Try again`，不能继续 defer。
- **修复（阻断）：** `relaunchHost` 直接创建新 Host，没有先停旧 Host。若旧 Host 只是报告 fatal 但仍短暂存活，两个 Router 会重叠。现在先 `await host.stop()`、释放数据锁、清空旧句柄，再启动新 Host；`launchHost` 在启动前检查数据锁。
- **修复（阻断）：** 单实例锁只能挡第二个 shell，挡不住“shell 已死、Host 子进程还活着”时新 shell 用新端口再起一个 Host。新增 `host.lock`（Host 子进程 PID + 端口，原子替换）；存活 PID 拒绝启动第二个 Host，死 PID 覆盖。`host-lock.test.mjs` 覆盖存活/死亡/损坏记录/只释放自己的记录。
- **修复：** 复审指出 `resume` 无条件清 `sessionEnding` 改变了 Windows 关机语义。现在只在非 Windows 清除；Windows 的 `session-end` 仍是最终状态。
- **修复：** 复审指出 `check-resident` 只断言“没有页面目标”，却把它写成“窗口隐藏”。现在不再声称真实 App 的页面关窗等于隐藏：真实 App 检查只声明“应用和 Host 继续、第二次启动回来、退出停止 Host、强杀后同数据同端口恢复”；隐藏/未销毁由真实 Electron 的 `check-lifecycle` 断言。
- **保留（边界）：** 没有让 Windows 真正进入休眠。`shell.suspend()/resume()`、`powerMonitor` 接线和真实 Electron 托盘状态已验证；Host 在休眠中死亡后的替换是假 Host 单测。真实 OS 睡眠、注销、关机没有运行证据，因此在 T46 记录中明确列为未完成项，不能把 A36 的真实休眠验收写成全通过。
- **保留（边界）：** 真实 DSH 检查没有模型；“隐藏期间实际工作继续并补读”由假 Host 的确定性工作计数证明。真实 Host 检查证明页面、团队、端口、重启和退出路径，不冒充真实模型回合。
- **保留（边界）：** 业务库/Session 备份恢复属于 T17/T42/T43 的公开契约。本轮重新运行 `schema-upgrade` + `session-persistence` **16/16**、`postgres-storage` **22/22**；T46 应用侧只证明升级不改业务/Session 字节、保留 preset 和用户配置。没有新增应用侧备份/恢复入口，也没有把核心契约测试算成应用功能。
- **保留（边界）：** 首次 setup/账号仍是 DSH 自己的登录、API key 和设置界面。T46 新增的是 Host 启动失败后的 `Try again` 和首次启动/目录问题在下次启动重新询问；没有新建账号管理或目录编辑界面。
- **保留（边界）：** `app/` 仍不消费 `ds-superagent`。T45 的客户端网关与真实桌面组合由 T55 汇合；T46 的 Host/客户端是现有桌面应用的 DSH Host 生命周期。

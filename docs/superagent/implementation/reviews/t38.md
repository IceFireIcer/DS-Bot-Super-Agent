# T38 双轴审查

- 审查基线：`7fa2c8b`（Windows CI 修复后的 `dev`）。
- 审查方式：两个独立只读子代理分别按 Standards 与 Spec 审查暂存 diff；主代理核对并修复。
- 审查范围：T38 的能力目录、Ticket/intake 能力要求、selection 阻止、Engine/chat 查询、测试与实施记录。

## Standards

发现均为判断项，无文档标准硬违规。

- 采纳：`capabilityPlan` 实际返回 item 列表，重命名为 `resolveCapabilities`；删除未使用的 `capabilityLocation`；Host 能力不再伪造 `environmentId`；chat 能力选择器改为从 `/capabilities` 构建，避免 catalog ID/位置重复；修正提交变量遮蔽 textarea 的命名。
- 采纳：计划中的非能力阻塞（如容量满）不再被“未声明能力”兜底覆盖；Host 能力阻塞原因明确为 Host-local。
- 保留：`submit` 与 `acceptSource` 的版本化指纹分支形状不同，强行抽公共构造器会增加参数耦合；本次不改。
- 保留：`reason.toLowerCase().includes(id)` 仍从候选原因聚合；当前原因文本由本模块生成且 capability ID 受控，结构化原因留待更大范围的选择证据重构。
- 保留：测试 fixture 与 `execution-target.test.mjs` 有相似装配代码；两张票的公开场景不同，提前抽共享 helper 会把测试耦合到同一内部夹具。
- 保留：UI 直接显示稳定缺口代码，便于核查实际原因；未改为只显示模糊文案。

## Spec

- 采纳：intake 的 `IntakeAssessment` 增加可选 `capabilities` 并通过 accept 回调持久化；来源推断接单不再丢失能力要求。
- 采纳：`Engine.getCapabilityPlan` 同时校验 source instance 与原 actor，防止同实例另一 actor 读取计划。
- 采纳：真实本地 Office 测试实际通过公开 provider 加载 `office` 技能并运行配置的 `office` 命令，而不只验证 selection。
- 采纳：未声明 Host 浏览器/MCP 在本机也 fail closed；补充回归测试。
- 采纳：非能力阻塞保留实际原因（容量等），不再错误报告为“能力未声明”。
- 保留：Host 浏览器/MCP 的可用性是部署声明，不在本票绑定或探测旧产品 provider；T38 的交付是位置与阻止契约，实际工具挂载属后续产品集成。
- 保留：Office 可用性不要求 Worker 角色提示词里列 `office`；T23 已规定技能列表只影响提示，不授予工具或能力。角色范围由 catalog 的 Worker 声明约束。

# T27 跨来源方向与 GitHub outbound 双轴自检

日期：2026-11-11。基线：`339993bffb112ef69cc4b9761b559cc4f6bbf429`，未提交工作树。依据：[T27](../../issues/T27.md)、规格 D03/D05/D10/D17、A03/A15/A34、AGENTS/CONTRIBUTING、[T55 修复前审计](../t55-evidence.md)。

本记录为本任务 Standards/Spec 两轴自检，不是两个独立子代理审查。父任务负责正式审查、exports、完整套件及真实平台验收；本任务不提交、不做外部写入。

## Standards

- 原 `attachSourceEvent` 保持来源隔离；新 owner 命令核验受信接收 Engine，不接受正文自报权限，不 patch DSH，不访问用户数据。
- Input、ownership、方向、可选目标与 relay 同一异步事务；使用已有跨后端记录/`work-command`，无 SQLite 专有新表。
- Engine/source/channel 测试使用隔离真实 SQLite、原生 DSH loop/mock provider，复用 native-mock/input-support，不复制 runtime、不测试私有调用顺序。
- `gh api` 仅通过结构化 argv/stdin JSON，错误不泄露账号凭据或原始响应；marker、原生目标、认证作者、正文与平台 ID 同时核验。POST 前持久 claim，unknown 只对账。
- 配置、正文、分页、CLI 时间有界。真实验收明确 `--t27`、指定隔离现有 PR；closed PR 使用讨论评论，不走分支/merge。临时请求/数据库/Session/进程均清理。
- 判断项：只授权精确单事件，未扩大为整个跨来源 Thread 的读取或订阅；保留这种限制使来源与私有上下文边界可核查。

## Spec

- 完整 Instance/Ticket 引用只提供证据，owner、receiver、scope、原生作者准入独立核验；错误、多目标、旧/冲突/删除、机器人/ambient/无权事件拒绝。
- A→B 保持 Ticket/Assignment/Worker/Session 与 Mandate，方向只增一次；接收本身不关联、不改投，重放不重复执行。
- stop/人工等待/处理暂停优先；Attention 对应精确外部事件，owner 用自己身份回答，原生回答核验实际作者/当前事件；同名用户不自动合并。自动回答另有当前投影 guard。
- 问题/回答返回各自原生对象，结果改投必须有合法承接且当前有效的证据；旧目标命令与 Outbox 也不能绕过。引用不授予私有 context/搜索或无关 Thread 历史，永久失败不广播回退。
- GitHub channel 成功需要原生 ID/URL/marker 回执，丢响应按原身份对账，预算耗尽/伪造/重复 marker 保持 unknown。旧历史“实际交付”推断已撤回。
- 新 `--t27` 脚本可在 closed PR 讨论验证正负原生评论、同工作 A→B 和真实 POST/读回，但脚本实现不等于已运行；真实结果归父任务。

本切片完成显式关联与实际 channel 的代码闭环；完整产品、真实模型和跨设备/托管证据不从 mock 回归推导。最终定向数字由交付记录，父任务完整验收另行记录。

## 评审后修复及对账回归

- Spec P2：新关联 command 不可复用已 handback/requeue 的 ownership 改投；原 receipt replay 无副作用。公开回归先红于“Missing expected rejection”，后通过。
- Standards：fixture/真实脚本逐项尝试所有 disposer 与经路径校验的删除，结束后汇总错误，不被首个 close 失败截断。
- 权限：原 owner 撤权后保留自身历史读取，执行/重试仍拒绝，其他来源读取不开放。现有 Host takeover 撤权回归通过。
- 正式复审修复：同 Instance 同 source 但不同 actor 不再因在自己的 allowlist 中而读取猜到的 Ticket；必须匹配原 trigger 的精确 actor。Delivery evidence 与 Attention 在 Outbox 发送前都复查 current projection 和当前 Policy 作者授权。
- 二次复审补齐枚举与重试边界：`listTickets()` 在固定的 1,000 条扫描预算内过滤后分页并返回来源安全 cursor；versioned-source 目标变更必须携带 current evidence；answer Outbox 复查当前 Policy；`/api/bot` send 可透传可选稳定 `requestId` 或 `Idempotency-Key` header，未改现有 UI 请求形状。
- 真实脚本对账失败已本地复现：首条 result 历史是改投前桌面对象，正确 Effect JSON array key 可找到平台回执，但该历史目的地被 channel 正确拒为 `DESTINATION_DENIED`。改取当前 conversation result 后成功，POST 总数仍为 1；不是 canonical fingerprint 排序缺陷。

# T50 双轴审查

- 基线：`218b246`；主代理按 Standards 与 Spec 两轴并行复核，修复后重新运行定向、真实 app importer、串行全量。

## Standards

- **修复：** `superagent/README.md` 原写“core does not read DSH_HOME, migrate or inspect a user's DSH data”，与 T50 的只读 archive importer 冲突。README 现在区分运行核心（不读取）与显式 opt-in `legacy-archive`（只读操作员指定的旧 source；不执行 old loop、不成为运行数据）。
- **修复：** `prepareLegacyArchive` 同时做校验、幂等、复制、角色映射和 manifest；`readLegacyObject` 同时分派多种 ref。两者仍较大，但 `prepare/verify/publish` 的阶段边界、source/target 校验和读取分发已分开；进一步拆成 store/reader 需要重做文件 staging 事务，保留为 judgement。
- **修复：** file 与 memory 的分页读取合并为同一个 file-page 路径；`within` 仍与 `app/src/copy-tree.mjs` 重复，跨 app/superagent 共享会引入 app 依赖，保留。
- **修复：** limits 仍是 `{ maxFiles, maxBytes }` clump；batch id 的五处重复校验统一由 `assertBatchId`，role/Session id 由 `safeSegment`。`listFiles` 名称保留，但它现在明确返回 path/size/digest/link 条目。
- **修复：** `manifest` 的重复 `id` 已删除，`archivePaths.root` 未使用字段移除；`mapping.sharedMemory` 不再只做校验，而是生成 `mapped-memory.json` 并在读取时标 `shared`。
- **保留判断：** `reviewItems` 直接读取 legacy `works/requests/questions/agents`，仍是一个 legacy-state adapter。schema 只在迁移时出现，当前用显式分类比抽象一层更易审计。

## Spec

- **修复（阻断）：** AC4 的真实 importer 路径已补：`legacy-archive-app-import.test.mjs` 调用既有 `app/src/import.mjs` 的 `importTeam`，用虚构隔离旧 home 验证取消、重试、成功和源 tree hash 不变；archive 自身的测试仍覆盖 staging/publish。
- **修复（阻断）：** 原引用读取只覆盖 bot/room/role/review/file/attachment/memory/session。现在 `work:`/`request:`/`question:`/`agent:`/`inflight:` 都可读，completed work 也保留历史读取；review 列表仍只列未完成/停止/未知。
- **修复（阻断）：** manifest source 只有 path/digest/stateRevision。现在增加 `sourceIdentity`/`profile`，profile 必须存在且是安全名称；mappingDigest 绑定 identity/profile。
- **修复（阻断）：** `publish` 原先信任 verified，未重查 staging checksums；现在 publish 调用 verify，verify 检查所有 source + mapping/roles/review/mapped-memory/staging checksums，再原子 rename。source change、tampered staging、existing target 均不发布。
- **修复（阻断）：** 真实 DSH 旧 Session 常为 `.zstd`，原来跳过内容验证、读取拒绝。现在用 Node zlib 解压 zstd/gzip/brotli，验证 JSON/连续 seq，并按原引用读取；新增 zstd Session 回归。
- **修复：** `sharedMemory` 现在生成 mapped-memory 文件和 `shared` 读取标记；私有 memory 仍保留为历史但标 `shared: false`，未来角色导入使用映射，不把全部 memory 当共享。
- **修复：** 角色记录的 `mainBot` 改为 `sourceMainBot`，并明确 `permissions: []`、`readOnly: true`；Main Bot 只作为来源证据，不继承权限。测试覆盖。
- **修复：** `works` review 现在显式覆盖 running/stopped/unknown（done 不列），取消/已完成只读历史不入待核查；测试加入 stopped/unknown。
- **修复：** 工作目录和附件 改为 opt-in `include`，默认档案只保留 D18 的团队/群/记忆/Session；测试读取时显式开启。
- **保留（边界）：** 档案是文件式只读入口，不接入 Engine；切换、旧核心停用和激活回退属于 T51–T53。
- **保留（边界）：** `state.json` 原样复制，可能含旧团队本地配置；credentials 和 raw profile patch 明确不复制。测试只用虚构隔离数据，不读取用户 DSH。
- **保留（边界）：** 没有 UI；公开模块/manifest 是可查询入口，设置/迁移界面留 T55。
- **保留（边界）：** 没有跨机传输、真实远程 archive 或产品旧数据验收；T50 只在同一主机文件系统上准备/验证/发布。
- **保留（边界）：** `mappedMemory` 只记录共享 scope 和 checksum；私有 memory 仍是历史可读但 `shared:false`。没有把 archive 自动写入新核心 memory/role 表。

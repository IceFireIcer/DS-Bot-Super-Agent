# T41 双轴审查

- 审查基线：`03a2149`。
- 审查方式：两个独立只读子代理分别按 Standards 与 Spec 审查 T41 diff；主代理核对、修复后重跑验证。
- 范围：中断交接的重启扫描/恢复、stop 优先、暂停与 unknown 约束、blocker 责任人、聊天交接面板、恢复测试。

## Standards

- 采纳：`revalidateHandoff` 与 `revalidateHandoffRecord` 合并成共享的 `revalidateHandoffTarget`；目标选择改为命名参数，避免第 5 个位置参数。
- 采纳：`Engine.recoverHandoffs` 更名为 `recoverInterruptedHandoffs`；扫描函数与单条恢复函数不再近似同名。
- 采纳：`blockEnvironmentHandoff` 只做阻断记录，owner 映射统一在 `saveEnvironmentHandoffIn` 应用一次；返回值使用持久化后的记录，blocker 的 `nextOwner` 不再丢失。
- 采纳：command 回执以记录上的 `command` 为准，去掉 `request.command ?? record.command` 的三处兜底；恢复继续同一记录时回执身份稳定。
- 采纳：删除未使用的 `handoff-interrupted` owner 条目，并补上 `handoff-recovery-failed`。
- 保留：`HandoffBlocker.code` 仍是 string；`workCopyBlockers` 会把 CoreError 的动态 code 带进来，收窄成字面量联合需要跨模块改造，当前由 owner 映射兜底。
- 保留：恢复测试与既有 handoff/work-copy 测试有装配重复；三处测试的断言语义不同，抽共享 fixture 会把失败定位绑在一起。

## Spec

- 采纳（AC4 / D07）：聊天预览新增 `Execution handoff` 面板，显示状态、源→目标、最后一步，以及每个 blocker 的 `next:` 责任人；`chat.test.mjs` 校验页面包含该面板。
- 采纳（AC1）：恢复路径也重新记录 settled job 证据和 `jobs-reconciled` 步骤，不再因走恢复分支丢掉原 job 对账。
- 采纳（AC2 / D13）：恢复记录保留原 `handoff.id` 与 command 回执；重启后重放原 commandId 返回同一条记录。T41 之前没有 command 字段的遗留记录仍可对账/阻断，但无法把原 commandId 对应到结果，已在文档中列为边界。
- 采纳（AC3 / D07）：unknown 只阻塞 Relay 结果（会影响执行世界），unknown outbox/notice 不再阻塞交接；新增测试证明 outbox 不阻塞。
- 采纳（AC4 / D09）：单条恢复失败不再中止整轮扫描；该记录写成 `handoff-recovery-failed`（host），其余记录继续恢复，并有混合损坏记录的测试。
- 采纳（AC3 / D09）：stop 在设置约束的同一事务把未终结交接写成 `blocked`；resume 只创建新的源 Assignment，不继续旧交接。暂停中的 requestHandoff 直接拒绝，启动/恢复扫描在暂停期间跳过，解除暂停后重试。
- 采纳：pause 命令先提交状态再恢复扫描；解除暂停后的恢复异常不再让已成功的 pause 命令报错。
- 采纳：暂停时的 command replay 先查回执再判断 pause，已提交的交接命令重放保持幂等。
- 保留：T41 不自动停止活跃 shell/PTY/job/子 Agent；它们阻塞交接，需人工 stop 或完成后才能继续。自动停止属于用户明确操作。

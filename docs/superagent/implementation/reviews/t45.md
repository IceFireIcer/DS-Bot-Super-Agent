# T45 双轴审查

- 基线：`1d485be`；主代理先按 Standards 与 Spec 两轴并行复核，再修复并复验。

## Standards

- **修复：** `ClientCommand` 改名为 `ClientCommandOutcome`，避免把“命令快照”误读为命令本身。
- **修复：** 删除 `SupervisionItem` 中未使用的 `stop` 字段；状态事件只投影实际读取的 supervision 字段。
- **修复：** 状态、Attention、result 的事件 key 全部改为内容摘要，避免长 `nextAction`/ID 超过事件 key 512 字节预算，并把 reason 与 nextAction 变化纳入 state 事件。
- **修复：** `Engine.createClientAccess()` 统一创建绑定到 Host fencing 存储的客户端访问；gateway 和 loopback 管理面拒绝同一 Instance 但来自另一存储/Engine 的 `ClientAccess`，防止撤销写错库。
- **保留判断：** `createClientGateway` 的路由处理仍在一个约 60 行的 handler 内。认证顺序、读写能力检查和错误映射集中在同一处更利于审计；继续拆表只会移动分支，不会降低复杂度。
- **保留判断：** `ClientAccess` 同时承载凭据与事件日志。两者共享同一 Instance 存储与命令事务，本票不拆成两个公共面；T55 接入真实桌面时可再按消费方拆分。
- **保留判断：** gateway 与既有 loopback chat 的 JSON body 读取仍有相同形状。chat 入口是既有本机受信管理面，gateway 还要求 Bearer 与更严格状态码；本票不为此改动既有聊天路由，后续可提取共享读取器。
- **保留判断：** `enroll`/`revoke` 都使用“指纹、`command-command` 重放、冲突检查”的形状，但重放结果与冲突文案不同；当前保留各自实现，避免用一个抽象掩盖两种命令的差异。

## Spec

- **修复（阻断）：** 复审发现 `reconcile` 只读当前 `getSupervision()`，而 `conversation.reports` 只含当前报告；客户端离线跨过多个 result 时只能看到最后一个。`Engine.getSupervision({ includeHistory: true })` 现在在有界 supervision 内附带持久 `reportHistory`/`attentionHistory`，`ClientAccess.reconcile()` 按历史逐项补读；新增同 Ticket 两次 result 的独立进程重连测试，两个 result 都只出现一次。
- **修复：** 删除“客户端可被授予多个 Instance”的无效表面。`ClientAccess` 的存储在 Instance 下隔离，gateway 也固定服务一个 Instance；现在 enroll 会拒绝非当前服务 Instance 的 grant，而不是写入永远不可用的凭据。
- **修复：** `createClientGateway`/`createChatServer` 要求 `ClientAccess` 由同一个 Engine 创建。仅比较 Instance 名称不足以证明撤销作用于同一个存储；现在用 Engine 绑定的工厂入口保证这一点。
- **保留判断：** `command` 是 Issue 要求的 Instance 级命令能力，包含 `answer`、`submit`、`stop`、`resume`、`retry`、`status`。只读客户端不能回答 Attention；没有设备/作业/预览/子 Agent 路由，客户端不能直接操作设备。提交仍走既有 Engine 的 actor、Environment 与 Mandate 校验，不扩大 Worker 工具权限。
- **保留判断：** loopback gateway 允许明文 HTTP，是因为它只绑定本机并仍要求 Bearer；任何非 loopback 地址必须在启动前配置 TLS，否则 `TRANSPORT_INSECURE`。该受信例外已写入 README 与 T45 记录。
- **保留判断：** `state` 事件是当前 supervision 快照，不是完整状态迁移史；Issue 要求补读的 Attention 与 result 已从持久历史逐项补读。超过现有 100 Ticket supervision 窗口的 Ticket 可按 ID 查询 `reportHistory`，但不会自动进入本轮事件补读；该边界已在 T45 记录中声明。
- **确认：** “真实桌面到隔离 Host”按 Issue 原文“本票协议可先在本机独立进程验证，托管组合由 T55 汇合”保留给 T55；本票只声明独立操作系统进程验收，不声明真实 Electron 桌面验收。

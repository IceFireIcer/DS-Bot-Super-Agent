# T44 双轴审查

- 基线：`51854bc`；主代理先按 Standards 与 Spec 两轴逐项复核，再修复并复验。

## Standards

- **修复：** `HOST_TAKEOVER_PENDING` 的准入判断与错误文案在 `host-takeover.ts` 收敛为 `isHostTakeoverPending()` / `assertHostTakeoverSettled()`，Engine 与 Execution 不再各写一份。
- **修复：** `Execution` 改为接收 `hostEpoch` 读取函数，而不是在构造时捕获一个可能尚未取得的 epoch；接管期间重新获取同一记录时不会拿到过期值。
- **修复：** successor Assignment 的构造收敛为 `successorAssignment()`；旧的“无 runtime 也算完成”分支删除，改为结束旧代、标记 `recovery-blocked` 并逐 Ticket 写 `blocked`/`takeover-failed`，不再把未对账的工作报告成成功。
- **修复：** 未知副作用、未知 job/子代理和待清理预览统一经过 `askTakeoverBlocker()` 生成一个结构化 Attention，选项固定为“已人工对账，继续”与“保留 unknown，继续”，并复用现有 stop 命令作为停止入口。
- **修复：** `HostLease` 增加 `owner`（进程身份）：同一进程里的多个 `Engine` 仍是同一个 Host，续租同一 epoch；另一进程即使复用相同稳定 `hostId`，在租约未过期时也得到 `HOST_LEASED`。
- **修复：** 事务回滚后内存里的 `this.current` 可能没有对应的持久记录；`assertInTransaction` 现在在这种情况下重新写入租约，而不是把本进程误判成“被替换”。
- **修复：** `apply()` 在启动 Host 时显式 `acquireHost()`，并在清理时先停 Effects 再释放租约；此前没有任何生产入口调用 `acquireHost()`，崩溃后的新进程会永远停在 `HOST_LEASE_EXPIRED`。
- **保留判断：** 释放过的租约（`releasedAt`）不再创建 takeover。它代表前一个进程已干净停止，启动恢复（T41/T42）负责未完成交接与输入；只有“过期但未释放”的租约被当作可能仍在运行的旧 Host，需要重跑对账。

## Spec

- **修复：** 非法接管顺序中“撤权”优先于“等待人工”：撤权会结束旧代、supersede 旧 Attention、清除 waiting-human 约束并把 intent 标为 `recovery-blocked`，不再保留可恢复的 successor。
- **修复：** 可继续的 intent 收敛为显式集合（running/router-pending/recovery-pending/followup-pending/context-rollover/worker-background/slot-queued/slot-priority-waiting）；不在集合内的旧代只结束，不制造空 turn。
- **修复：** 崩溃/重连演练保持 `HOST_REPLACED` 恢复原因；SIGKILL 后原 Host 复活、以及同稳定 ID 的第二个进程，都在未过期租约上得到 `HOST_LEASED`。
- **修复：** 传输层崩溃夹具区分“测试自己的租约获取”和“被注入的提交失败”，避免把租约获取也当成要崩溃的业务事务；CLI/真实子进程用例继续验证原回执与原 commandId。
- **保留判断：** T16 的输入恢复用例模拟“Host 已知停止”：恢复前把崩溃进程的租约标记为已释放，避免把 T16 的输入边界测试与 T44 的接管对账混在一起；崩溃中投递 + 接管的组合由 `host-takeover.test.mjs` 的 `input-pending` 用例覆盖。

复审后 Node 24.22.2 全量 **388 项，387 pass / 0 fail / 1 skip**（既有 Windows-only POSIX 用例）；接管定向 `host-takeover` 10/10、真实两进程 1/1、`handoff-recovery` 6/6；typecheck 通过，lint 0 error（保留 `source-evaluations.ts` 既有 warning）。

# T33 双轴审查

- 审查基线：`8b4cde9`（仓库改名提交）；当前 T33 工作尚未提交时以 working tree diff 审查。
- 规格：[T33 / #61](../issues/T33.md)，[spec v2.1](../../spec.md) D08/D09/D14、A08/A19/A20/A33、用户故事 67/78。
- 标准：[AGENTS.md](../../../../AGENTS.md)、[CONTRIBUTING.md](../../../../CONTRIBUTING.md) 及 Fowler smell 基线。

## Standards

首轮发现及处理：

- **硬性：函数过大。** `commandOperation` 同时处理 resolve/start/inspect/cancel，`validateCommands` 混合类型校验、argv/env 和时限；违反 `AGENTS.md` “Keep functions small”。已拆为 `resolveCommand`、`startJob`、`launchJob`、`inspectJob`、`cancelJob`、`jobIdFor` 和 `validateCommandEntry`。
- **重复输出窗口。** 设备与 Host 各自复制 `completeUtf8Length`、8192 字节上限和 base/total/lossy 逻辑。已提取 [`remote-output.ts`](../../../../superagent/src/remote-output.ts) 的 `BoundedOutput`；两端共享同一字节边界实现。
- **重复作业身份与时限。** job ID 前缀/长度和命令 deadline 边界在设备、Host、provider 多处重复。已集中到 `remote-protocol.ts` 的 `remoteJobIdPrefix`、`validateRemoteJobId`、`validRemoteCommandSpec` 与常量。
- **重复 begin/attach 收尾。** 已提取 `afterObserved`，统一 started/cancel 排队/schedule。
- **判断项：测试重复配置与重复 close。** fixture 现只构造一次 `config`，并移除重复的 `context.after` 注册。
- **判断项：`runCommand` 持有 Host 等待预算。** 保留；设备 deadline 由命令 spec 拥有，Host 的 +5 s 是等待传输/确认的调用方策略，不是第二份设备时限。
- **判断项：`commandNames` 与本地 `commands` 并存。** 保留；远端不能把设备 argv 暴露给 Host，`environmentCommandNames` 是唯一的工具列表来源。
- **判断项：transport 小对象。** 保留；它把 call/sanitize 与设备 provider 细节收束在一处，避免 provider 直接依赖 `RemoteEnvironment`。

## Spec

首轮发现及处理：

- **公开 provider 形状不完整。** 已把 `RemoteSubprocess.spawn` 改为 `spawn({ name, mode })`，同步返回 `RemoteJobHandle`；handle 提供 `done`、`terminate()`、`waitForExit()` 和 `collected.stdout/stderr.readFrom(offset)`。原始管道和 PTY 不属于 T33，未支持组合保持 `undefined` 并在记录中声明；不假装完整 DSH runtime。
- **Engine job ID 与设备身份分离。** `Jobs.start` 现在优先使用 `LocalJob.jobId`；远端作业的持久记录、`job_status`/`cancel_job` 和 `JobView.id` 都是包含 Instance/Environment/incarnation 的设备 ID。新增 `Jobs` 记录测试。同 ID fingerprint 已加入 `mode`。
- **接回观察预算过短。** `attach()` 使用一小时观察预算，`waitForExit` 至少等待到 job deadline；不再对一小时后台作业在约 61 s 后放弃。
- **取消竞态。** `terminate()` 不再预先宣称 cancelled；启动完成前只记录 `cancelRequested`，启动后发送 cancel；只有设备快照的 `cancelled` 才进入结果。新增“立即取消”测试。
- **范围判断：`RemoteDevice.close()` 停止活跃作业。** 保留；这是设备生命周期清理，防止优雅关闭留下孤儿进程，不是 Worker 可调用的清理工具。
- **范围判断：有命令能力时 ready 报告要求写后命令。** 保留；这是既有验证规则在新增命令能力上的一致应用，避免远端写后没有同世界证据。
- **证据补强。** 新增 UTF-8 字符跨字节与断连测试；真实 Linux 最终代码 9/9（split/断连、立即取消、丢启动响应、attach、daemon 重启/崩溃 unknown、撤销），初验 10/10 另覆盖前台 quick 与两作业隔离。

## 结果

- Standards 复审：首轮硬性问题全部确认修复；`commandOperation` 已成为短分发器，`validateCommands` 委托 `validateCommandEntry`，无新增硬性违规。剩余为判断项，均有代码边界或文档依据。
- Spec 复审发现两项真实缺口，已修复：`terminate()` 在传输失败时保留 stop intent，并由 polling/waitForExit 重试到设备确认（新增断连中取消测试）；作业元数据持久化 `stdoutTotal`/`stderrTotal`，截断输出文件前先写总偏移，daemon 重启后大输出仍保持 `lossy` 而不是回退或抛错（新增大输出重启测试）。
- 验证：Windows Node 25.4.0 `npm test` **283/283**，typecheck、lint 通过；最终代码真实 Windows→Linux 设备 9/9。
- `attachCommand` 是 Host 恢复观察的公开入口，不是 Worker 工具；Worker 侧 attach 工具和 PTY/进程树清理留给 T34/T35。

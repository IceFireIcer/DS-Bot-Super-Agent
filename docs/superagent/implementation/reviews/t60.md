## Standards

- `ds-bot/src/client/`、`ds-bot/client.js` 和 `app/ui/` 保持零 diff；新 UI 明确记录复制来源并使用独立 build id。
- 新 bundle 由 build 脚本生成，`client.js --check` 覆盖生成一致性；新增文案通过 `t()` 查找；输入框保留 `:focus-visible` 焦点环。
- Host 只使用公开 DSH `connection.fetch.register`；profile 只通过公开 profile boot、bundle patch 和 `dsh.client` 清单装配。
- 初始化失败和正常关闭都会清理 Engine、Session、SQLite；测试使用隔离目录和 mock 模型。

## 结论

T60 的本地实现和远程完整 CI 均通过。远程 [Test #87](https://github.com/IceFireIcer/DS-SuperAgent/actions/runs/43183561377) 覆盖 Super-agent core、Desktop app profile、三个 DSH 版本矩阵和 Windows/macOS/Linux 打包；Super-agent 全量 538 项为 535 通过、0 失败、3 跳过。Super-agent 核心通过新 Host 的 v1 feed 接入复制来的 DS Bot 聊天展示层，结果的可见性遵循 Router 和 Outbox 的已发送 delivery。真实模型、托管 Host 和第二设备继续由 T57/T58 验收。

审查提出的来源疑问已记录到 UI README：聊天骨架、Composer DOM 和布局 CSS 复制自仓库已有的 DS Bot 桌面聊天 `app/ui/src/chat.js`、`app/ui/src/app.css`，再接到 v1 feed；消息气泡和问题卡继续使用复制的 `ds-bot` 组件。本轮未改原 UI。审查后的生命周期、国际化、键盘焦点、结果 delivery 与持久序号问题均有对应修复。

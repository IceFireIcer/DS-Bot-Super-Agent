# T60 双轴审查

- 审查目标：当前工作区 T60 复制 UI 与 Host 接线变更。
- 规格来源：[T60](../../issues/T60.md)、[规格 D20](../../spec.md)、[设计记录](../../../plans/2026-11-12-superagent-profile-and-ui.md)。
- 结论：**未通过 T60 验收**。本次是可启动、可发送、可读取 Engine 结果的复制 UI 桥接切片，不是 v1 产品界面完成。

## Standards

已通过：

- 复制源码保留 `ds-bot/src/client/` 的原始结构和来源说明；`ds-bot` 自身无 diff。
- `client.js` 由 `superagent/ui/scripts/build-client.mjs` 生成，并有 stale check。
- 新增 profile 使用公开 `runProfile`、bundle patch、`dsh.client` 清单；未修改 `deepseek-harness`。
- 真实 profile 检查使用隔离 `DSH_HOME`、临时 SQLite、mock 模型和空闲端口，结束时关闭 Host。
- `DSBOT_UI_CHANGE_APPROVED=1` UI 边界检查通过。

未解决：

- `superagent/host/index.js` 直接重新导出整个 `ds-bot` Host；它与 T60 的“只交付 v1 窄接口、不复制 85 个端点”冲突。
- 复制 UI 的 `api.js` 仍是 `/api/bot`；`superagent/host` 只是协议桥，不是新 UI host。
- 复制 UI 仍包含未实现面板，违反“未实现入口隐藏或明确拒绝”。
- `chatPage` 的回退是适配器层补丁；主聊天仍依赖 DSH Session projection，不能证明前端主界面显示 Engine 结果。

## 风险与下一步

- 当前复制 UI 在真实窗口中可能只显示 DSH Session 的用户消息，不显示 Engine Worker 的结果；`chat` 回退是读取接口证据，不等于主聊天已接入。
- 下一步先设计 `/api/superagent` 的 v1 feed 和复制 UI 的投影替换，再删除旧 Host 依赖；在完成前不要把 T60 标为已实现。

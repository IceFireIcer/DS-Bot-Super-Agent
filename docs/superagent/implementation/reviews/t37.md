# T37 双轴审查记录

- 审查目标：`cc06d40...9881500`（首轮交付）。
- 审查方式：Standards 与 Spec 两个独立子代理并行审查，主代理汇总并修复。
- 后续修复：技能公开 provider、资产命名空间、断连续查入口、分页边界、工具启用条件等；修复后的验证见 `t37.md`。

## Standards

首轮结论：没有硬性标准违规；没有依赖私有 DSH 安装文件，没有写入密钥/用户 DSH 数据，`client.js` 未改，提交作者为 `IceFireIcer`，产品文案为英文。判断项及处置：

- `saveAttachmentTool`/`readAssetTool` 在本地与远端重复：已抽出 `attachmentToolInput`、`assetReferenceFromArgs`、`assetPageOptions`、`attachmentBytes`，本地、远端和 Engine 共用。
- `65536` 字面量与解码逻辑重复：已统一使用 `maxAssetBytes` 与 `attachmentBytes`。
- `assertMatchesEnvironment`、`skillAssetId`、`pruneSpill`、`asset.stat` 无调用：已删除，避免推测性入口。
- `{ maxBytes, spillBytes }` 数据团：已命名为 `AssetLimits`。
- `environmentFacts`/`reference` 名称不直白：已改为 `environmentIdentity`/`assetReference`。
- 本地与远端 `readAsset` 的 kind 分支：保留。附件/artifact/spill 的传输和存储位置不同，强行合并会掩盖环境差异；共享的参考解析与分页已抽出。
- `environment-assets.ts` 同时包含参考 schema、分页和文件存储：保留在同一模块，因为引用格式与内容寻址存储共享同一组不变量；后续若出现第二种后端再拆分。
- `t37-acceptance.mjs` 复制 T35 的 SSH 辅助函数：保留。每票验收脚本可独立运行是现有证据格式；提取公共 harness 会改变历史票的复现方式。
- `StrictHostKeyChecking=no`：沿用现有临时验收脚本；只连接本次临时 Ubuntu 设备，不是产品路径。

## Spec

首轮结论：主要缺口与处置：

- **技能只拒绝未映射**：已改为挂载公开 `@deepseek-ai/dsh-skill` + `@deepseek-ai/dsh-skill-filesystem`，本地与设备都只扫描部署 `skillsPath`，不读用户 DSH/agents 根；`list_skills` 与 `read_asset kind=skill` 在本地、远端和子代理中可用。
- **缺少第二设备证据**：已补 `dev/t37-acceptance.mjs`，真实 Windows→Ubuntu 10/10，并写入 `t37.md` 与 `linux-acceptance.md`。
- **断连后公开入口不能续查**：`Engine.readEnvironmentAsset` 已改为先 `prepare` 重新核验设备/根身份，再检查能力；新增 Engine 测试覆盖设备关闭→恢复→同一引用读取。
- **工具重绑引用导致无法拒绝外来引用**：Worker 工具只能在本 bound Environment 内构造引用，这是工具输入的边界；公开查询仍校验完整引用。跨 Environment 的资产库已按 `Instance + Environment` 命名空间隔离，新增测试证明同根不同命名空间不能凭 digest 互读。
- **artifact 被资产库门槛误拒**：已按 kind 分别检查；artifact 只依赖绑定 fs 和摘要，不需要 attachments/spill 支持。
- **`maxBytes` 为 1–2 时多字节字符可能不前进**：`pageOf` 在无法组成完整 UTF-8 字符时退回 base64 并保证 `nextOffset > offset`；测试覆盖。
- **未支持组合仍暴露工具**：`save_attachment` 仅在 attachments 可用时暴露，`list_skills` 仅在技能根可用时暴露；无资产/技能根的设备不再广告对应写入/技能工具。

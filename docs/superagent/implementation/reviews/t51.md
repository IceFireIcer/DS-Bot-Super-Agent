# T51 双轴审查

- 基线：`5c0d37f`；主代理按 Standards 与 Spec 两轴并行复核，修复后重跑定向、真实双进程、类型、lint 与串行全量。

## Standards

- **修复：** `begin` 原来把参数校验、archive、stop、restart、bind、heartbeat 和 verify 混在一个方法。现拆为 `validateBeginOptions`、`stopLegacy`、`disableLegacyRestart`、`isolateEntry`；`ingestGapInput` 的归属分类抽为 `classifyGapInput`。
- **修复：** `text(...)` 改名为 `boundedText(...)`；snapshot review 校验统一抛 `SWITCHOVER_SNAPSHOT`，不再混用 `SWITCHOVER_INPUT`。
- **修复：** 删除未使用的 `LegacyStopEvidence.stoppedAt` 和过早加入的 `activation` 字段；`heartbeatMs` 在校验通过后才写入实例状态。
- **修复：** `LegacyCore` 注释不再声称已有 desktop-host 实现；`close()` 在网络失败/存储已关闭时仍用 `finally` 释放 listener，避免遗留端口。
- **保留判断：** `Switchover` 仍同时拥有持久状态、TCP gap intake、archive 复核和旧核心适配编排。T52/T53 会改变 activation/回退边界，当前按一张票一个公开行为保持一个模块；进一步拆 `gap-intake` 类会把状态事务拆成跨模块协作，留到激活票再决定。
- **保留判断：** 两个测试文件各自保留 `freePort`/`netSend`/archive fixture helper。现有测试套件普遍采用单文件自足 helper；为两个文件抽公共 support 会增加跨测试耦合，收益有限。

## Spec

- **修复（阻断）：** 原实现只在 ingest 时相信调用方声明的 receipt state，最终 snapshot 没有和 gap buffer 对账。现在 `verify` 扫描全部 gap input：旧 snapshot 必须能找到 receipt；旧 accepted 覆盖 held；声称 accepted 但无旧事实、receipt cursor 不可比或 cursor 未覆盖的输入转 quarantine。新增旧 accepted 输入、伪造 accepted 输入、held 与 cursor 边界测试。
- **修复（阻断）：** 原来只停旧进程并占端口，没有持久停用旧重启入口。`LegacyCore` 增加 `disableRestart`/`restartDisabled`；`begin` 记录 disabled 证据，每次复核重读；真实演练把 launcher 改名为 `.disabled` 并证明原入口重启失败。
- **修复（阻断）：** `newEpoch` 原来只是调用方数字。现在 `begin` 读取当前 `HostLease`，要求 epoch 匹配、未释放且未过期；旧 home lock 只记录为 `usedAsFence: false`。新增伪造 epoch 拒绝测试。
- **修复：** 最终复核现在持久保存两次 checkpoint 的 active turns/jobs/outbound、increments、cursors、receipts、review 与 entry-held 事实，并在后续 increment/源 revision 变化时把 quiesced 降回 quiescing。
- **修复：** 重复 holder 只有在心跳新鲜且 intake 端口实际可连通时才复用记录；否则重新 bind。`close()` 先持久释放再关 listener，重复启动不会降级仍在工作的 holder。
- **保留（边界）：** `LegacyCore` 由宿主实现；本票的真实演练使用虚构 launcher/receiver，没有接入真实 DS Bot 的安装目录、Windows 服务或 systemd 自启动。真实部署适配与用户授权属于 T52/T55。
- **保留（边界）：** 不激活新消费；不创建 Ticket/Assignment/Effect；不对 gap input 调用 Engine。activation、缓冲按 ID 释放与唯一入口属于 T52。
- **保留（边界）：** gap intake 只 bind loopback；真实跨机旧核心、真实产品旧数据、UI 与远程迁移未运行。

## 结论

- Standards：0 个 hard violation；剩余判断是模块内聚与测试 helper 重复。
- Spec：三项阻断（gap 对账、持久重启停用、epoch fencing）已修复；剩余是真实旧核心适配/激活边界，明确留给 T52/T55。

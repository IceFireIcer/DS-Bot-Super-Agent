# T48 双轴审查

- 基线：`0c6a992`；主代理按 Standards 与 Spec 两轴并行复核，修复后重新运行定向、串行全量和 Session 验收。

## Standards

- **修复（硬）：** `Engine.createSupervisor(options)` 原先把 `...options` 放在身份字段之后，调用方可在运行时覆盖 `engine`/`storage`/`instanceId`/`actorId`。现在只解构允许的监督选项，身份字段由 Engine 最后决定；`version` 默认带当前 `roleConfigRevision`。
- **修复（硬）：** `Supervisor.decide` 原先只比较同一提案上的 commandId，且先执行 stop/direction 再写决定；并发批准可执行两次，commandId 也可跨提案复用。现在 `supervisor-decision` command record 带 `[proposalId, decision, reason]` fingerprint；事务内 CAS `proposed → deciding` 后才执行动作；并发决定只有一个 claim 成功，其余 `PROPOSAL_CLOSED`；动作后事务内完成 `approved`/`rejected`；崩溃或重放按派生动作 command ID 幂等续做。
- **修复（硬）：** 提案查询原先只扫一页 100 条，且 `getProposal` 靠全表扫描。现在提案 key 是稳定的 `["supervisor-proposal", id]`，`getProposal` 直接读取；列表/按 Ticket 过滤分页扫描最多 1000 条。新增 105 条提案的回归。
- **修复：** `SupervisorObservationResult.signal` 与 `AbortSignal` 同名易混。分类字段改为 `finding`，类型改为 `SupervisorFindingKind`。
- **修复：** `Watchdog` 与 `Supervisor` 各自复制 `bounded`。提取 `src/bounds.ts` 的 `boundedInteger`，两处共用。
- **修复：** `result()` 与 `writeObservation()` 都维护 `last`/`history`。现在 `result()` 只负责结果和历史，`writeObservation()` 只持久化。
- **修复：** `impact.scope: 'ticket'` 是固定值，删除；`wakesWorker` 对纠偏为 true（direction input），对暂停为 false。
- **修复：** 动作结果原先只记录 `{kind:'stop'}` 或错误字符串。现在 `action` 有 `status: done|failed`、bounded stop 摘要/direction input id、错误；失败不伪报成功。
- **保留判断：** `Supervisor` 仍从 `Record<string, unknown>` 的 supervision item 读取事实，`SupervisionItem` 目前是 `client-access.ts` 的局部模型。把它提升为公共监督模型会同时改 T24/T45 的消费者；本票保留局部规范化，后续 T55 可收敛。
- **保留判断：** `Supervisor` 仍是约 500 行的单模块，包含策略、提案、决定和观察存储。它们围绕同一组事实和预算；拆成四个模块会把一次巡检拆散。当前保留一个可审计入口。

## Spec

- **修复（阻断）：** 原实现的 `correct` 只调用 `addTicketNote`，note 不进入 Worker 的输入链。新增 `Engine.correctTicket({commandId, ticketId, text, reason})`，在既有授权下调用 `WorkInputs.attachSyntheticInput` 生成真实 direction input（basis `supervisor-correction`），Worker 下一回合读取；`Supervisor` 批准纠偏改走这个命令。`supervisor-engine.test` 验证 `getTicketDirection().inputs` 出现批准文本。
- **修复（阻断）：** unknown effect/job 原先只记 `unknown` 后停止。现在先调用既有 `reconcileRemoteWork`（stop 中则 `reconcileStop`），把 command ID、bounded 结果/错误写入 observation 的 `reconciliation`；不直接提案、不重放。无 runtime 时错误可见。
- **修复：** 提案原先不在监督视图。`Engine.getSupervision()` 现在为每个 Ticket 附带 `supervisorProposals`（当前 proposed）；公开 `getSupervisorProposals`/`getSupervisorState` 仍可单独查询。
- **修复：** 进度 fingerprint 原先不含请求/Mandate。现在包含 `request`、`mandateId`、`mandateScope`；目标或 Mandate 变化算进展，不会误报停滞。
- **修复：** 提案/观察版本只写 `supervisor-1`。现在 `createSupervisor` 默认 `supervisor-r<roleConfigRevision>`；Session assessor 在 assessment 中记录 `assessorVersion` 和 `model`；提案 evidence 保存 assessment。
- **保留（边界）：** 没有运行真实模型语义评估。当前有确定性正常等待/循环/no-progress/偏离用例、注入 assessment，以及真实 DSH Agent loop + mock 模型的独立 Session；没有 API key/模型端点，真实模型判断质量未报告。
- **保留（边界）：** 提案是 `supervisor-proposal` 事实，不是既有 `Attention` 行。这样不伪造 Worker 问题、不改变 Worker 输入链；监督视图可见，聊天 UI 的批准/拒绝按钮留 T55，外部通知未实现。
- **保留（边界）：** 暂停批准调用 `stopTicket`，不是可逆 pause；impact 明确需要显式 resume。纠偏是 direction input，不改变 Mandate、不执行 Worker 工具。
- **保留（边界）：** 同一 Instance 单 Supervisor 假设；没有额外协调锁。提案查询上限 1000；每 Ticket 提案预算 2 次/6 小时是动作预算，模型调用的 token/时间仍受既有 Session/模型预算约束。
- **保留（边界）：** 没有自动改角色/提示词/策略/模型；T49 负责版本化配置。语义纠偏只在用户批准后以既有 stop/direction 命令执行。

# T53 双轴审查

- 基线：`0ad0e09`；主代理并行 Standards/Spec 复核，修复后重跑定向、真实进程、类型/lint 与最终全量。

## Standards

- **修复：** `reverseIn` 在 ready/restart-failed 分支提升 Host epoch 时原只返回新对象、不落库；现在同一事务持久更新 reverseEpoch，status 与结果一致。
- **修复：** `LegacyRecovery` 拆出 `LegacyRestartControl`；`completeReverse` 只要求 enable/restart 检查，`abandon` 才要求完整 stop/snapshot 能力。`abandon` 的验证也明确要求 snapshot。
- **修复：** `completeReverse` 增加最终 compatibility 回调；兼容性在 ready 后变化会写 `COMPATIBILITY_CHANGED` blocker，且不启用旧入口。
- **修复：** 完成 reverse 时同时把 T51 switchover 记录置为 `abandoned` 并释放 entry，消除 activation=reversed、switchover=active 的矛盾。
- **修复：** 真实进程演练加入 held gap：activation 释放 marker 一条、旧 receipts 为空、source 不变；最终真实 child 中断/新 epoch 恢复。
- **保留判断：** `abandon`/`reverseIn` 仍较长，命令幂等、外部 stop/restart、状态和 blocker 分类集中在一个模块；T55 UI 接入前拆分会提前固定恢复界面契约。
- **保留判断：** blockers 仍是带引用的文本码（`UNKNOWN_EFFECT: id`），没有结构化 `{code,message,ref}`；与当前 migration 模块的可读记录一致，结构化留给 T55 的读模型。

## Spec

- **修复（阻断）：** reverse 完成只改 activation，T51 switchover 仍显示 active。现在同一完成事务置 switchover 为 abandoned、entry 释放，查询不再矛盾。
- **修复（阻断）：** complete 只检查重启能力，未重查旧核心权限/格式/作业兼容性。现在 `compatibility` 是 final gate 的必需回调，失败保留 blocker 且不重启。
- **修复（阻断）：** 真实进程没有两侧 gap 归属。现在 activation 释放一个真实 held gap，process marker 恰一条；reverse 后旧 receipts 仍空、source state 不变，证明新核心接受不重放进旧队列。
- **修复：** real Engine pending outbound 作为 reverse blocker 的定向测试已补，避免空 evidence 的 adapter 直接 ready；停止执行仍由宿主 control 提供，文档明确该 seam。
- **修复：** abandon 测试加入 batch-2 archive，放弃 batch-1 后两个 archive 都保持 published，source 不变。
- **修复：** 中断 reverse 与 ready 后 epoch 前移都持久化；同一 reverse command 恢复不重复外部 stop。
- **保留（边界）：** `ReverseControl` 是宿主适配器，不是 Engine 内置的全量停止器；真实 Electron/产品旧团队、跨进程 gap holder 和用户数据迁移未运行。
- **保留（边界）：** abandon 对 held/quarantine 保守阻塞；用户核查和显式处置留 T55。

## 结论

- Standards：0 hard violation；剩余判断是模块内长方法和文本 blocker 结构。
- Spec：switchover 状态矛盾、final compatibility、真实两侧 gap 归属、Engine outbound blocker 与 batch 保留均已修复；执行停止器与真实应用边界明确留给宿主/T55。

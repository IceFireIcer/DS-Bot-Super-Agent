# T56 双轴审查

审查目标：T56 生产 Engine factory 注入 `ds-bot` Host 的工作树 diff。Standards 与 Spec 两个子审查并行执行，随后按发现修复并重跑定向测试。

## Standards

初始发现：

- `ds-bot` 与 `ds-bot-host` 都注册 adapter cleanup，所有权重复。
- 服务 adapter 的 close 路径没有独立断言。
- stop 测试只检查命令回执，没有检查可见活动状态。
- production factory/adapter 吞掉 cleanup 错误，可能把未释放的 Engine/Session/Effects 报成成功。
- 进程恢复测试只用 item 数量判断重复，证据不够独立。

处置：

- 删除 `ds-bot` 侧的 adapter close；由提供服务的 `ds-bot-host` 插件持有生命周期。
- `close()` 和 factory `dispose` 聚合错误并抛 `AggregateError`；close 后拒绝新 scope。
- stop 测试等待 `live()` 不再显示活动。
- 进程测试比较完整 Session 页的 `seq` 集合和用户消息数。
- 剩余 judgement：测试 fixture 与 host 测试有少量重复的 mock 设置；本票保留独立进程/进程内两种证据，暂不抽象成共享 helper。

## Spec

初始发现：

- 只有 adapter/factory，没有证明真实 `ds-bot` profile 使用它。
- 真实进程只测 prompt/deliver，没有 stop/resolveAgent。
- 缺少 `executionAdapterRequired` 时仍可静默走旧路径。
- `resolveAgent` 仍 unsupported，会破坏现有 Host 的部分路径。
- `chatPage` 的 `NOT_FOUND` 处理需要说明，避免掩盖真实缺失。

处置：

- 新增 `ds-bot-host-profile.test.mjs`：真实 `ds-bot` `install()` 消费插件服务。
- 真实进程 fixture 改为加载 `ds-bot-host` 插件并通过 `ds-bot` `install()/executionDispatch()` 完成 prompt、deliver、resolveAgent、stop；第二个进程重放同一请求。
- 新增 `executionAdapterRequired`，缺失 adapter 时明确失败；测试覆盖。
- `resolveAgent` 新增 UI Session facade，映射 followup/cancel/status/whenIdle；group/steer 继续 fail-closed。
- `chatPage` 只在 assignment 已存在且 Session 尚未物化时返回空页；真实缺失仍抛错。
- 剩余边界：真实模型/信道归 T57；app 打包 wiring、托管 Host 和第二设备归 T58；本地 delivery 仅是账本，不冒充平台回执。

## 结论

Standards 硬性发现已清零；Spec 的实现缺口已补到 profile seam 和真实进程层。T56 不宣称完整产品验收，T57/T58 的边界保留。

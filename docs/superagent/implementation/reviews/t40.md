# T40 双轴审查

- 审查基线：`7eeabd7`。
- 审查方式：两个独立只读子代理分别按 Standards 与 Spec 审查 T40 diff；主代理核对、修复后重跑验证。
- 范围：`Engine.requestHandoff` / `getEnvironmentHandoff`、`Execution` 交接状态机、目标重验、交接提示与准入 gate、`NativeSessions.flush`、交接测试与第二设备验收脚本。

## Standards

- 采纳：交接记录、阻塞项、状态判断、提示文本和持久化抽到新模块 `src/environment-handoff.ts`，`Execution` 不再因交接承担多个不相关改动原因（Divergent Change）。
- 采纳：`requestEnvironmentHandoff` 拆成锁入口、边界阻塞、阻断落库、切换事务和阶段方法；`Engine.requestHandoff` 抽出 `handoffTarget`、`revalidateHandoff`、`verifiedHandoffCopy`，消除与 `prepareHandoffCopy` 重复的前置与重复越权判断。
- 采纳：`uniqueBlockers` 只保留一份（`work-copy.ts` 导出），`engine.ts` 与 `execution.ts` 的重复实现删除；active job/subagent/preview 判断抽成 `activeBackgroundBlockers` 并被边界与切换事务共用；交接提示不再有第二个副本。
- 采纳：`WorkerTurnRequest` 取代 8 个位置参数；轮次原因收敛为 `TurnCause`，准入激活级别和提示文本由同一判定派生（Repeated Switches / Data Clumps）。
- 采纳：阻塞项类型从 `WorkCopyBlocker` 改为 `HandoffBlocker`，因为其中包含 stop、活跃工作、session flush 等非工作副本原因（Mysterious Name）；`handoff` 布尔改为 `contextHandoff`，与 `environmentHandoffId` 区分。
- 保留：`requestEnvironmentHandoff` 仍是分阶段编排方法；每段已抽成有名字的阶段函数，再拆文件只会把同一流程的局部变量跨模块传递。
- 保留：`Execution` 仍需读取 jobs/subagents/previews/slots 以决定安全边界；这些是 Assignment 生命周期的既有归属，不构成 Feature Envy。

## Spec

- 采纳（D19「停止/查询/对账原 job」）：交接记录新增 `settledJobs`，remote job 还要求 `rangeSettled`，并写入 `jobs-reconciled` 步骤；active 或 unknown 范围继续硬阻塞，不把未静止范围写成已静止。
- 采纳（D19「flush 后校验目标与交接内容」）：flush 后重新解析目标并重新 verify 副本，失败记录 `target-ineligible` / `handoff-copy-*` 并保持旧 Assignment；目标在 flush 期间离线或换代不会被误报完成。副本仍必须在 flush 之前就存在，避免白 flush。
- 采纳（D13「稳定 command ID + 同事务回执」）：`completed` 记录与 `work-command` 回执在同一事务写入；重放返回原记录，不再新建一次交接 UUID。切换前若已有 `requested/flushing/switching` 记录，新请求以 `HANDOFF_IN_PROGRESS` 失败关闭，并保留原进度（T41 负责对账继续）。
- 采纳（D09「未承接工作继续」）：交接提示 turn 若 setup 失败，`promptStartedAt` 在同一事务清除，`retrySetup` 重新入队同一条交接 relay；提示不会再因一次失败被永久标记为已消费。
- 采纳（并发）：同一 Ticket 的交接请求在进程内串行，避免两个请求同时通过副本核验后重复 flush/切换。
- 保留（T41 范围）：`requested/flushing/switching` 崩溃后的启动对账与继续不在 T40；当前行为是失败关闭 + relay 继续 defer，不产生双执行。
- 保留（T39 范围）：实际文件传输仍是显式同步；T40 只重新核验并切换执行世界，不新增自动传输 API。

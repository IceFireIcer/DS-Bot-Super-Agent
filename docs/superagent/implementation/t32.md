# T32：配对授权远端设备并完成文件与搜索任务

- Issue：[T32 / #60](https://github.com/IceFireIcer/DS-Bot-SuperAgent/issues/60)。
- 固定实施基线：`f17abbe`（仓库改名后的 `dev` 头部）。

## 已交付

- `RemoteDevice` 在设备侧打开一个显式绝对工作目录，只暴露 `read`、`write`、`search` 三类文件能力；不装载 Router、Worker、DSH Session、业务数据库或 Outbox。
- 配对使用设备端一次性八位码、Host 端 X25519 密钥和 Ed25519 设备签名。设备签名覆盖配对 transcript、X25519 交换键和 sealed 载荷，Host 必须提供 `expectedDeviceId` 与设备签名公钥指纹，首次配对即 pin；不在日志、错误或响应中回显配对码。
- 设备把 `(instanceId, environmentId, allowedActorIds, permissions)` 作为显式 grant；配对时要求与 Host 请求完全一致。每次 RPC 都重新读取当前 grant，不信任配对时的权限快照；授权被移除或收窄后立即拒绝文件操作，越权返回 `GRANT_DENIED`。
- 配对与 RPC 载荷使用 X25519 + HKDF-SHA-256 派生的 AES-256-GCM 加密并认证；请求带时间窗和请求 ID 重放保护。传输保护在应用层完成，不依赖 TLS，也不读取 Host 的 `rg`、路径或同名文件。
- 设备把静态身份、incarnation 与配对授权持久化到显式 `statePath`；原子写失败时不会留下“已配对但响应未送达”的内存状态。Host 可用 `snapshot()` / `RemoteEnvironment.restore()` 恢复连接；状态含 Host 私钥，只能放入受保护存储，读回后仍由设备校验配对是否已撤销。
- `RemoteEnvironment.revoke()` 先在设备侧持久化撤销，再让 Host 停止使用该连接；设备不可达时 Host 本地也进入撤销态并报告失败，不会继续悄悄执行。设备操作者还可用 `RemoteDevice.listPairings()` / `revokePairing()` 在本地停掉某条连接，不需要等 Host 主动撤销。
- `RemoteEnvironment` 作为新的 `ExecutionEnvironment` 被 Engine 使用。Assignment 记录 `kind: remote`、设备 ID、incarnation 与实际设备目录；`conversation().executionLocation` 可查本次实际执行位置。
- Worker 工具按 Environment 权限裁剪：远端 Assignment 只有 `write_file`、`read_file`、`glob`、`grep`，没有 `run_command`、后台 job 或 `delegate_subagent`。越目录、绝对路径、链接、受保护文件和未知工具均被拒绝。
- 设备侧 glob/grep 自己遍历授权目录，返回相对路径、行号与有界文本；不使用 Host `node:path` 盲转发，也不把设备绝对目录写进搜索结果。
- 远端写入后的 ready report 需要一次成功的写后 `read_file` 或 `grep` 作为证据；没有 command 能力时不再沿用本地“必须运行验证命令”的规则。
- `dev/remote-device.mjs --config <absolute-json> --pairing-code-file <absolute-path>` 是设备侧最小入口；配对码写入 0600 文件，stdout 只输出 endpoint、设备 ID、公钥指纹与文件位置。监听 `0.0.0.0`/`::` 时必须配置可达的 `advertiseHost`，否则拒绝启动，不会返回不可用的 loopback 端点。

- `test/remote-execution.test.mjs`：真实 Engine + NativeSessions + mock 模型；Host 与设备各有同名 `answer.txt`，Worker 首次读取得到设备内容，写入/读取/glob/grep/artifact 均发生设备目录，Host 文件不变；Assignment 与 `executionLocation` 记录 remote 设备；撤销后新提交拒绝；无命令工具的 ready 报告在缺少写后文件证据时被拒。
- `test/remote-device-process.test.mjs`：独立 Node 进程启动设备守护进程，通过 `dev/remote-device.mjs` 写配对码文件；Host 跨进程配对、写入、读取、grep 并撤销。
- 真实第二设备（2026-11-09）：Windows Host → 临时 Ubuntu 6.8 x86_64 云服务器（2 vCPU / 1.9 GiB）。设备以 Node 24.22.2 和 `listenHost=127.0.0.1` 启动，Host 经 SSH 本地端口转发配对；Linux 设备目录已有 `same-name.txt`，Host 同名文件保持不变。Host 读取到 Linux 内容，写入 `cross-os.txt` 后读取/glob/grep 均返回相对路径；artifact SHA-256 `bda38c...3ad2` 与服务器 `sha256sum` 完全一致。Host 快照关闭后恢复并重新读取成功；撤销后设备状态持久记录 `revoked: true`，再次 prepare 返回 `DEVICE_REVOKED`。
- Linux 全量回归：Node 22.23.4 **269/269**（106.7 s）、Node 24.22.2 **269/269**（106.4 s）；两版 `typecheck`、`lint` 均通过。Linux 与 Windows 平台差异也由同一套跨 OS 远端读写/搜索验收覆盖。

## 边界

- 真实第二设备验收已完成，但使用 SSH 本地端口转发，没有直接向公网暴露设备端口；生产部署仍需自定网络边界、防火墙和 `advertiseHost` 配置。
- 传输保护是原创应用层 AEAD，不是 TLS；静态 X25519 不提供前向保密，设备公钥 pin 是配对信任前提。生产部署仍需网络分段、受保护状态文件和设备侧最小权限。
- T32 只开放远端 fs/search。远端 command、后台 job、PTY、预览、子代理、附件/技能/Office/MCP 与跨设备交接仍属于后续票；这些组合不会以本地能力替代，也不会静默回退。
- 设备端符号链接检查与文件操作之间仍存在本地高权限写者利用 TOCTOU 的理论窗口；设备工作目录应按部署要求只允许受信写者。
- 没有真实设备上的性能预算、长时间断连、Host 重启接管或设备撤销后的跨机清理验收；这些不在本票冒充完成。
- T32 的代码与真实第二设备验收均完成；仍为 open，等待推送、合入与发布。

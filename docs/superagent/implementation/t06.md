## 行为

接单时，来源 Thread 与原 Ticket 建立持久订阅。后续来源事件在同一接收事务内完成 fan-out：逐目标保存订阅依据、作者、addressing、事件类型、归属和原因；来源 receipt、fan-out、Input、方向版本、intent 与 relay 意图一起提交。队列故障会回滚整次接收，后续使用原 command ID 恢复。

同 Thread、当前版本且由允许人类发出的 direct/mention 消息成为稳定 Worker Input。Input 按 `(Ticket, sourceEvent)` 去重，方向版本逐项递增；Router 再研判该事件时返回 `ALREADY_OWNED`，不调用语义层，也不创建第二张 Ticket。未列名、ambient、删除、过期投影和 stop/waiting 约束保留为可查询的 context fan-out，不取得 Worker ownership。

有效跟进直接进入原 Ticket 的 Worker；Ticket 仍开放时复用 Assignment 和 Session。已交付并自然 ended 的 Ticket 可由自有 Thread 的合法人类跟进恢复同一 Ticket；恢复事务记录原 Mandate、Decision、policyVersion 和来源证据，重新开放后再派发。结果交付后，无约束的 Ticket 自然结束。原 Mandate 不因跟进扩大。

公开 `getTicketDirection(ticketId)` 返回当前状态、方向版本、订阅、Input、全部 fan-out 决策与恢复决定。`conversation(ticketId)` 继续提供最新 report/message 投影，并新增 `reportHistory` 与 `messageHistory`，恢复跟进不会覆盖旧结果和交付依据。所有 ownership、fan-out、恢复、报告和交付历史查询声明 1,000 条硬预算；超过时明确失败，不静默截断。

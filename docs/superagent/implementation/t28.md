# T28：用定时来源产生可追溯且不重复的候选

- Issue：[T28 / #56](https://github.com/IceFireIcer/DS-SuperAgent/issues/56)。
- 固定实施基线：`a13db2e`。

## 已交付

- `ScheduleSource` 具有独立 `ruleId`、时区、间隔、持久 `schedule-state` 和稳定 occurrence ID；occurrence 由规则本地墙钟边界推导，ID 是该边界对应的真实 UTC 时刻。
- 规则按 revision 持久化：interval、文本、补发策略变化形成新 revision；同一 `ruleId` 修改时区被拒绝。`ruleHistory()` 与每次 tick 的 `schedule-occurrence` 证据都支持 `limit`/`after` 游标查询。
- 每次 occurrence 记录规则 revision、来源事件 ID 与时间；来源事件可通过 `getSourceObject` 重查。
- 首次 tick 产生当前 occurrence；同一 tick 重放不重复；漏执行按 `skip`/`once`/`all` 与 `maxCatchUp` 上限补发。
- 时区参与计算：DST 回拨的重复本地小时不二次触发；DST 前拨不存在的本地时刻被跳过；`once` 会越过不存在的时刻推进到下一个真实边界。
- interval 变更形成新 revision 时，下一槽位按新网格重新对齐，不复用旧网格的相位。
- 旧版缺少 revision 的 `schedule-rule` 行在首次使用前归一化，避免历史数据产生无效 revision。
- 每个 occurrence 只经 `receiveSource` 进入普通 Gate；来源类型为 schedule 且 actor 与来源实例一致时，`system` 事件可由推断规则（observe/auto）处理，显式规则仍只属于人类直接请求。
- 暂停仍记录 occurrence 事实；暂停期间 Gate 拒绝评估，恢复后同一事实才可接单。

## 真实隔离计划运行（2026-11-09）

- 真实时钟：规则 `acceptance`、`Asia/Shanghai`、1000 ms、runner 400 ms，运行约 3.4 s。
- 产生 4 个连续 occurrence（间隔 1000 ms），各有一条 revision 1 的来源事件证据；持久规则的 revision 与时区正确。
- 关闭并重新打开同一 SQLite、重建 Engine/Source 后，按原最后时刻 tick：新增 0 个。
- 真实 occurrence 经 Intake Policy `auto` 评估后被接受，形成正常 Ticket；没有用 `acceptSource` 绕过 Gate。
- 暂停后按可控时间记录一个新 occurrence；Gate 以 `PROCESSING_PAUSED` 拒绝，恢复后同一事实被接受。

## 边界

- 验收使用的 Gate assessor 是确定性的注入回调，不是真实模型；不证明模型研判质量或主动准备结果（T29）。
- 重启证据是同进程内的存储重开，不是独立进程重启；进程级恢复由既有 SQLite 恢复测试覆盖。
- DST 回拨/前拨与 interval 重对齐由可控时间单测验证，不是等待真实 DST 日的运行证据。
- 规则版本化界面属于 T49；本票只提供公开查询。
- 没有 host/CLI/UI 入口；规则与触发证据目前只通过公开 Engine 查询。
- T28 仍 open，等待合入 `dev` 与发布。

# T33：在远端启动稳定身份的命令并续读输出

- Issue：[T33 / #61](https://github.com/IceFireIcer/DS-SuperAgent/issues/61)。
- 实施基线：仓库改名为 `DS-SuperAgent` 后的 `8b4cde9`。

## 已交付

- 远端权限新增 `command`。设备配置显式列出最多 16 个固定 `argv` 的命名命令、前台 deadline、可选后台 deadline 和显式环境；Host 只收到命令名与时限，不收到 `argv` 或设备环境。命令型 grant 必须至少配置一个命令，配置命令也必须提供持久 `jobsPath`。
- 设备自己解析 executable：裸名按设备 PATH/PATHEXT 查找并校验可执行位，绝对路径必须存在且是文件；相对路径带分隔符被拒绝。解析结果是设备上的规范路径，不是 Host 的 `targetKey`、作业 ID 或文件名。每次启动前重新核对设备工作目录的 `dev/ino/birthtime`，目录被替换返回 `ENVIRONMENT_CHANGED`。
- `RemoteSubprocess` 是 Host 侧的公开 provider 适配器。`spawn({ name, mode })` 同步返回 `RemoteJobHandle`，其公开形状与 DSH `SubprocessHandle` 的收集模式一致：`stdin/stdout/stderr/control` 为 `undefined`，`collected.stdout/stderr.readFrom(offset)` 是非消费字节读取，另有 `done`、`terminate()`、`waitForExit(signal)`。Provider 仍由设备执行命令和持有真实进程；原始管道、PTY 与终端接口不在 T33，未支持组合不启用。
- 作业 ID 由 Host 在发送前生成，格式为 `job:<instanceId>:<environmentId>:<deviceIncarnation>:<uuid>`。设备按当前 pairing 的 Instance、Environment 和自身 incarnation 校验前缀；同一 ID 携带不同命令、argv、环境、cwd 或 deadline 返回 `IDENTITY_CONFLICT`，不会再次启动。启动响应丢失时 Host 先用同一 ID 调 `command.inspect`，确认作业存在就继续观察；查不到则保持 unknown，不自动重新 spawn。
- 设备为每个作业保留最多 8192 字节的有界 stdout/stderr，按整字节偏移返回增量；读取不消费窗口，重复读取相同偏移得到相同内容。返回值在 UTF-8 字符边界截断，多字节字符跨读取或跨断连不会出现替换字符。`lossy` 明确报告内存尾部丢失。
- 作业记录写入显式 `jobsPath`：每个作业一个原子替换的 JSON 元数据文件，加上 stdout/stderr 追加文件。正常结束的作业和输出在设备 daemon 重启后仍可按原 ID 查询；重启时原状态为 `running`/`stopping` 的作业不能证明原进程仍归本 daemon 管理，统一恢复为 `unknown` 并保留已收到的输出。设备最多保留 64 个作业记录，超过后先清理已结束记录，仍有活跃记录则返回 `JOB_BUDGET`。
- 取消先写 `stopping`，设备向同一子进程发 `SIGTERM`，250 ms 后升级 `SIGKILL`；只有观察到该子进程 `close` 才返回 `cancelled`。Host 的 `waitForExit` 只有在同一作业进入 `exited`/`cancelled` 且 `settled` 时返回 `true`，未知或不可观测不伪报停止。
- Host 在 `RemoteBoundEnvironment` 上提供 `resolveExecutable`、`run_command`、`spawnCommand`、`startCommand` 和 `attachCommand`。`attachCommand(jobId)` 用稳定 ID 恢复同一作业观察；新配对的 Host 也可在 `prepare` 后接回。Worker 仅在 `command` 权限和配置命令同时存在时获得 `run_command`、`start_command`、`job_status`、`keep_preview`、`cancel_job`；ready report 在有命令能力时要求写后成功命令，没有命令时才沿用文件读取/搜索证据。
- 设备命令环境从父进程剔除 `DSH_*` 与凭据形状变量后，再合并显式 `env`；`PATH`/`PATHEXT` 统一为大小写规范键，Windows 与 POSIX 都能用同一配置解析。stdin 固定 `ignore`，不启用 Shell、PTY 或任意 argv；Windows 只接受 `.exe`/`.com` 原生可执行文件，`.cmd`/`.bat` 等未验证脚本组合返回 `UNSUPPORTED_CAPABILITY`。

## 边界

- 只管理单个直接子进程，没有 PTY、进程树取消、任意 argv 或 Shell；设备后代进程是否随父进程退出不在本票证据内。
- 设备 daemon 崩溃后保留终态输出和 unknown 事实，不能恢复原进程继续运行；Host 接管、多分钟断连和宿主间租约竞争仍由后续恢复/接管票验收。
- 真实设备使用 SSH 本地端口转发，没有直接暴露公网设备端口；生产部署仍需网络边界、防火墙和受保护状态/jobs 目录。
- 命令组合只在显式配置且授权时启用；未配置命令、只读 pairing 或撤销连接都不会回退到 Host 本地命令。

## 行为与边界

接单沿用 T01/T17 的事务和稳定身份。提交后的 notice 驱动原生 Router；只有受限 assign_worker 工具能创建当前 Assignment 与持久 relay。Worker 使用独立原生 Session，原文输入不经 Router 摘要改写，只开放 report_ready。报告必须有非空结果和验证依据；idle、普通文本和越权调用不能形成 result。

ready 报告、Assignment、原生 Session 日志与业务 Session 引用分别保存。Worker 回合结束并完成公开 flush 后记录 ready 投影，再通知同一 Router Session。Router 的 deliver_result 工具只接受当前 Assignment 的 ready 报告，通过有序 Outbox 将结果与确认写到原消息位置。重复入站复用原回执、Assignment 和交付。原生循环每次最多八个模型步，默认 15 秒 turn 预算；配置的 Effects 超时必须更长。

`createChatServer(engine)` 提供只绑定 loopback 的隔离统一聊天入口，显示 pending/running/ready、确认、结果及可展开的验证和 Session 引用。`node dev/chat.mjs` 启动真实服务与真实 DSH loop，使用原创脚本 LlmAdapter，无密钥；示例请求为 `What is 2 + 2?`。浏览器状态保留已接受消息，失败重试复用 command/event 身份。HTTP 校验 Host/Origin、请求体和 CSP；这是受信本机预览入口，未切换旧 Bot 生产输入。

Session 使用 DSH 第一方 JSONL provider，显式隔离临时根目录；T15 的 SQLite Session provider、重启恢复和 T19/T20 fencing 未由本票冒领。真实模型、外部信道和设备仍须对应后继验收。界面证据同样明确标注脚本 mock，不能称为真实模型结果。

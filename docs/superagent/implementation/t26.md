# T26：跟踪 PR 交付条件直至工作结束

- Issue：[T26 / #54](https://github.com/IceFireIcer/DS-SuperAgent/issues/54)。
- 固定实施基线：`3e807ea`。

## 已交付

- `bindDeliveryCondition` 把一条 P/R 交付条件绑定到 Ticket，记录来源实例、repo、编号、依据与创建者；同一 Ticket 可以绑定多个 P/R。
- ready report 仍可交付结果，但只要还有 `open`/`draft` 条件，Ticket 保持 `open`，`conversation.deliveryPending` 为 true，`deliveryConditions` 可查。
- `reconcileDeliveryCondition` 从已接收的来源文本按 P/R 编号推进状态（draft/merged/closed/open），保留 `result` 与 `reason` 依据；全部条件终态且结果已投递后，Ticket 才结束。
- 多 P/R 分别判断；存在未处理 Input 时即使条件已关闭也不结束（承接跟进未完延迟结束）。
- 结果交付仍经过 Outbox；准备权限不产生发布、合并或自动合并动作。
- 评审与 CI 事件进入同一 Ticket 的原始工作，`ready` 后仍继续核查交付条件；条件全部终态且无未处理 Input 时才结束。
- 只有 result 的交付回执为 `sent` 时结算条件才结束 Ticket；`pending` 或 `dropped` 不冒充已送达，Ticket 保持 open，结果仍可随后交付并结束。

## 真实仓库验收（2026-11-09）

- 隔离仓库 `IceFireIcer/SuperAgentTest`：真实创建 Issue #13、分支、PR #14、review 5820849029，并等真实 CI check run 128938483337 完成（`success`）。
- ready 后 Ticket 仍为 `open` 且 `deliveryPending: true`，证明结果就绪不会因 Agent idle 自行结束。
- PR 合并后二次轮询收到真实 `merged` 事件，`reconcileDeliveryCondition` 把条件置为 `merged`，Ticket 变为 `ended`，`result`/`reason` 带真实 PR 文本。
- 合并动作由验收脚本以人工授权步骤调用 `gh pr merge`；新核心本身没有自动合并权限，也没有在准备阶段发布。

## 边界

- 模型为 mock；本票验证的是交付条件与真实 PR 生命周期，不是模型产出质量。
- 多 PR、关闭但承接未完成、结果交付经 Outbox 的路径由 `delivery-conditions.test.mjs` 覆盖，不替代另一条真实仓库轨迹。
- draft 条件与“结果未送达前不得结束”的回归由 `delivery-conditions.test.mjs` 覆盖。
- T26 仍 open，等待合入 `dev` 与发布。

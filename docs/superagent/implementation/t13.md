- Issue：[T13 / #41](https://github.com/IceFireIcer/DS-SuperAgent/issues/41)。依据：规格 v2.1 D01/D06/D08/D14，A08/A09/A33，用户故事 67、72。
- 固定实施基线：`68047eb`；实现提交：本票提交。
- 公开测试边界：`Engine.listSubagents`、`getSubagent`、`cancelSubagent`、`stopTicket`、`resumeTicket`、`conversation`、`listSlots`，`Subagents`/`BackgroundWork` 契约，以及真实 DSH 子 Agent（`ctx.agents.create({ parentAgent, meta: { origin: 'subagent', delegationDepth, parentSession } })`）、真实本地 Environment 与 mock 模型的原生集成。未使用真实模型、外部账号或用户 DSH 数据。

## 行为

Worker 通过新的 `delegate_subagent` 原生工具委派一个受限子任务：立即返回 `subagentId`、状态与开始时间，不等待子任务完成。子代理是真正的 DSH 子 Agent——用 `ctx.agents.create()` 的公开 `parentAgent` 入口创建，Session 头写入 `origin: 'subagent'`、`delegationDepth: 1` 和 `parentSession`，因此运行期归属与持久血缘都由 DSH 记录，而不是我们另造一套。`subagent_status` 读取状态与有界结果（默认 16 KiB，超出标记 `truncated`），`cancel_subagent` 由 Worker 自行取消。

继承范围是父 Worker 已解析好的那一个世界：同一个 `BoundLocalEnvironment` 的绝对工作目录、同一 Instance/Actor 授权与同一 Ticket Mandate，以及同一套本地工作工具（`write_file`、`read_file`、`glob`、`grep`、`run_command`）。子代理不继承父任务的后台 job 工具（`start_command`/`job_status`/`cancel_job`）：那些闭包属于整个 Ticket，交下去会让子代理看到或取消父任务的 job，而参考语义是"子代理结束时其 job 一并结束"，本票因此直接不给。子代理也永远拿不到 Router 工具（`assign_worker`、`deliver_result`）、`report_ready`、`ask_human`、Thread 订阅、handback，也不再拿到 `delegate_subagent`，因此不能提交结果、不能提问、不能扩大授权、不能继续嵌套委派。子 Agent 使用 worker 模型路由，工具通过 `scoped.tools.restrict({ allow: [] })` 清空全局可见集后用 `defineTool` 逐个注册，作用域是子 Session 自己的，不与父或另一个 Worker 共享；子工具调用也使用独立的调用计数，不消耗父回合的 24 次预算，也不能替父任务满足 `report_ready` 的验证前提。

子任务完成事件以 relay 送回原 Worker 的同一 Session，正文带子任务 id、状态与有界结果，本身不构成 ready；它按 `activation: 'background'` 走普通槽，不占人工的额外槽。回合结束时若仍有子代理在跑，Ticket 保持 `worker-background` 并继续持槽（与 T12 的后台 job 共用同一份后台工作账目）。迟到结果只有在 Ticket 仍 open、无 constraint、且 Assignment 的 id 与 generation 都仍是当前代次时才唤醒。

清理按归属进行：`stopTicket`、`cancelSubagent`、交付（ready）与交回人工（waiting-human）都会以该原因持久取消相应子代理，再通过 DSH 的 `agent.cancel({ kind: 'parent' })` + `whenIdle()` 结束子 Agent 并释放作用域。取消分两段：先写 `cancelling`，只有在声明清理预算内观察到子 Agent 静止后才写 `cancelled`；观察不到时记 `unknown`，绝不读作已停止。每 Ticket 默认最多 2 个并发子代理（`subagents.maxPerTicket`，在启动事务内检查）、默认 10 分钟声明期限（`subagents.deadlineMs`），到限终止子 Agent 并把 deadline 事实送回 Worker。子 Agent 的结果在窗口内保留原始记录，不做自动删除；单票查询有界为最新 100 条。

应用关闭时 `Engine.shutdown()` 先取消所有子 Agent，再停止 Effects；子 Agent 句柄不会漏到下一个 runtime。没有被本进程持有的 running 记录（崩溃后重启、或本进程已丢失句柄）在读到时记为 `unknown`，因此不会永久占槽。

## 支持的继承组合与公开 API 边界

已验证可用：

- 子 Agent 由 `ctx.agents.create({ sessionId, parentAgent, meta: { cwd, origin: 'subagent', delegationDepth, parentSession }, agentOptions, setup })` 创建；`isOwnedBy(child, parent)` 在父 Agent 存活期间为真。
- 子 Session 的 cwd 就是父 Assignment 的绑定目录；子工具是父已授权工具的子集，作用域独立，且子工具调用单独计数，不消耗父回合预算，也不能替父满足 `report_ready` 的验证前提。
- `agent.cancel({ kind: 'parent' })` 会中止子 Agent 的活跃回合，`whenIdle()` 在预算内确认静止。
- 子 Agent 可以比父回合活得更久：父回合结束、甚至父 Agent 句柄释放后，子 Agent 仍能继续并写回自己的 Session。
- 子回合的结束原因取自它自己的持久 Session `turn/end`：`completed` 才算成功；`error`/`max-tokens`/`blocked`/`interrupted` 记 `failed`，父、人或宿主停止发出的 `aborted` 记 `cancelled`，其他 `aborted` 与没有完成记录记 `failed`。因此“Agent 变 idle”不会把一次失败的子任务报成成功。

本票的实现边界（不使用未经验证的组合）：

- 本票没有迁移到 `@deepseek-ai/dsh-subagent` 的 `startActivation`。该包在本 DSH 版本已发布且提供 `stopReason` 与生命周期事件，但本地路径需要宿主装配 `workingDirectory`、`sessionQuery` 与 preset 组合，属于一项独立的运行时迁移，不能在本票的收尾修复里顺带替换掉已验证的执行路径。当前实现使用同一版本已公开的 `ctx.agents.create({ parentAgent, meta })` 入口，并以 Session `turn/end` 作为结果事实。
- DSH 的 `parentAgent` 只表达“运行期归属”，会随父 Agent 释放而失效；它不提供跨回合的自动级联停止。因此本票用持久 Session 血缘（`parentSession`/`origin`/`delegationDepth`）表达“原代次”，由本核心按归属显式取消与对账。多级嵌套委派因此不支持：子代理不获得 `delegate_subagent`，`delegationDepth` 固定为 1。
- 子 Agent 的工具集由本核心在 `setup` 中显式注册，不使用 harness 内部 preset；子 Agent 的结果取自它自己的 Session 事件，并保留 `truncated` 标记。

## 验证

```sh
cd superagent
npm run typecheck
npm test
npm run lint
npm run build
node dev/subagents.mjs
```

2026-11-08，Windows x64 / Node 25.4.0：新核心全量 **152/152** 通过（T13 新增 10 项），typecheck 与 lint 无错误。T13 定向覆盖：子代理写入父目录并由父 Worker 收到完成事件、子工具集只有 5 项本地工作工具（无 Router/交付/提问/job/再次委派）、子代次记录父 Mandate 与父代次、两个 Worker 绑定不同 Environment 时各自子代理只写自己的目录且互相 `NOT_FOUND`、子回合以 `turn/end` 的 `error` 结尾时记 `failed`，人工取消与子回合自身取消记 `cancelled` 且不唤醒 Worker，子代理跨父回合存活并占用槽、stop 取消子代理且迟到结果不唤醒、每 Ticket 并发预算、声明期限、恢复换代后迟到结果仅审计、stop 无法确认时保持 `stopping` 并拒绝 resume。

`node dev/subagents.mjs` 在声明负载（4 个子任务、每个 3 步、50 ms 扫描）下实测：从接单到父回合交出控制（`worker-background`）约 171–203 ms；子代理“在跑”的峰值 4，且在子代理运行期间父 Ticket 仍持有执行槽；每个子代理只拿到 5 项本地工作工具（无 job/交付/提问/再次委派）。这些数字来自确定性 mock 负载，不是模型或生产 SLA。

## 边界

本票验证受限子代理的继承、完成回送、槽预算与按归属清理，不实现交付验收时的预览服务与槽释放（T14），也不代替 T54 的性能比较。真实模型、外部信道、第二设备与正式部署验收仍待对应票；上述数字来自确定性 mock 模型与真实 DSH 子 Agent/Session，不是生产吞吐或 SLA。

多级嵌套委派、子代理流式输出与跨设备/远端子代理不在本票范围内，已在实现中明确拒绝。迁移到 `dsh-subagent` 的 `startActivation` 需要另立一张票：它要一并接入 `workingDirectory`、`sessionQuery` 与 preset 组合，并重做现有的取消、结果与槽语义，属于运行时替换而不是本票的收尾修复。

## 收尾修复（2026-11-08）

- 子回合失败曾被记成成功：现在从子 Session 自己的 `turn/end` 读取结束原因，`error`/`max-tokens`/`blocked`/`interrupted` 记 `failed`，父、人或宿主停止发起的取消记 `cancelled`，其他 `aborted` 与无完成记录记 `failed`。新增回归测试。
- 目录隔离测试改为给两个 Worker 绑定不同的 Environment 根，并断言彼此的产物互相不存在；原先两者共用同一目录，只证明了不同文件名。
- 基准改为测量“接单到父回合交出控制”的真实延迟、子代理在跑的真实峰值，并在子代理运行时断言父 Ticket 仍持有执行槽；原来的 6 ms 是接单耗时，峰值把已结束的子代理也累计了进去。

- `NativeSessions` 创建 Session 时把工作目录写入公开的 `meta.cwd`；此前使用的 `sessionMeta` 不是 `CreateAgentOptions` 的字段，父 Worker/Router 的 cwd 实际没有落到 Session 头。该字段修正随本票一并验证。
- 人工 `cancelSubagent` 记 `cancelled` 且不唤醒 Worker 的回归测试已补齐；取消路径与子回合自身 `turn/end: aborted` 的记录规则分开说明。

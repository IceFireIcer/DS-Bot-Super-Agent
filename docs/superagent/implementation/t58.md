# T58：组合托管 Host、断连撤销、接管与第二设备

- Issue：[T58 / #92](https://github.com/IceFireIcer/DS-SuperAgent/issues/92)。
- 状态：**部分验收**。真实远程 Host、PostgreSQL、客户端断连/补读、撤销、Watchdog 替换和 Ubuntu 设备执行已完成；离线 stop、双向交接、T59/T60 远程 UI 和飞书仍未完成。
- 日期：2026-11-13。

## 环境

- 操作者指定的临时 Ubuntu，Linux `6.8.0-101-generic` x86_64，2 vCPU / 1.9 GiB；服务器地址不写入仓库。
- 安装 Node `24.22.2` 和 PostgreSQL `16.15`；业务库与 Session 后端均在同一隔离 PostgreSQL 数据库 `ds58`。
- Windows 是主设备/客户端；Ubuntu 是远程 Host 和第二设备。没有使用同机 loopback 作为 Host 的业务/Session 后端。
- 客户端和 Host 之间使用 SSH 本地转发，因此网关本身绑定 Ubuntu loopback；用户明确暂不配置 TLS。网络传输由 SSH 保护，不宣称生产 TLS。
- 真实模型：`pro.pokexiao.com` / `deepseek-v4.1-flash-1017`；密钥只存在于服务器 600 权限文件，未写入仓库或日志。

## 已交付入口

- `superagent/dev/t58-host.mjs`：托管 Host。使用 PostgreSQL 业务库和 `session-persistence-postgres`，注册真实模型，启动客户端网关、本地 Environment 和 Ubuntu 设备 Environment；写原子状态文件并响应 Watchdog IPC shutdown。
- `superagent/dev/t58-client.mjs`：Windows 独立客户端进程，只调用公开 client-gateway 协议；支持 state、submit、events 和按游标等待结果。
- `superagent/dev/t58-admin.mjs`：使用同一 PostgreSQL 业务库撤销一个客户端。
- `superagent/dev/t58-takeover.mjs`：独立 Watchdog 启动 Host、强杀后替换，并读取 PostgreSQL Host lease 的新 epoch；模型 key 文件通过环境变量/参数注入，不写死服务器个人路径。
- `superagent/src/execution.ts` 修复跨 Ticket 历史污染：`reportHistory`/`retryHistory`/`sessionRollover` 共用扫描现在只接受当前 Ticket 前缀，避免客户端补读到下一条 Ticket 的结果；新增回归测试。该修复是 cursor 补读正确性的前置，不扩展 T58 的领域行为。

## 未完成边界

- **T56 production factory / T59 / T60 UI 没有接进这条远程组合。** 当前 `t58-host.mjs` 直接构造公开 `Engine`，没有使用 `createDsBotHostAdapter`；app 的 `ds-superagent` profile 是本地 Host，UI 的 `/api/superagent` 也没有远程 client-gateway 传输；T58 的 remote desktop UI 连续性和四目标连续报告因此未验收。
- **离线 stop、同范围静止确认和显式 resume 没有运行。** 设备重连后可以继续新工作，但没有证明运行中的远程作业在设备离线、Host stop 和回连后的完整轨迹。
- **本地↔远端双向交接没有运行。** 设备文件/命令执行已真实通过，但保留未提交/未跟踪内容、双向切换和旧回调隔离仍缺组合证据。
- **飞书未验收。** 维护者已在 T57 明确暂缓；T58 不把飞书列为通过。
- **Host 与设备共处 Ubuntu 服务器。** 这是用户指定的“Windows 主设备、Ubuntu 第二设备”拓扑；它不是独立物理设备，不能据此宣称跨两台执行设备的故障隔离。

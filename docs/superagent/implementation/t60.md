# T60：复制聊天界面为 `ds-superagent-ui`

- 票：[T60](../issues/T60.md)（本地票，尚未发布到 GitHub）。
- 状态：**本地 v1 实现与定向检查通过，完整 CI 待远程确认**；真实模型、托管 Host 和第二设备仍属于 T57/T58。
- 日期：2026-11-12。

## 实现

- `superagent/ui` 从 `ds-bot/src/client/` 与 `ds-bot/src/shared/` 复制聊天单元格、问题卡、主题、布局和图形资源，生成独立 `ds-superagent-ui` bundle；生成文件只由 `scripts/build-client.mjs` 写入。
- `superagent/ui/index.js` 和 `cordis.patch.yml` 提供独立 DSH 插件入口；只注册单会话入口、复制来的聊天展示组件和单一 Super-agent 侧栏项，未挂载团队、群聊、浏览器、附件、steer、记忆、日程、用量和密钥入口。
- `superagent/ui/src/client/api.js` 只调用 `/api/superagent`。聊天数据通过 v1 feed 投影到复制来的 `ChatRows`、气泡、问题卡和主题布局。
- `superagent/host` 只通过公开 `connection.fetch.register` 注册六个 v1 endpoint：`state`、`send`、`evidence`、`answer`、`stop`、`resume`。不再挂载旧 `ds-bot` Host，也没有 `/api/bot` 路由。
- `state` 只投影已发送的 acknowledgement、result 和 answer；Worker 内部 report 只有经过 Router 和 Outbox 成为 sent delivery 后才显示。游标使用 `ClientAccess` 的持久序号并按 100 条补读，避免随全量历史增长。
- profile 初始化、关闭和失败路径都关闭 Engine、Session 和 SQLite 资源；数据仍在独立 `DSH_HOME/core/state.sqlite`。

## 来源与范围

- 复制来源是仓库现有 `ds-bot/src/client/` 和 `ds-bot/src/shared/`，不修改原 UI。新 `superagent-chat.js` 只把复制的聊天结构接到 v1 feed，并复用 `ChatRows`、`Bubbles`、`PendingQuestion`、主题和样式。
- 未使用的复制模块保留在独立包中作为来源和后续扩展材料，生产 bundle 开启 tree shaking；未挂载的入口不会出现在新页面。
- 新文案通过复制的 `i18n.js` 的 `t()` 查找，新增 Super-agent 文案也有中文映射；输入框保留可见焦点环。

# T08：就地提出人工问题并由授权回答继续

- Issue：[T08 / #36](https://github.com/IceFireIcer/DS-Bot-SuperAgent/issues/36)。依据：规格 v2.1 D06/D07/D10/D17，A05/A09/A13，用户故事 10、11、12、45、89。
- 固定实施基线：`15a2e60`；实现提交：`c5ff37e`。
- 公开测试边界：Worker `ask_human`、`Engine.answerAttention`、`getTicketAttention`、`conversation`、chat preview `/answer`、Effects/Outbox 和原生 DSH Session mock。

## 行为

Worker 可用 `ask_human` 提出一个有界问题及最多十个候选选项。系统把问题、当前 Assignment/Session、来源目标、当前来源事件和顺序写入 Attention；Ticket 进入 `waiting-human`，当前 Assignment 结束，问题通过 Outbox 作为 `attention` 消息返回对应消息或发起处。提问后本回合的本地工具、报告和订阅修改均被封住。

回答命令必须绑定当前 Attention。直接 UI 回答来自受信本地 actor；若带 `sourceEventId`，还会验证来源实例、当前投影、人类作者、名单、问题接收人及同一 Thread。回答通过后清除 waiting 约束、追加真实来源 Answer Input、递增方向版本、复用原 Assignment/Session 继续。重复同 command 幂等；已回答或已取代的问题返回 `ATTENTION_STALE`，不能覆盖新问题或唤醒其他工作。

waiting 是持久 Ticket 约束：普通跟进只形成 blocked context，不启动 Worker；其他 Ticket 独立运行。新问题取代仍等待的旧问题，旧待发问题 Outbox 会以 permanent `dropped` 结算，不阻塞后续交付。`getTicketAttention` 和 `conversation` 暴露当前问题、稳定顺序历史及最新回答。Chat preview 在等待状态显示问题、选项和回答表单，动态样式使用页面 CSP nonce。

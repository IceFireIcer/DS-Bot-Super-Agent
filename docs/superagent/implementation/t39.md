# T39：准备并核验可交接的跨设备工作副本

- Issue：[T39 / #67](https://github.com/IceFireIcer/DS-SuperAgent/issues/67)。
- 实施基线：`4fb2106`。
- 规格：v2.1 D06、D11、D14、D19；A28、A29；用户故事 30、86、87。

## 已交付

- 新增只读 Git 工作副本预检 `WorkCopySnapshot`：记录仓库根、base commit、branch、全部 tracked 文件的哈希、修改/新增/删除/未跟踪变更、总变更字节、patch 字节数与 SHA-256。扫描上限 16 MiB / 2000 文件，变更上限 8 MiB / 500 文件，patch 上限 1 MiB；超出明确 `handoff-blocked`，不生成部分清单。
- `Engine.prepareHandoffCopy({ commandId, ticketId, targetEnvironmentId })` 读取固定 Assignment 的源 Environment 和目标 Environment，比较 commit 与目标现状，持久化 `handoff-copy` 及历史。未知目标修改、目标 commit 不同、目标已有不同内容、源目录非 Git 根、rename、符号链接、Git 不可用、预算超限都成为具名 blocker；预检不改变 Assignment、不启动执行、不写目标文件、不读取 Host 路径替代远端。
- `Engine.verifyHandoffCopy({ commandId, ticketId })` 重新读取源和目标；源在 prepare 后变化、目标缺少变更、目标出现未列出变更或内容哈希不符时保持 `handoff-blocked`。只有 commit、全部源变更哈希和目标无额外变更都一致时才写 `verified`。
- `Engine.getHandoffCopy(ticketId)` 查询最新记录；记录含源/目标 EnvironmentLocation、Assignment ID、base commit、branch、变更文件、patch、总字节、blocker、prepare/verify 时间。公开 `HandoffCopyView` 通过可选 `preparedAt`/`verifiedAt` 区分预检与核验。
- `PreparedEnvironment.inspectWorkCopy()` 是本地/远端共用的只读环境能力。设备新增 `workcopy.inspect` RPC，Host 只在该 Environment 授权范围内调用；缺少 read 权限或 Git 时阻塞，不回退 Host 文件系统。
- 实际文件传输不在本票：清单是明确的同步清单，T40 用它执行安全 handoff；T39 只准备、核验和报告 `handoff-blocked`，不把缺少同步证据误报成外部 unknown。

## 边界

- 只支持 Git worktree；非 Git 目录、rename/copy、符号链接、超出扫描/变更/patch 预算均明确阻塞。二进制内容只参与哈希和 patch 预算，不改写为文本。
- 不做实时双写，不自动传输、不覆盖目标未知文件，不切换 Assignment；这些属于 T40。
- preflight target 是显式目标，只受 Environment/actor 授权约束；T40 在真正 handoff 时重新核验 Ticket/Mandate 目标并结束旧 Assignment。
- 不做跨 Host 共享存储、Session flush 或旧回调隔离；分别留在 T40/T41。

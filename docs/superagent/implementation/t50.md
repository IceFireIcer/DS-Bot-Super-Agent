## 已交付

### 1. Prepared staging，不提前发布

- 新增公开 `ds-superagent/legacy-archive`：`prepareLegacyArchive`、`verifyLegacyArchive`、`publishLegacyArchive`、`getLegacyArchive`、`listLegacyArchives`、`readLegacyObject`。
- source 与 target 必须是分离的绝对路径；target 必须是空目录或已有 archive store；source 必须包含 `bot/state.json`。target 不能包含 source，source 也不能包含 target。
- `prepare` 写 `<target>/.staging/<batchId>` 下的 `manifest.json`、state、Session、memory、review/mapping；`archives/<batchId>` 在 `publish` 前不存在。manifest 保存 source path/identity/profile、source digest、state revision、batch ID、mapping/digest、计数、Session/checksum、review 和 limits。
- 同一 batch/source/mapping 重试幂等；source 或 mapping 变化得到 `ARCHIVE_CONFLICT`；已有目标不会被覆盖。batch/role/Session id 做路径安全校验。
- credentials（`.credentials.yaml`/`.env`）和原始 profile patch 不复制；`profile` 只作为 source identity 证据，模型配置不进入档案。

### 2. 校验 Session、缺失历史和副本一致性

- Session 接受 `session.v<version>.jsonl[.zstd|.zst|.gz|.br]`，版本 1–4；压缩日志用 Node zlib（zstd/gzip/brotli）解压后检查 JSON 与连续 `seq`。未知格式、更新格式、截断、空缺和缺失 Session 都让 verify 为 `invalid`，`publish` 拒绝。
- `verify` 检查 staging 的每个 checksum（state/Session/memory/review/mapping/roles），重新计算 source digest；source 变化为 `SOURCE_CHANGED`。`publish` 会再次 verify，之后才原子 rename；tampered staging、source change、existing target 都不会发布。
- `readLegacyObject` 只读已发布档案；文件/内存分页有 offset/limit 和 path containment 检查，Session 按原 seq 读取；压缩日志解压后读取。
- 源目录不写入；测试对虚构 source 做 tree hash，prepare/verify/publish/失败/取消/重试后保持不变。

### 3. 角色、共享记忆和待核查项

- `mapping.roles` 按 source Bot ID 生成 `mapped-roles/<id>.json`：name/roleLabel/instructions/model 来自显式映射或旧 Bot 事实；`sourceMainBot` 只是证据，`permissions: []`、`readOnly: true`，不继承 Main Bot 权限。
- `mapping.sharedMemory` 允许 `team` / `group:<roomId>`；写 `mapped-memory.json` 记录文件、digest；所有 memory 保留为历史，`readLegacyObject` 对映射内 memory 标 `shared: true`，私有 memory 标 `shared: false`。未来角色导入使用 mapping，不把私有记忆当共享。
- `bot/workspace` 和 `attachments` 是 opt-in `include`（默认不复制），保持 D18 的团队/群/记忆/Session 历史范围。
- `state.works`/`requests`/`questions`/`agents` 与 `bot/inflight.json` 只形成 review items；未完成、stopped、unknown 明确列出，done/ended/completed/cancelled 不当作待核查。没有旧 Agent loop、没有新 Ticket/队列。
- `work:`/`request:`/`question:`/`agent:`/`inflight:`/`bot:`/`room:`/`role:`/`review:`/`memory:`/`session:`/`file:`/`attachment:` 都按原引用可查；completed work 仍可读，只是不在待核查列表。

## 使用方式

```js
import { prepareLegacyArchive, verifyLegacyArchive, publishLegacyArchive, readLegacyObject } from 'ds-superagent/legacy-archive'

await prepareLegacyArchive({
  source: '/absolute/legacy-home', target: '/absolute/archive-store', batchId: 'batch-2026-11-11',
  sourceIdentity: 'legacy-team', profile: 'desktop',
  mapping: { roles: [{ sourceBotId: 'bot-chief', name: 'Chief' }], sharedMemory: ['team', 'group:room-ops'] },
  include: { workspace: true, attachments: true },
})
await verifyLegacyArchive('/absolute/archive-store', 'batch-2026-11-11')
await publishLegacyArchive('/absolute/archive-store', 'batch-2026-11-11')
const memory = await readLegacyObject({ target: '/absolute/archive-store', batchId: 'batch-2026-11-11', ref: 'memory:team/MEMORY.md' })
```

## 边界

- **档案不接入 Engine。** 这是文件式只读迁移入口，不会自动成为运行中的业务库/Session；切换、旧核心停用和激活属于 T51–T53。
- **默认不复制 工作目录和附件。** 只有调用方显式 `include` 才进入档案；D18 的默认范围是团队/群/记忆/Session。
- **memory 全量保留，但只有 mapped scope 标共享。** `mapped-memory.json` 与 `shared` 标志供未来角色导入使用；档案读取仍是历史查看，不会写新 memory。
- **state.json 原样复制。** 它可能包含旧团队本地配置；credentials 和原始 profile patch 不复制。测试使用虚构隔离数据，不读取用户 DSH。
- **不支持跨机传输或真机旧数据。** source/target 在同一主机；真实远程迁移、旧数据清理和真实产品数据验收未运行。
- **没有 UI。** 公开模块/命令和 manifest 可查；设置/迁移界面留 T55。
- **没有激活或自动回退。** T50 只准备并发布档案，不创建新队列、不恢复 old agent loop、不继承 Main Bot 权限。
- 没有发布；没有等待 CI 结论。

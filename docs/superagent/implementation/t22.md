# T22：上下文满后换 Session 并继续未完成工作

- Issue：[T22 / #50](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/50)。依据：规格 v2.1 D07、D09、D11、D13，A10、A16、A31。
- 固定实施基线：`78d5917`。

## 交付行为

Worker 回合以 DSH 的 `turn/end.reason.kind = "max-tokens"` 作为上下文耗尽事实。此时新核心不会把回合当作 idle 或 ready，而是：

1. 用 DSH 公开的 fork seed 从原 Session 的事件前缀构造新 Session，保留父 Session 血缘与继承 cut；如果 live fork 不可用，则新 Session 以显式交接文本继续。
2. 在业务事务中结束旧 Assignment，创建新 Assignment ID/generation，保留 Ticket、目录和 Mandate。
3. 写入 `session-rollover`：旧/新 Session、旧/新 Assignment、目标、Mandate、约束、未处理 Input、证据引用和是否成功 fork。
4. 将意图置为 `context-rollover`，排入带 `handoff: true` 的 relay。

新 Session 的第一条 Worker 指令显式包含原目标、Mandate、当前约束和未读 Input，并要求先用 `read_context` 读取原始请求与证据、检查文件/版本控制/外部状态后再修改。旧 Session 的事件仍可通过公开 `engine.getSessionHistory(sessionId, { after, limit })` 读取。

迟到事件仍只回到产生它的 Assignment generation。进程在交接提交前退出时，旧 Assignment 仍是当前代；在交接提交后退出时，启动恢复扫描 `context-rollover` 意图并对当前 Assignment 重新排入交接 relay，不丢工作。

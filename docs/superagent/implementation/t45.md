## 已交付

- `Engine.createClientAccess()` 在 Engine 已取得的 Host fencing 存储上创建 `ClientAccess`，并复用同一个 Instance 身份。独立构造的 `ClientAccess` 仍可用于隔离测试，但生产入口不会再绕过 T44 的 Host 租约守卫。
- `ClientAccess.enroll()` 只返回一次 `sc1.<clientId>.<secret>` 凭据；持久记录只保存 SHA-256，不保存明文。重复同一个 `commandId` 返回同一个客户端且不再返回 secret；同一 ID 的标签或授权不同则得到 `IDENTITY_CONFLICT`。客户端只能获得当前服务 Instance 的授权，并显式区分 `read` 与 `command`；为另一个 Instance 授予凭据会在写入前被拒绝。
- `ClientAccess.revoke()` 持久记录撤销时间与原因。认证在每次请求重新读取数据库，撤销后的下一次查询或命令立即得到 `CLIENT_REVOKED`，不需要重连；跨 Instance 或缺少相应能力得到 `INSTANCE_NOT_AUTHORIZED`。
- `createClientGateway(engine, access)` 提供专用客户端入口。路径固定在 `/instances/<instanceId>/...`；`GET state`、`events`、`tickets/:id`、`conversations/:id`、`receipts/:id` 需要 `read`，`POST commands/{submit,answer,stop,resume,retry,status}` 需要 `command`。没有设备路由，也没有暂停、作业、预览或子 Agent 管理路由。
- 入口只允许 loopback 明文 HTTP；绑定其他地址必须配置 TLS key/certificate，否则在启动前得到 `TRANSPORT_INSECURE`。请求要求 Bearer 凭据、`application/json`（允许 charset 参数）和有界 JSON 对象；无效 JSON、非法游标和超出输入预算的请求返回 400。
- 客户端事件日志是持久事实：每个事实有稳定内容 key，重复投影不会新增事件；`seq` 单调递增并按 12 位十进制存储，`after` 为排他游标，分页返回 `cursor` 与 `hasMore`。`reconcile(engine)` 把当前 supervision 的 state 快照写为事件，并从持久 `attentionHistory`/`reportHistory` 补读每个 Attention 状态和每个 result，而不是只看当前报告；随后按 1,000 条一批追加，避免大快照被单次输入预算截断。
- 命令成功后写回执事件。回执记录失败不会把已经成功提交的命令报告成失败，而是返回 `CLIENT_JOURNAL_UNAVAILABLE`，客户端用原 `commandId` 重试即可返回原回执；同一个命令的重复回执只保留一个事件。
- loopback 聊天入口新增受同源保护的管理面：`GET /clients`、`POST /clients`、`POST /clients/revoke`。它只给当前 Instance 授权、列表不返回 secret/hash，未配置 `clients` 时明确返回 `UNSUPPORTED_CAPABILITY`。它只是本机受信运维入口，不是公网客户端 API。
- 公开导出新增 `ClientAccess`、`createClientGateway` 及类型，并新增 `./client-access`、`./client-gateway` 包入口和构建入口。

## 使用方式

```js
import { createClientGateway } from 'ds-superagent'

const access = engine.createClientAccess()
const gateway = await createClientGateway(engine, access, {
  tls: { key: process.env.CLIENT_TLS_KEY, cert: process.env.CLIENT_TLS_CERT },
})
```

```text
GET  /instances/private/state
GET  /instances/private/events?after=<cursor>
POST /instances/private/commands/submit
```

## 验收证据

### 独立客户端进程断连与补读

`test/client-process.test.mjs` 用独立操作系统进程运行 `test/fixtures/client-runner.mjs`，不是同进程函数调用：

1. 第一个客户端进程读取 `state.cursor`、提交请求并退出；Host 在客户端不存在时继续完成 Worker 与 Router 工作。
2. 客户端离线期间，同一 Ticket 通过显式 retry 产生第二个结果；新进程从保存的游标读取 `events`，收到一次漏掉的 receipt 和两个历史 result，各只出现一次；随后再按新游标读取为空。
3. 同一进程用原 `commandId` 重试提交，返回原回执，事件日志不新增事件。
4. 撤销后新进程访问 `state` 得到 401 `CLIENT_REVOKED`。

### 入口、授权与传输

`test/client-gateway.test.mjs` 覆盖：

- 同一 Instance 的 `read`/`command` 分别授权；只读客户端不能提交命令，只有命令能力的客户端不能读状态。
- 跨 Instance 路径、其他 Instance 的 grant、缺失或伪造 token 均被拒绝；设备路径不存在。
- 回执查询、Ticket/Conversation 查询、事件游标分页与重复命令回执重放。
- 非 loopback 无 TLS 启动被拒绝；自签名 TLS 监听可完成认证请求，明文端口不能完成同一请求。
- 无效 JSON 返回 400，`application/json; charset=utf-8` 正常接受，非法事件游标被拒绝。
- `ClientAccess` 与 Engine 的 Instance 不一致时拒绝启动入口。

### 管理面与日志领域行为

`test/client-admin.test.mjs` 覆盖 loopback 管理面的 enroll/list/revoke、只读授权、列表不泄露 secret/hash、重复 enrollment 不再返回 secret、缺失字段/非法能力被拒绝，以及未配置客户端访问时的 `UNSUPPORTED_CAPABILITY`。

`test/client-access.test.mjs` 覆盖一次性凭据、Instance/能力隔离、撤销即时生效、游标分页去重、状态快照与 Attention/result 历史补读去重。

## 边界

- 本票按 Issue 允许的方式先用本机独立操作系统进程验证客户端协议；**未运行**真实 Electron 桌面到隔离 Host 的断连、重连和撤销组合。`app/` 当前不消费 `ds-superagent`，该托管组合由 T55 汇合，不能据此宣称真实桌面验收已完成。
- 当前客户端采用拉取/轮询游标，没有服务端推送订阅；日志 key 没有回收/压缩策略，长期运行需要后续容量治理。
- `reconcile` 跟随现有 supervision 的 100 个 Ticket 窗口；窗口外的 Ticket 仍可按 ID 查询其持久 `reportHistory`/`attentionHistory`，但不会自动出现在本轮事件补读中。`state` 事件表示当前快照，Attention 与 result 才按持久历史逐项补读。
- 客户端入口只暴露查询与六种控制命令；设备操作、后台作业、预览、子 Agent 和 Worker 工具权限不因此扩大。
- 客户端列表最多返回 100 项，没有分页管理面。受保护传输在本票用自签名证书夹具验证，不代表生产证书、域名、mTLS 或公网网络质量已验收。
- 未完成真实模型、外部信道、第二设备或托管部署验收；本票未发布。

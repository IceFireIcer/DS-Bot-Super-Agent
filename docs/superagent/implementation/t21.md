# T21：沿证据卡片和分页入口读取完整上下文

- Issue：[T21 / #49](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/49)。依据：规格 v2.1 D03、D05、D11、D17，A15、A16、A18、A40。
- 固定实施基线：`78d5917`。

## 交付行为

新增公开 `engine.readContext({ ticketId, ref, after?, maxBytes? })`。卡片支持 ticket、trigger、decision、mandate、report、attention、delivery、source-event 与 source-thread；每张卡片返回稳定引用、标题、摘要、正文页、事实、下一跳引用和分页事实。

正文按 UTF-8 字节分页，默认 4096、允许 256–16384 字节；游标只接受本卡片产生的字节位置。截断页明确 `truncated: true`，拼接各页可重建全文；不会把截断页伪装成完整正文。

Worker 新增只读 `read_context` 工具。它可以读取原始请求、授权、当前报告、人工问题和 Outbox 回执，不必依赖 Router 摘要；`kind`、`id`、`threadId`、`objectId`、`after`、`maxBytes` 都是显式参数。状态回合不获得该工具。

读取遵循 Ticket 归属：source-event 与 source-thread 只能来自原始 Thread 或该 Ticket 的合法订阅；直接猜另一个 Thread 的事件或分页会被拒绝。卡片只暴露本 Ticket 的 decision、mandate、report、attention、delivery 与可达来源，不把其他 Ticket 的对象作为邻近结果返回。Correlation 只提供显式引用和下一跳，不据此自动路由或合并工作。

本地聊天预览新增 `/context` 同源查询，并在报告证据区提供 “Read original request” 入口；界面与 Worker 使用同一个公开读取契约。

## 验证与范围

2026-11-09，Windows x64 / Node 25.4.0：新核心全量通过，typecheck、build、lint 通过。

新增回归覆盖：

- 含多字节字符的长请求在 512 字节页中逐页重建，页大小不超预算，非法游标被拒。
- 真实 native Worker 通过 `read_context` 读到原始请求，随后提问、回答并产出 ready；公开卡片可读当前 attention、delivery 回执与 ready report。
- 两个来源 Thread 的 Ticket 不能读取彼此的 source-event 或整段 history；自己的 Thread 可读。
- 聊天页提供同一上下文入口，`/context` 返回与公开 Engine 相同的卡片。

本票没有实现跨月长期记忆质量、相似度排序或自动关联；只交付有界、可核查、按归属授权的读取入口。

## 已交付

### 1. 关闭窗口与退出服务是两种操作、两种状态

- 托盘菜单先显示一行不可点击的 Host 状态：`Host running`、`Starting the Host…`、`Host not running`、`Host could not start`，电脑休眠时显示 `Paused while this computer sleeps`；工具提示同一状态。下面才是 `Open DS Bot` 和 `Quit DS Bot`。
- `src/shell.mjs` 暴露 `status()`、`isSuspended()`、`suspend()`、`resume()`；`src/tray.mjs` 每次状态变化重新标注菜单和工具提示。
- 关窗口仍是隐藏，Host 继续；托盘 Quit 仍是唯一正常退出入口。首次关窗提示改成“只要电脑没有休眠，关掉窗口时 Bot 们照常工作”，不再把休眠说成继续执行。

### 2. 休眠/唤醒与中断恢复

- `powerMonitor` 的 `suspend`/`resume` 接到 shell：休眠时状态变为暂停；唤醒时清掉主进程的 `suspended`，重新读取 Host。
- Host 还活着：窗口重新加载 Host 的普通地址，补读隐藏期间 Host 保留的状态。
- Host 没活下来：`hostFailure` 在休眠期间只记录 `deferredFailure`，不弹错也不退出；唤醒时先停掉旧 Host、释放数据锁，再在同一 profile、同一数据目录、同一端口启动新 Host，窗口用新启动地址重新接入。
- 唤醒以外的启动失败：错误框提供 `Try again` / `Quit`。`Try again` 不重走首次启动的位置和导入，只重启 Host；目录或账号修好后可直接重查。首次启动本身没走完仍按原设计在下次启动重新询问。
- `HostProcess` 新增 `isRunning()` 和 `pid()`：shell 能判断 Host 是否还在，数据锁能记录 Host 子进程。

### 3. 同一份数据只允许一个活动 Host

- 新增 `src/host-lock.mjs`：在数据目录写 `host.lock`，记录 Host 子进程 PID 和端口，临时文件加 rename 原子替换。
- 启动前检查锁：锁里的 PID 仍存活且不是本进程时拒绝再启动一个 Host，错误信息给出 PID 和端口，走 `Try again` / `Quit`；PID 已死或记录损坏则覆盖。停止 Host、替换 Host 时释放自己的锁。
- 这补的是“shell 已经不在、Host 子进程却还活着”的窗口：单实例锁只挡第二个 shell，数据锁挡第二个 Host。正常关闭窗口仍只是隐藏，不会释放锁，也不会启动第二个 Host。

### 4. 升级只改 profile，不动 Host 数据

- `claimBundles` 仍把应用 bundle 排在最前，保留用户 bundle、依赖、`dsh.profile.preset`、其他 profile 设置和 manifest 其余字段；重复升级不改文件。
- `test/upgrade.test.mjs` 在隔离数据里预置业务 `bot/state.json` 和 Session 文件，升级后逐字节比较不变。
- 业务库和 Session 后端的备份/恢复、拒绝不支持 schema、迁移中断恢复由 T17/T42/T43 的公开契约承担；本票重新运行这些契约，应用侧只负责不覆盖它们。

### 5. 安装、更新、工具能力边界不变

- 没有改安装包、更新器、`profile-boot` 入口或 Host 进程归属；Host 仍由 `app/src/host.mjs` 用 `runProfile()` 启动，Linux 用随包 Node，Windows/macOS 用 Electron 的 Node 模式。
- 模型端点和本地执行位置仍相互独立；本票没有新增模型路由或执行位置逻辑。

## 验收证据

### Windows 原生：窗口与假 Host（真实 Electron）

`npm run check-lifecycle`（Windows 11、Electron 44.7.0、Node 24.22.2；假 Host、无 DSH、无用户数据）：

1. 窗口显示 Host，托盘显示 `Host running`；
2. 关窗口后窗口隐藏，Host 的工作计数继续增长；
3. 托盘打开原窗口，页面补读到隐藏期间的工作；
4. 窗口被销毁后托盘新建窗口，仍连同一个 Host（`hosts === 1`）并补读；
5. 休眠时状态为 `Paused while this computer sleeps`，休眠中关窗口不退出应用，唤醒后恢复 `Host running`；
6. 托盘 Quit 结束应用。

### Windows 原生：真实 App + 真实 DSH Host

`npm run check-resident`（Windows 11、真实 `app/`、真实 DSH 0.2.1-rc.4、临时 `DS_BOT_HOME`/`DS_BOT_SHELL_DATA`、无模型）：

1. 窗口显示真实 Host 和 Bot 团队（页面含 `Chief`）；
2. 关窗口后 Host 仍以原端口提供页面，应用没有退出；
3. 第二次启动交给已运行实例，窗口回来，端口文件不变，仍是同一个 Host；
4. 显式退出后应用以 0 结束，Host 端口停止监听；
5. 强杀应用后 Host 停止，重新启动仍在同一数据、同一端口恢复团队。

## 使用方式

```sh
cd app
npm ci
npm test
npm run check-lifecycle   # 真实 Electron + 假 Host，需要桌面
npm run check-resident    # 真实 App + 真实 DSH，临时数据，需要桌面
```

`check-resident` 结束时停止本轮 Electron/Host 并删除临时目录；不读取或写入用户自己的 `~/.dsh` 或桌面应用数据。

## 边界

- **没有真的让 Windows 进入休眠。** 休眠/唤醒事件路径由真实 Electron shell 的 `shell.suspend()/resume()` 和 `powerMonitor` 接线验证；“Host 在休眠中死亡、唤醒后替换”由假 Host 单测验证。真实 OS 睡眠周期、真实注销/关机（而不是强杀进程）没有本次运行证据，不能据此宣称 A36 的真实休眠项已全部通过。
- **真实 DSH 检查没有模型。** 它证明真实 Host、页面、团队、端口、重启和退出路径；隐藏期间“实际模型工作继续并补读”由假 Host 的确定性工作计数证明，不是真实模型回合。
- **真实 App 的关窗检查用的是页面 `window.close()`。** 该路径下渲染目标会从调试端口消失，所以 `check-resident` 能证明应用和 Host 继续、第二次启动能回来，但不能从页面侧证明“隐藏而不是销毁”；隐藏/未销毁由真实 Electron 的 `check-lifecycle` 断言。
- **备份恢复不是应用代码。** T17/T42/T43 的契约证据在本轮重新运行；T46 只证明升级不改业务/Session 字节、保留 preset 和用户配置。没有新增应用侧备份/恢复入口。
- **首次 setup/账号仍是 DSH 自己的界面。** 登录、API key、模型设置和来源配置由 DSH 页面提供；本票新增的是 Host 启动失败后的重试，以及首次启动/目录问题的重新询问/重查，不是新的账号管理界面。
- **app 仍不消费 `ds-superagent`。** 新核心的客户端网关与真实桌面组合仍由 T55 汇合；本票的“Host/客户端”是现有桌面应用的 DSH Host 生命周期。
- 没有发布、真实模型、外部信道、第二设备或托管部署验收；没有等待 CI 结论。

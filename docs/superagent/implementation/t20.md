# T20：在本机协调 Host 写权与合法接管

- Issue：[T20 / #48](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/48)。依据：规格 v2.1 D09、D13、D14，A21、A30、A31。
- 固定实施基线：`3c6a4a0`。

## 交付行为

每个实例现在有持久 Host 租约：host ID、单调 epoch、不可复用 token、取得/续约/过期时间。业务存储由租约守卫包装，每个事务在读写前核验并续约：

- 另一个 Host 的未过期租约返回 `HOST_LEASED`；旧 Host 的提交、查询和 Outbox 结算都被拒绝。
- 租约过期本身不自动授予新 Host 写权；必须显式 `engine.acquireHost()`，取得新 epoch。
- 同一 Host 身份可以续约；默认身份是本机稳定身份，使 CLI 与崩溃重启可继续原实例。
- `engine.getHostLease()` 返回当前 epoch、token、续约和过期事实；`shutdown()` 释放本 Host 租约。
- 所有内部组件共享同一守卫存储，包括业务命令、Effects/Outbox、Session 元数据与查询。

Session 后端继续独立核验 writer epoch（T15），业务事务继续核验 Assignment ID 与 generation（T19）。数据库锁只保证单次提交串行，不证明设备进程静止；未知或未确认作业仍按 T19 的恢复规则阻塞新代。

## 验证与范围

2026-11-09，Windows x64 / Node 25.4.0：新核心全量通过，typecheck、build、lint 通过。

新增回归覆盖：

- 两个隔离 Host 连接竞争同一实例：第二个未过期租约写入被拒；租约续约后仍被拒；过期后首次写入要求显式接管，接管得到 epoch 2。
- 接管后旧 Host 的读取、提交和 stop 尝试被拒；新 Host 能读取旧 Ticket 与原确认事实。
- 两个真实 Node 进程持有不同 Host 身份：第二个进程在旧租约有效时得到 `HOST_LEASED`，旧进程退出且租约过期后取得新 epoch。
- 同一进程重启、CLI 顺序调用与真实崩溃恢复保持通过，避免把“同机新进程”误判成第二个 Host。

租约默认 30 秒，可按部署配置 10 ms–1 小时。测试使用 100 ms 与 5 秒声明值；这些是开发负载预算，不是生产 SLA。未验证远程多机竞争、设备静止证明或真实部署切换；这些仍属于 T32–T44、T55。

## 行为

每个 Environment 固定 Instance、允许 Actor、绝对 root、权限集合和具名 command。准备阶段验证 root 及所有祖先不是符号链接/junction、命令可解析；setup 失败保存退出码和有限输出，不启动 Worker。只有显式 `retrySetup({ commandId, ticketId })` 可重新检查同一个 Assignment 和物理目录。命令 argv 来自部署配置，模型只能传具名 command，Shell、任意 argv、PTY、异步 job 和远端语义保持拒绝。

Worker 在绑定的 DSH 执行世界中使用 `write_file`、`read_file`、`glob`、`grep`、`run_command`。文件、搜索和命令共享同一 root；路径拒绝绝对路径、`..`、敏感文件、符号链接和越界目标。读写/search/command 由 Environment permission 控制；不同 root 的绑定不共享文件。命令输出有字节上限、退出/取消事实、provider-managed range 和 `waitForExit`；取消等待确认退出。失败输出会脱敏，发生截断时整体隐藏，避免凭据前缀被截掉后保留秘密尾部。

Worker 的 ready report 必须在最近一次写入后成功运行配置的 verification command，并列出 1–10 个相对 artifact 路径。每个 artifact 保存当前字节数和 SHA-256，toolFacts 保存工具名称、成功/失败及有界输出。报告提交后本地工具被封闭，迟到写入会得到 `REPORT_SEALED`，因此 ready 交付不会引用过期摘要。结果仍须经过当前 Assignment 与有序 Outbox。

聊天入口可选择已授权的 `sample-project` Environment；结果展开显示 artifact 和工具事实。`node dev/local-chat.mjs` 使用真实本地临时文件、搜索和 Windows/Node 命令 provider，经原生 DSH Router/Worker loop 运行脚本 mock，适合复跑界面路径。界面不会把 setup failure 当作 ready；用户能看到有限失败输出并显式 retry。

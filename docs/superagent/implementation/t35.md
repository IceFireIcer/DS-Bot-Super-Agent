# T35：设备断连与 daemon 重启后对账原作业

- Issue：[T35 / #63](https://github.com/IceFireIcer/DS-SuperAgent/issues/63)。
- 实施基线：T34 提交 `5eb23d7`。
- 规格：v2.1 D07、D09、D13、D14；A12、A20、A30、A33；用户故事 27、28、48、69。

## 已交付

- 设备作业记录升为 v2，原子保存 Instance、Environment、device incarnation、稳定 job ID、启动 actor、工作目录身份、PID/进程身份、原始 deadline、bounded stdout/stderr 和最近 8 条恢复记录。配置命令或 `jobsPath` 的设备现在必须提供 `statePath`；设备状态也改为临时文件加 rename 原子替换。daemon 不保存任何模型 Session 或权威对话历史。
- daemon 重启逐 job 重新分类：`live-process`、`log-only`、`identity-changed`、`unverifiable`。Linux 用 `/proc/<pid>/stat` 的 start time 与 process group 同时匹配才恢复控制；`log-only` 只保留日志和 unknown 退出，不伪装进程仍可观察。PID-only 平台只观察存活，**不发送结束信号**，结束后记录 `unverifiable-range-ended`。根进程已退出但原进程组仍存在时，显式取消仍可向该组收尾。
- 恢复的 live 进程继续受设备本地 deadline 约束：重启后立即补建 deadline timer，过期会向原进程组停止；原生取消只有范围实际为空才写 `cancelled`。重启后新输出不再来自已关闭的旧管道，只有重启前已 durable 的字节可读；`inspect` 在返回快照前等待输出 append 和状态持久化完成。
- Host `JobRecord` 新增 remote ownership/recovery evidence，公开 `engine.reconcileRemoteWork({ commandId, ticketId? })`，并在 startup 先按持久 job ID 对账。原 Environment/incarnation、当前来源授权、启动 actor 与 deadline 都重新核验；live range 由 `attachCommand` 接回，已结束范围接管真实 exit code 与输出，身份变化、记录不可查或设备离线保持 unknown。远端对账失败不会回落到本地 Environment。
- 远端后台启动与前台 `run_command` 都先在 Host 事务中持久 `starting` intent（job ID、owner、deadline），再发送设备 start；后台确认后转 `running` 并挂 handle，前台结束转 `exited/cancelled/unknown`。Host 在 spawn 与提交之间崩溃时，原 ID 仍可在 startup 对账；离线 stop 可凭原 ID 查询和取消，不再存在没有 JobRecord 的前台远端命令。
- 设备作业按启动 actor 归属；其他 actor 的 inspect/cancel/terminal 操作返回 `JOB_OWNER_MISMATCH`。旧 v1 记录没有 actor 归属时保留环境级只读/控制兼容，但 Host 不会把缺失 owner 当作其他 actor。
- stop 确认接受 `settled exited/cancelled`，也接受 `settled + recovery.rangeAlive = gone` 的日志恢复证据；日志中的退出码未知不会伪报成功，但已证明范围静止的 stop 可以结束 pending-device-confirmation。人工 stop、撤权、缺当前来源授权、waiting-human 和旧未知结果仍优先，不会自动恢复。
- 无法观察的 remote range 产生一次带 job ID、device ID、incarnation、状态和恢复原因的 Attention；同一 job 的问题 ID 持久化，后续 reconciliation/startup 不会重复通知。不同 Ticket 的失败互不阻塞，远端恢复预算耗尽也不会跳过 Input recovery。
- 远程协议升为 v2，`RemoteEnvironmentState` 升为 v2；旧 Host 状态以 `INVALID_CONFIG` 明确拒绝，不再用旧 transcript 派生错误密钥。

## 边界

- Windows/macOS 没有可验证的进程创建时间时只保留 PID 证据：允许观察存活，不允许 attach 或发送信号；这类 unknown 要由人工决定，不能冒充 live-process。Windows 进程树仍是 `taskkill /T` 最佳努力，不是 Job Object 级证明。
- PTY 在 daemon 重启后不会重新挂回 master；live terminal 只恢复范围控制，不恢复终端读写/尺寸。T35 不把日志恢复冒充 PTY 会话恢复。
- 重启前旧管道已关闭，之后写出的新输出不可观察；只有重启前已 durable 的 bounded 字节可读。
- 同一 Instance 的 Host 重启/接管需保留 `RemoteEnvironment.snapshot()` 并重新 prepare；跨 Host 租约竞争、共享 Session 后端和服务器替换仍属于 T44/T42/T43。没有自动回落 Host 本地执行。
- daemon 的 unverifiable/identity-changed 记录没有自动删除；它们保留证据并可能占用 64-job 预算，需人工决策或后续清理票。

# T10：调整策略和暂停处理而不丢失输入

- Issue：[T10 / #38](https://github.com/IceFireIcer/DS-Bot-SuperAgent/issues/38)。依据：规格 v2.1 D04/D06/D12/D15，A05/A06/A17/A23/A37/A42，用户故事 38、42、43、44、45、101。
- 固定实施基线：`a3b5a5b`；实现提交：`85fd312`。
- 公开测试边界：`Engine.updateIntakePolicy`、`setProcessingPaused`、`assessSourceBatch`、`receiveSource`、`listEvaluations`、`conversation`、Effects 派发、chat preview 的同源 `/pause`，以及两个 source instance 共享存储的隔离回归。

## 行为

每个 source instance 持久保存一份带 revision 的 Policy 和一份全局处理状态。初始化配置只在首次变更后持久保存；`updateIntakePolicy` 采用 `expectedRevision` 比较并拒绝过期写入，`origin: 'sync'` 还保存来源 revision 并拒绝重复同步。Policy 的 `off`、`observe`、`auto` 继续控制推断候选；人类 direct 明确请求在所有模式按原有授权处理，`observe` 只记录 `WOULD_ACCEPT`。命令重放返回当前 revision 和配置，不把旧输入重新应用到内存。

Policy 变更在同一事务中失效当前来源的 running/queued Eval，并保存新的重排事实；其他 source instance 的 Eval 和 acceptance head 不受影响。失效后的候选由后台重排重新研判，更新命令本身不等待旧模型回调超时。只有确实拥有被失效候选的 open Ticket 会收到带 revision 的 policy Outbox，历史保持可查。Engine 重启后保留 Policy revision 和处理状态。

全局暂停先持久提交，再停止新 Eval、命令受理、Input 投递、notice/relay/outbox 派发；来源事件仍正常记录。Effect claim 在写事务中再次检查暂停状态，避免暂停与领取之间竞态。已送达 assessor 的 Eval 在暂停时将剩余超时冻结，并记录 `EVAL_PAUSED`；恢复后从新批次重新研判。已有 Worker turn 不被自动中断，排队 work 在恢复后继续。Chat preview 分别显示全局暂停、waiting-human 和 Ticket stop。

来源正文、Policy 中的规则文字和同步内容不能修改 source actor allowlist 或 Ticket Mandate；ended Ticket 只有在 Mandate、来源 scope、当前事件和当前 requester allowlist 均通过时才可接收跟进。

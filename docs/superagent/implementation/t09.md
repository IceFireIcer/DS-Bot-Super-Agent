# T09：持久停止本地工作并显式恢复

- Issue：[T09 / #37](https://github.com/IceFireIcer/DS-Bot-SuperAgent/issues/37)。依据：规格 v2.1 D06/D07/D09/D14，A05/A30，用户故事 8、91。
- 固定实施基线：`cc999a7`；实现提交：`a0436b6`。
- 公开测试边界：`Engine.stopTicket`、`resumeTicket`、`conversation`、Effects 回执、原生 DSH Session mock、真实本地 setup command 取消和 chat preview stop/resume 路由。

## 行为

`stopTicket` 先在事务中持久写入 stopped 约束、撤销后续执行意图、取消该 Ticket 的待派发 effect，并保存 stop 请求及原 Assignment。运行中的 Worker 和目录 setup 通过 AbortSignal 请求取消；控制器存在时立即 abort。若没有活动执行，stop 直接记录 cancellation confirmation；若仍有执行，显示 `stopping`，直到 Worker/Setup 退出并提交确认后才显示 `stopped`。

Stop 是持久的人工约束。普通跟进只形成 `BLOCKED_STOPPED` context，不产生 Input；Engine 重启后仍保留 stopped/stopping、原 Assignment、Session 和历史。重启遇到内存中已不存在的 `stopping` 执行时，把旧 Assignment 结束并记录 `ENGINE_RESTARTED`，但没有实际取消证据时不伪造 cancelled；这种 unresolved stop 会阻止 resume，直到原执行完成确认。

`resumeTicket` 只接受明确的人工命令，且要求 stop 已完成、无 waiting-human、无同 Ticket 的 unknown effect，并在写事务内重新核验 Ticket 属于当前 source instance、原来源事件仍当前且作者仍在 allowlist。通过后保留 Ticket/Session/Environment，创建新代 Assignment，追加 assignment、stop 和 resume 历史，再派发恢复回合。旧 stop command 只重放原 stop，不会取消后来创建的新 Assignment。

Worker 起始事务会复查 Ticket constraint，防止 Router 在 stop 提交后继续创建 Assignment。迟到 report/tool/result 在 stopping 或 ended Assignment 上被拒绝。Chat preview 分开显示 stopping、已确认 stopped、取消证据不可用和 stop reason，并提供同源 `/stop`、`/resume` 操作。

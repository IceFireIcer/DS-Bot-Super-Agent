# T30：接收飞书讨论并保持来源归属

- Issue：[T30 / #58](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/58)。
- 固定实施基线：`a13db2e`。

## 已交付

- `FeishuOpenApi` 按飞书官方服务端接口实现真实传输：tenant access token（缓存，收到 token 失效响应时刷新一次并重试）、群信息、会话历史消息分页、群成员分页。
- 消息历史使用 `container_id_type=chat`、`sort_type=ByCreateTimeAsc`、`page_size` 与 `page_token`；重启后无内存 page token 时，从持久游标时间回看一段窗口（默认 10 分钟）重新拉取，以发现旧消息的编辑/撤回。
- 消息映射覆盖 text、post（标题与段落文本）和常见非文本占位；发送者区分 human/app，提及列表保留原生 ID，撤回消息带删除依据，`updated` 或 `update_time > create_time` 记为编辑。
- 原生版本：`update_time` 是可靠版本（毫秒、连续）；没有更新时间时退回 event 身份，作为不可靠版本保持冲突/待查。事件 ID 由 message、更新时间、事件种类与内容指纹组成，同版本不同内容形成不同命令并进入冲突，而不是卡在 `IDENTITY_CONFLICT`。
- `FeishuSource` 校验 tenant、chat 与发送者范围；p2p 记为 `direct`，群内 @ 自身记为 `mention`，其余群讨论记为 `ambient`；来源自身消息过滤但推进游标；记录成功后才推进 `channel-cursor`。
- 游标是消息创建时间位置，不会被旧消息的编辑拉回；重放由来源命令回执识别为 `SOURCE_REPLAY`，不重复接单，也不重复计数为已处理。
- `FeishuPoller` 在 setup 后开始接收：调用方未提供 setup 时自动使用传输的 `setup`（token + 每个群可达）；来源失败有独立 health 与游标，单轮有声明期限，`stop()` abort 并等待当前轮；传输层畸形项计数合并进 health。
- `FeishuMemberSync` 把各群的 `listMembers` 结果合并去重，按当前快照严格递增 revision，再调用 `syncSourceMembers`；启动或人工命令都可触发，旧 revision 仍被拒绝。
- HTTP、网络、中止与无效 JSON 统一映射为有界的 `SOURCE_STOPPED` / `SOURCE_FAILED`；token 失效只刷新并重试一次。

## 协议与测试证据

- 参考飞书官方接口：`auth/v3/tenant_access_token/internal`、`im/v1/messages`、`im/v1/chats/:chat_id`、`im/v1/chats/:chat_id/members`。
- 脱敏夹具覆盖：text/post 消息、p2p/mention/ambient、编辑与旧版本忽略、撤回、缺失发送者的畸形项、消息分页与回看窗口、重复页/乱序重放、token 失效刷新、成员分页去重与分页预算、setup 先于接收、成员同步 revision。
- 全部为协议夹具证据；没有读取或写入任何真实飞书租户数据。

## 边界

- 真实隔离飞书群与真实名单 API 运行未做：维护者明确暂缓真实群测试；当前没有使用任何飞书应用凭据。真实信道验收仍未完成。
- 成员同步结果不自动改写 Intake Policy：按 D05，来源身份/白名单/授权不与其他来源自动合并；应用名单是受信部署步骤。
- 只读取 chat 容器的根消息；普通对话群中的话题回复需要 thread 容器，属于后续范围。
- 编辑/撤回的发现依赖回看窗口；早于窗口的变更不会重新投递（Feishu 历史接口没有 updated-since 过滤）。
- 没有 host/CLI/UI 入口；消息、游标和成员只通过公开 Engine 查询。
- T30 仍 open，等待合入 `dev`、真实信道验收与发布。

## 本次补齐

新增 `FeishuRuntime`，组合公开 Engine、FeishuSource/FeishuPoller、OpenAPI、成员同步和交付 Channel。构造不联网；必须 `bind(engine)` 后显式 `await start()`。

启动依次核验 token 对应的原生 tenant key、全部配置群可达性、完整成员分页及持久同步，完成后才启用接收和外发。setup 默认 60 秒（1–300 秒），每次 HTTP 请求默认 30 秒（1–300 秒）。失败仅影响本来源；关闭 abort 并等待 setup、轮询、成员同步、外发及回执写入，再清理 token/内存分页状态；不关闭父任务的 Engine/Storage。

来源实例为 `feishu:<tenant>:<sorted-chat-ids>:app:<app-id>`，不同应用隔离。允许 1–20 个不同群，每群每轮最多 50 条，总页不超过接收器 1000 条预算。群消息按原生 `root_id`（根消息用自身 `message_id`）归入 `feishu:<tenant>:<chat>:message:<root>`；p2p 保留 `feishu:<tenant>:<chat>`。原生 `thread_id` 用于补读话题容器，不把同群其他根讨论当作原问题的回答。

`sourceBinding` 带原生 Thread 范围、独立 actor 列表、显式 Intake Policy 和 `versionOrder: 'sequence'`。Bot 原生身份需显式配置，应用 ID 也加入自身消息过滤。名单同步只保存来源快照，不自动修改 Policy/白名单，不跨平台合并人，也不让消息正文调用 setup 或修改配置。

API 不再用创建时间伪造更新时间。可靠 `update_time` 交给 Engine 处理旧序列、同版本异文、删除 tombstone。未提供可靠更新时间的非删除消息先调用公共 `Engine.receiveUnverifiedSource(event)`，在来源事务中使原对象投影进入 unknown、撤掉旧文本的候选资格，并保留原生事件与回执；该路径不 fanout、不 Eval、不自动回答。随后读取 projection 确认 unknown 或既有 deleted，才保存附带领域回执的独立原生接收检查点并推进游标。`getUnverifiedMessage(chatId, messageId)` 可查，返回 SOURCE_VERSION_UNVERIFIED，不送入新接单、方向更新或回答。有原生撤回依据但无更新时间时用序列 0 记录删除，沿用 Engine 删除优先语义。

仅保存旁路 quarantine 而保留旧 current projection 的原实现有 P1 授权缺口，本轮已移除该接收路径。receiveUnverifiedSource 已由共享核心实现，是直接强类型依赖，无 feature detection 或可选降级。若方法返回后对象仍 current/不存在，抛出 SOURCE_UNVERIFIED_NOT_APPLIED，不确认页或推进游标。运行时不直接写 source-object，不以配置字段或假序列伪造不可靠版本。

运行时启用可确认分页：全部事件持久接收/过滤后才确认令牌；持久失败保留原页并进入来源退避。重放使用持久回执去重，游标只前移。运行时循环每群原生历史分页，不用共享最大创建时间跳过慢群或旧话题；重启丢失内存令牌后重新补读。此选择增加重复读取，容量/时延未经实测。

成员同步在网络读取前保留下一 revision，同一同步器拒绝重叠调用；其他实例/人工先提交新版后，旧同步被 Engine 拒绝。中止后不提交；畸形成员身份、错误身份类型、不前移的页令牌或超预算均失败，避免把部分名单当完整结果。

请求错误使用固定码/HTTP 状态，不透传 token、secret、平台 msg 或 fetch 异常文本；基址仅允许无凭据的 HTTPS origin，禁止 redirect，非法 URL 也转为固定配置错误。

## 父任务装配契约

父任务已在根 `index.ts` 导出：

```ts
export { FeishuRuntime } from './feishu-runtime.js'
export type { FeishuRuntimeOptions } from './feishu-runtime.js'
```

```ts
interface FeishuRuntimeOptions {
  storage: Storage
  instanceId: string
  tenantKey: string
  chatIds: string[]
  actorId: string
  selfActorIds: string[]
  allowedActorIds: string[]
  intake?: IntakePolicy
  api: FeishuApiOptions
  intervalMs?: number
  pollTimeoutMs?: number
  maxBackoffMs?: number
  setupTimeoutMs?: number
  maxTextChars?: number
}
```

1. `const runtime = new FeishuRuntime(options)`；api 的 appId/appSecret 仅由可信 Host 注入，不写入业务配置或日志。
2. 用 `runtime.sourceBinding` 创建这个来源专属的 Engine，将 `runtime.channel` 注入现有 `deliveryOptions.channel`；不得绑定另一来源 Engine 或另起模型循环。
3. `runtime.bind(engine)`；`await runtime.start()`。Host 继续管理 Engine 原有 Effects/执行生命周期。
4. 可信管理入口可调用 `syncMembers(commandId)`（每次新同步使用新 ID）、`health()`、`getUnverifiedMessage(chatId, messageId)`；另有 T31 的回答和回执查询。
5. 关闭先 `await runtime.stop()`，再关闭 Engine/Storage。

共享核心已实现公共方法 `Engine.receiveUnverifiedSource(event: ReceiveSourceEvent): Promise<SourceReceipt>`。它先执行 ensurePolicy、activation 和 Host admission guard，再调用 `SourceEvents.receiveUnverified(event)`；后者沿用原生来源 scope、输入预算和幂等校验，在同一 guarded transaction 内保存来源事件、unknown 投影和回执，移除投影正文，既有 deleted 保持 deleted。命令 ID 使用 `feishu:unverified:<eventId>`，不透明版本为 `unverified:<eventId>`；与可靠版本的接收回执隔离。旧未知事件重放不能复活旧投影；后续同对象、带可靠原生命令版本的新事件可以完成查证并把投影恢复为 current，同时保留 unverified 不可变历史。由两个已验证但不可比版本产生的 unknown 不会自动猜测恢复。

实际内部契约为 `SourceEvents.receiveUnverified(input: ReceiveSourceEvent): Promise<SourceReceipt>`，与普通 receive 共用私有 receiveObservation 事务。模式由受信方法选择，不加入外部请求字段白名单；fingerprint 带 unverified-observation-v1，事件保存 opaque 版本和 versionVerified:false。即便此前没有 source-object 也建立 unknown；不调用 onRecorded，因此无 fanout、Eval、主动规则或自动回答。

不要求新增 Storage schema。未知版本、发送回执检查点复用现有 `channel-cursor` 类别，使用 `feishu-unverified-version` / `feishu-delivery-receipt` 独立元组键并保留 cursor/updatedAt，不覆盖原入站 `['channel-cursor', sourceInstanceId]` 键；两个后端使用同一公开事务 API。

父任务/T27 worker 已在共享 Engine 自动回答路径加入当前候选 ID 校验，并实现上述 unknown 接收事务；本轮只读核对两处源码，P1 的旧 current 候选保留问题已在代码路径修正。共享文件修改不属于本任务所有权。

部署权限至少需允许当前应用查询租户身份、读取配置群和消息历史、读取群成员、查询目标消息并回复；权限不足导致 setup 失败或外发 pending，不声称仅配置 app ID/secret 就通过平台授权。

## 预先固定的流程

```sh
cd superagent
node dev/t55-acceptance.mjs --plan
node dev/t55-acceptance.mjs
```

| 顺序 | 阶段 | 可观察范围 | 不能证明 |
| --- | --- | --- | --- |
| 1 | continuous-mock | 连续对话、并发、改方向、人工问题、停止和明确恢复 | 真实桌面、GitHub、模型判断 |
| 2 | long-command-stop | 实际本机命令、loopback 设备断连和停止 | 独立第二设备 |
| 3 | handoff | 执行目标、双向交接、安全边界和中断恢复 | 当前真实跨机部署 |
| 4 | proactive-supervision | 规则内准备、语义提案/批准边界、mock Session | 真实模型误触发和语义质量 |
| 5 | client-host | 独立客户端/Host 进程、撤销、故障、隔离 PostgreSQL | 实际桌面接新核心、服务器托管 |
| 6 | migration | 隔离旧/新入口的激活、崩溃、逆向交接 | 用户生产应用正式切换 |

这些阶段是一次连续 mock 场景加组件故障演练，**不是**一条真实桌面→GitHub→远端设备→托管 Host 的完整链路。每阶段最多 300 秒、测试文件并发为 1，不自动重试失败阶段。退出码 `0` 不用于表示本票完整通过：自动阶段全通过时返回 `2`（仍有真实验收缺项），自动阶段失败返回 `1`。

运行前读取所有 54 份实施记录、证据索引、人工核验表及选定测试文件，记录 SHA-256；构建后顺序执行固定文件。每次先建立独立 `.dsh-test-t55/run-<uuid>/` 及 preflight 报告，再读取前置；最新快照保存在 `.dsh-test-t55/report.json`，旧轮次不覆盖。报告含 Node/OS、开始/结束时间、实际计数、退出码、超时与输入摘要；前置缺失记本轮失败，跳过、取消、零测试、TAP 汇总缺失均不能记作阶段成功。中断时终止本轮子进程树并记录 aborted；Windows 的程序发送 SIGTERM 不等于 POSIX 信号行为，平台测试分别报告。日志仅供本地诊断，不直接发布。

## 核验发现的缺陷

- **T27 / #55：真实跨信道方向和外发缺证据。** 现有 GitHub 脚本接收真实事件并检查目的地字段，但没有配置真实 GitHub outbound channel；本轮跨来源实例直接 attach 被明确拒绝。桌面所有者授权改投的契约通过，完整 A→B 方向和平台回复仍未验收。
- **T45 / #73、T46 / #74：真实桌面仍未接新核心。** 当前 profile/依赖使用旧插件；新核心网关和旧桌面生命周期各自通过不能合并为一条产品轨迹。
- **T54 / #82：等负载比较不成立。** 实际订阅直通只处理 1 个初始请求 + 6 个跟进，共 7 条，却标记 12 条；其他两模式处理 12 条。历史时间数字不能用于同负载速度结论，需回 T54 修正 workload 后重测。
- **证据索引：** 54 份实施记录齐全；T18–T32 缺少 15 份独立审查文件；T33–T36 的历史审查有 4 个错误相对链接。这是索引/审查证据缺口，不等于实现缺失。commit 检查的 3 处数字 CI run ID 告警为误报。

其余 T22/T41 实际崩溃窗口、T38 工具复用、T48/T49 模型/UI、T50–T53 真实旧核心控制适配等边界详见证据表。T55 不通过改写历史测试或扩展生产能力消除这些缺口。

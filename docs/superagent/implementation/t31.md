## 本次补齐

运行时装配签名见 [T30](t30.md)。`runtime.channel` 在 setup、成员同步完成前及停止后返回 transient，交付保持 pending。目标必须属于这个精确 app/tenant/chat 来源实例、明确允许的 actor 和 Thread；发送前公开查询原生消息核对目标群，不凭 message 字符串跨群发送。不自动改投其他对象或信道。

`replyMessage` 使用原消息 `POST .../messages/:id/reply`，不写死 `reply_in_thread`，让平台按原消息是否属于话题采用其默认原位/话题回复语义。保留默认 4000 字符 IM 截断及平台字节限制；稳定 Outbox idempotencyKey 转为 SHA-256 前 32 位十六进制 UUID。发送必须返回原生 message_id。

运行时持久保存原生交付检查点：deliveryId、幂等键、messageId、目的地/正文 fingerprint 和时间。检查点在现有 channel-cursor 类别中使用独立 `['feishu-delivery-receipt', sourceInstanceId, deliveryId, idempotencyKey]` 键，并保留 cursor/updatedAt，不覆盖入站游标。`getDeliveryReceipt(deliveryId, idempotencyKey)` 可查。已保存且 fingerprint 一致的真实回执恢复时不再 POST；fingerprint 冲突保持 unknown。

平台已收而响应丢失时，去重仍依赖相同 UUID 和飞书一小时窗口。为避免迟到恢复重复发送，交付创建时间超过 **55 分钟**、时间非法或时钟倒退且无持久回执时返回 `FEISHU_RECONCILIATION_REQUIRED` / unknown，不继续盲发。该保守界限也可能阻止延迟首次发送，需要可信人工对账；没有声称已实现远端 UUID 查询或平台 exactly-once。

HTTP 429/5xx、发送频率限制、token 失效、停止和网络故障保持 transient；明确消息删除，以及已知目标、参数或权限拒绝为永久不可达；未知平台码为 unknown。原因不透传异常文本。重试耗尽保留 pending，恢复由原 Outbox 的显式恢复/对账处理，不换人发送。

同根话题回复进入现有公开 `receiveSource → answerFromSourceEvent` 事务：明确允许、非自身的人类输入匹配唯一 waiting Attention，Engine 核查 actor 和授权。同 Thread 多个问题不猜测，可信入口可调用：

```ts
runtime.answerAttention({ commandId, attentionId, sourceEventId, text })
```

sourceEventId 必须是当前原生人类事件；Engine 从事件核验实际文本、actor 和 Thread，调用方不能冒充他人。无可靠更新时间的消息必须先经 T30 的公共 receiveUnverifiedSource 事务使原 projection 变为 unknown；不能只保存旁路检查点而保留旧 current。旧事件随后不再是 candidate，不能 accept 或解除等待。结果仍回既定目的地，不自动复制私人上下文。

共享 Engine 自动回答的事务内当前候选 ID guard 及 receiveUnverifiedSource 来源事务均已由 T27 worker 实现，本轮只读核对源码。Engine 执行 policy/activation/Host guards 后调用 SourceEvents.receiveUnverified；同一事务保存 opaque 不可变事件、unknown 投影和回执，保留 tombstone，不执行 onRecorded/fanout/Eval/自动回答。运行时直接强类型调用该方法，无 feature detection，不退回仅隔离旁表。本任务不编辑 Engine。

关闭会中止发送前范围查询和原生发送，等待已启动请求及检查点写入后清理 token。临时关闭不令排队交付 dropped。

# T01: Persistent isolated intake

Issue: [T01 #29](https://github.com/IceFireIcer/DS-Bot-SuperAgent/issues/29). Contract sources: [spec v2.1](../spec.md), especially D01-D04, D06, D10, D13 and D18, scenarios A01, A02, A11, A18 and A32, and the published ticket body.

## Result

The new private [`superagent/`](../../../superagent/) package provides an independent TypeScript core through a public Cordis plugin and SQLite async transaction adapter. A configured desktop source can submit an explicit local request, receive an acceptance receipt and inspect its original Trigger, Decision, immutable Mandate, open Ticket and pending intent. The pending reason is `worker-not-enabled`. The package provides no Worker loop and does not connect the legacy `ds-bot` input path.

## Durable behavior

- Stable command identity and a versioned SHA-256 fingerprint return the original receipt. Stable event identity deduplicates transport retries using a new command ID. Reuse with different content fails with `IDENTITY_CONFLICT`.
- One SQLite transaction writes the event, authorization, work identity, pending intent and command/event receipts. A thrown adapter failure or a process exit before COMMIT leaves no accept or intent. A new process retrieves a committed receipt after a process exit.
- SQLite uses a versioned schema and scoped async transaction capability. Calls from one worker are serialized; all reads and writes derive `instance_id` from the active transaction, not request fields. Two independent engine instances cannot query each other's receipts or tickets.
- Untrusted request objects cannot supply source identity, instance, allowed actors or expanded scope. Explicit request mode and local execution are the only enabled capabilities. Nonempty unversioned databases and future schema versions are rejected before WAL/schema changes.
- Built artifacts expose `Engine` and `Storage` as the extension points for later contract-tested storage backends. The Cordis service name remains `superagent`. The single process owns SQLite; external systems, models and disk tools are not called inside the database transaction.

## Red-green evidence

TDD used the already agreed public Engine command/query and storage-adapter seams in spec v2.1, lines 6 and 407-414; no seam approval was requested. The following were observed RED before the minimal fix and GREEN after:

- The public plugin assembly test failed because `dist/index.js` did not exist; the Cordis plugin, storage and Engine module compiled, then the real-SQLite submit/query test passed.
- Forged request identity fields were silently ignored and accepted; unknown request properties are now rejected before any write.
- Mutating a request object after `submit()` began changed the persisted scope while keeping the earlier fingerprint; a normalized request snapshot is now used before the first await.
- Falsey unsupported execution modes such as `false`, `null`, `0` and `""` were silently accepted; only omitted values or the explicit supported values now pass.
- Future schema opened as generic `STORAGE_UNAVAILABLE`; startup now returns `UNSUPPORTED_SCHEMA` and an unchanged-file hash proves no journal/schema change.
- A nonempty SQLite file with user_version 0 was incorrectly treated as fresh. A real SQLite fixture reproduced this. Startup now lists no application tables/views as the only acceptable version-0 condition; the v0 rejection test is registered to close a mistakenly opened adapter as well as delete its temp directory.
- The schema guard's SQL `LIKE` pattern also mistook an application table named `sqliteXdata` for a SQLite-owned table. That fixture failed before replacing the pattern with a literal-prefix `GLOB`; the database now remains byte-for-byte unchanged.
- A lone surrogate in an Instance ID was converted to the replacement character by SQLite binding and could expose another Instance's receipt. Public identifier validation now rejects ill-formed Unicode across Instance, source, actor, command and event IDs while preserving Chinese text, paired emoji and the valid replacement character.
- Independent entry bundles produced different `CoreError` constructors. A public `instanceof` regression now passes with shared ESM chunks.
- A one-slot transaction queue still rejected the next transaction immediately after the first Promise resolved. The admission slot is now released before its result becomes visible; the same contract verifies excess work is rejected and an expired transaction capability cannot be reused.
- Separate CLI process test failed before `dist/cli.js` existed; the built CLI now writes an explicit request and separately reads the receipt/work through a new Cordis context.

Current package test result: 15/15 passing, with no skips. Additional passing public behaviors include 20 concurrent command IDs for one event creating one ticket, same-command replay, cross-identity collision rejection, two instance isolation on the same DB, separate source instances, actor allowlist denial, and rollback leaving the original command reusable. An independently held SQLite writer causes the request to reject as `LOCK_TIMEOUT` within the declared 250 ms lock budget's 150-2000 ms test tolerance, with no accepted record.

## Load and compatibility

`npm run mock` measures 50 sequential SQLite commits, then sends 20 parallel submissions for one event, then starts the CLI as a new process to read an existing receipt. On Windows x64 with local Node 25.4.0, the 2026-11-04 recheck measured p50/p95/max per serial submit of 0.76/1.24/1.88 ms. All 20 parallel deliveries reused one Ticket. The JSON reports the workload and timings without recording local paths or user data. The test budget for the adapter is a 128-item admission queue and a 250 ms cross-process SQLite lock wait (both explicitly configurable within hard caps). These are local T01 limits, not a production performance SLA.

On Windows x64 the complete 15-test suite passed on actual Node 22.19.0, 24.0.0 and local 25.4.0 runtimes. The minimum and Node 24 runs took approximately 990 ms and 976 ms with zero skips. New-package build, typecheck, lint and isolated mock passed. A separate TypeScript consumer compiled against the built public declarations; the documented CLI example, including creating its isolated parent directory, returned queryable pending work. Dependencies are pinned: `@deepseek-ai/cordis` 4.0.5, TypeScript 6.0.3, esbuild 0.28.2, Node types 22.19.0, oxlint 1.76.0. No Harness install location or DSH source internals are imported. Product runtime: public Cordis plugin, `node:sqlite`, `node:worker_threads`; there is no real model or Worker call in this slice.

The legacy `ds-bot` checks also passed in the ticket worktree: 1431 unit tests passed, 2 skipped, 0 failed; generated-client consistency passed; lint exited 0 with existing warnings. No legacy host or client code changed, so host smoke and UI evidence are not applicable to this isolated slice. CI includes the new package's typecheck, tests and lint in the required `Test result` gate. These results do not constitute overall Super-agent, real-model or deployment acceptance.

The implementation is original Apache-2.0 project code. It does not copy the official research prototype or need a new NOTICE entry. The pre-existing `NOTICE` and legacy plugin code are untouched.

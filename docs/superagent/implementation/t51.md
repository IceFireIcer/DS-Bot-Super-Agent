## 已交付

### 1. 持久 quiescing/quiesced 与真实 epoch 复核

- 新增公开 `ds-superagent/switchover`：`Switchover` 及其 `begin`、`recheck`、`status`、`ingestGapInput`、`listGapInputs`、`getGapInput`、`close`。
- 持久记录 `switchover` 保存 batch、`quiescing`/`quiesced`、新 Host epoch、archive source/mapping digest 与 state revision、旧 home 锁证据、stop/restart 事实、两次 checkpoint、blocker、gap 计数。
- `newEpoch` 不再只是调用方给的数字：`begin` 读取当前 `HostLease`，要求 epoch 相同、lease 未释放且未过期；旧 home 的 `state.lock` 只记录为 `usedAsFence: false`，不能代替 epoch。
- 每次 `begin`/`recheck` 重新读取已发布 archive；archive 未发布、digest/mapping 改变、source revision 改变都会留下 blocker。

### 2. 停用旧消费、旧重启入口并核验静止

- `LegacyCore.stop()` 停旧消费；`LegacyCore.disableRestart()` 必须持久停用旧重启入口并返回证据，`restartDisabled()` 在每次复核时重读该事实。只停进程、只拿旧 home 锁都不够。
- 旧入口必须让出配置的 loopback intake 端口；`Switchover` 在 stop 后实际 bind 该端口，失败保留 `ENTRY_STILL_HELD`/`ENTRY_UNAVAILABLE`，不报 quiesced。端口持有带 PID、进程启动时间与心跳；重复启动只能复用仍可连通的 holder，不能降级它。
- 最终复核采集两次旧核心 snapshot（默认 1000 ms，可配 0–60 s）；要求 turns/jobs/outbound 为空、increment 为零、所有 source cursor `complete`、accept receipt 不处于 pending/unknown，且两次 snapshot digest 一致。blocker 逐项持久化，包括 `ACTIVE_TURNS`、`ACTIVE_JOBS`、`PENDING_OUTBOUND`、`PENDING_INCREMENT`、`INCOMPLETE_CURSOR`、`PENDING_RECEIPT`、`SNAPSHOT_CHANGED`、`SOURCE_CHANGED`、`ARCHIVE_CHANGED`、`RESTART_NOT_DISABLED`。
- quiesced 只在 stop、restart 停用、端口隔离、archive 与两次 snapshot 全部通过后写入；之后新增 increment 会把记录降回 quiescing，不保留假 quiesced。

### 3. 空窗输入持久缓冲与归属核清

- quiesced/quiescing holder 在已隔离的 loopback intake 上接收一行一个 JSON，单条上限 131072 bytes；落库成功后才回应 `{ ok: true, durable: true }`。
- 稳定 ID 为 `gap:<sha256(sourceInstanceId, threadId, objectId, version.order, version.value)>`；全限定身份同时持久保存。重复同 ID 同事实幂等；同 ID 异事实 `GAP_INPUT_CONFLICT`，不覆盖。
- 每个 gap input 记录 `dispatch: 'not-dispatched'`，本模块不创建 Ticket、Assignment、Effect 或旧 Agent loop。
- 分类：
  - `legacy-accepted`：旧 accept receipt 已接受，永不重派；
  - `held`：旧 receipt 明确 not-accepted，留给 T52 按原 ID 承接；
  - `quarantined`：缺稳定身份、缺 cursor、缺 receipt、receipt pending/unknown/rejected、cursor 源不一致或超出预算，保留原始有界内容供人工核查。
- 最终 snapshot 会重新对账已缓冲输入：receipt 必须能在旧 snapshot 中找到；旧已接受但当时标为 held 的输入升级为 `legacy-accepted`；声称 accepted 却无旧事实、receipt cursor 不可比、或 cursor 未覆盖的输入转 quarantine。旧 accepted 的 cursor 必须已覆盖，新空窗 held 的 cursor 必须不落后于最终 cursor；opaque cursor 只有相等才可通过。

### 4. 真实隔离新旧进程演练

- `test/fixtures/legacy-entry.mjs` 是旧入口 launcher；`legacy-receiver.mjs` 是真实旧接收进程，持有 intake/admin 端口并记录 turns/jobs/outbound/cursor/receipt。
- `switchover-runner.mjs` 是真实新进程：打开 SQLite、读取当前 Host lease、调用 `Switchover.begin`、持有隔离 intake，并可按 status/recheck 查询。
- 演练：旧进程先接收一条已接受输入；新进程 stop 旧进程、把 launcher 改名为 `.disabled`、bind intake、完成 quiesced；窗口输入分别成为 held/legacy-accepted/quarantine；伪造的 accepted 回执在 recheck 后隔离；SIGKILL 新进程后重启可重新 bind 并恢复 quiesced 与全部缓冲；旧 receipts 仍只有一条，新库 Ticket/Effect 均为 0。

## 使用方式

```js
import { Switchover } from 'ds-superagent/switchover'

const switchover = new Switchover(storage, instanceId)
const record = await switchover.begin({
  batchId: 'batch-2026-11-11',
  newEpoch: (await host.currentLease()).epoch,
  archive: { target: '/absolute/archive-store' },
  oldHome: '/absolute/legacy-home',
  entry: { host: '127.0.0.1', port: 8796 },
  legacy: {
    stop: async () => ({ evidence: 'old host exited' }),
    disableRestart: async () => ({ evidence: 'old launcher renamed', entry: '/absolute/old-entry.disabled' }),
    restartDisabled: async () => true,
    snapshot: async () => oldSnapshot,
  },
  settleMs: 1000,
})
// record.state === 'quiesced' only when stop, restart disable, port isolation, archive and two snapshots passed.
```

## 边界

- **不激活新消费。** T51 只准备 quiesced 与 gap buffer；activation manifest、当前核心、缓冲释放和唯一消费属于 T52。
- **旧核心控制由宿主实现。** `LegacyCore` 是公开适配契约；本票用虚构 launcher/receiver 证明真实进程行为，没有把真实 DS Bot 安装/服务管理器注册表写入代码。真实产品的旧进程/自启动实现仍需 T52/T55 按部署形态接入。
- **只支持 loopback intake。** gap 接收面拒绝非本机 bind，避免把迁移缓冲暴露成公网入口。
- **没有 UI。** 公开模块、持久记录与查询是当前入口；设置/迁移界面留 T55。
- **没有真实产品旧数据验收。** 测试全部使用虚构隔离 home、mock/本地进程和空闲端口；不读取用户 DSH。

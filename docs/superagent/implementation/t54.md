# T54：比较协作负载并确认已声明的资源预算

- Issue：[T54 / #82](https://github.com/IceFireIcer/DS-SuperAgent/issues/82)。
- 实施基线：`c08c3d1`（T53 已推送头）。
- 规格：v2.1 D01、D04、D05、D08、D09、D11、D15、D16；A02、A07、A08、A16、A20、A21、A23、A24、A28、A36；用户故事 2、7、38、40、52、76。
- 证据文件：[t54-bench.json](t54-bench.json)。

## 可重跑命令与固定负载

```sh
cd superagent
node dev/collaboration-bench.mjs
```

脚本固定 seed `2026-11-11`、6 个初始请求、6 个同 Thread follow-up、20 ms mock Worker turn、Router batch 上限 20、2 个 normal slot + 1 个 priority slot。所有结果在本次运行中测量，不读取文章或原型数字；Node/OS 由输出记录。mock 模型没有 token 用量，因此不把 token 填成估算值。

同一事件流以三种结构运行：

- `singleSession`：一个 Native Session 顺序处理 12 条消息；
- `routerWorker`：12 个独立 Thread（6 个初始请求 + 6 个 follow-up 文本），每个都经过 Router batch、接受和 Worker；
- `subscriptionDirect`：首个 Thread 建 Ticket，后续 6 条同 Thread follow-up 直通已有 Worker。

## 本次 mock 结果（Windows / Node 24.22.2）

| 模式 | events | total ms | acceptance p50/p95 ms | response p50/p95 ms | Router calls/batches | Worker calls | direct ratio | notifications ack/result/dup |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| singleSession | 12 | 667.78 | 48.51 / 118.78 | 48.51 / 118.78 | 0 / 0 | 12 | 0 | 0 / 0 / 0 |
| routerWorker | 12 | 1763.43 | 43.80 / 65.92 | 136.76 / 203.68 | 24 / 12 | 12 | 0 | 12 / 0 / 0 |
| subscriptionDirect | 12 | 983.99 | 116.39 / 233.07 | 118.94 / 233.07 | 2 / 1 | 7 | 1.0 | 1 / 0 / 0 |

- 每种模式在 JSON 中保留 `acceptanceBoundary`/`responseBoundary`：single 的 acceptance/response 都是同一 Native Session turn；Router/Worker 的 acceptance 到 Router assessment，response 到 Worker Assignment；subscription 的 response 到 follow-up Input 持久投递。不是把不同阶段伪装成同一单位；`totalMs` 是同一 12 条流的总时间。
- Router calls 包含 batch 研判与后续 `assign_worker`；subscription 模式只对首条请求调用 Router，6 条 follow-up 全部直通（directRatio 1.0）。
- duplicate replay：重复 receive/assess 后 duplicateTickets 0、duplicateNotifications 0；状态重开 `stateReopenMs` 46.10 ms。这里只证明状态重开，不等同于崩溃恢复时间。
- happy-path unknown effects/jobs 均为 0；本 workload 不制造 unknown，不能据此声称 unknown 对账已验收。

| Host lease | 默认 30 s；接管必须显式过期/合法 fencing | 本地 benchmark 不重启 Host；T20/T44 历史证据 |

本表只列主要预算；“历史证据”表示该票已有定向/真实环境记录，不在 T54 用不同 workload 冒充重新测量。

本次固定 mock 负载没有触发任何已声明 timeout、队列/并发/重试上限，因此没有建立“超限”问题；这不表示所有预算在其他负载下都已验证。

## 未验证/边界

- **真实模型 token/延迟未运行。** 当前环境没有 `POKEXIAO_API_KEY`/`OPENAI_API_KEY`；脚本把 realModel 标为 not run。T29 的 4 次真实模型样本是 proactive 路径，不是本 collaboration benchmark 的同一事件流。
- **远端 Host/Managed Host 未运行。** T32–T37/T47/T52 的历史设备与托管证据不能替代本 workload 的 remote/managed 对照；本票明确标未验证。
- **proactive/supervisor 未在本 workload 重跑。** T29 真实模型小样本和 T48 mock/真实 DSH loop 证据分别保留；本票不以 happy-path 0 未知充当这些路径的验收。
- **恢复只测 state reopen，不测崩溃/接管。** 43.65 ms 是同一 SQLite 重新连接和读取 Ticket 的时间；T16/T20/T44 的恢复证据不被覆盖。
- **没有 UI/生产设备/发布。** 命令仅使用 mock 模型、隔离临时目录和空闲端口；没有产品 SLA 声明。

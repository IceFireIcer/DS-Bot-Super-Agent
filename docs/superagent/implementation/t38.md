## 已交付

- 新增 Instance 级能力目录 `CapabilityLocationView`。浏览器与 MCP 声明为 `host` 能力，凭据和隐私留在 Host；Office 声明为 `environment` 能力，要求 skills provider、配置的 `office` 命令以及 `read` + `command` 权限，凭据和隐私属于绑定环境。角色范围显式记录为 Worker。
- `DesktopSource.hostCapabilities` 声明 Host 实际提供的浏览器/MCP；未声明按 unavailable 处理，不合成默认能力。该声明只属于当前 Instance，不写入 Trigger、Mandate、远程设备或另一个 Instance 的目录。
- `submit`、`acceptSource` 与 intake 的 `IntakeAssessment.capabilities` 接受 `capabilities: ['browser' | 'mcp' | 'office']`，保存到 Trigger 与 Mandate，并纳入 v4 命令指纹；重复、未知或超过一项同名能力被拒绝，同 command ID 改能力返回 `IDENTITY_CONFLICT`。
- Execution selection 在创建 Assignment 前解析能力：`host` 能力只允许本地 Assignment；`environment` 能力要求 probe 明确声明并具备所需权限；所有远程目录项都带 `remote-browser-contract-unverified`、`remote-mcp-contract-unverified` 或 `remote-office-contract-unverified` 缺口。`remote-only` 缺少任一能力时保持 `environment-waiting` 且不创建 Assignment，`auto` 只能选择满足条件的本地候选。
- `LocalEnvironment.probe` 只在同时配置 `skillsPath`、`office` 命令且有 `command` 权限时声明 Office；`RemoteEnvironment.probe` 明确声明三项产品能力都不可用。未声明的 Host 浏览器/MCP 即使在本机也 fail closed；能力解析只读 probe，不增加权限、设备授权、Host 路径或发布权。
- 公开入口：`Engine.getCapabilityLocations()` 返回完整目录；`conversation(ticketId).capabilityPlan` 与 `Engine.getCapabilityPlan(ticketId)` 返回所需能力、位置、可用/受阻状态、候选原因、凭据与隐私范围。等待中的 Ticket 同样可查询。
- 本地聊天预览新增 `GET /capabilities`、Browser/MCP/Office 能力选择、每 Ticket 的能力位置卡片和全局目录。受阻状态直接显示选择原因，例如远端 Office 的 `remote-office-contract-unverified`。

## 边界

- 本票声明能力位置和阻止条件，不把旧 DS Bot 的浏览器、MCP 或 Office 工具自动挂进新核心；Host 声明为 available 是部署事实，不是新的工具实现。
- Office 本地组合只允许已配置的 `office` 命令，不使用任意 shell；skills 根仍由 T37 的公开 provider 负责。远端 Office/MCP/浏览器契约未验证，继续明确 unavailable。
- 不实现双向交接、跨设备能力切换或远端工具代理；分别留在 T39–T41。真实模型质量、真实外部账号和第二设备上的远程浏览器/MCP/Office 运行不在本票。

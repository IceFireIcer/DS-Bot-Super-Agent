## 已交付

### 1. 独立语义 Session 只产出判断，不执行动作

- 新增公开 `Supervisor`（`ds-superagent/supervisor`）和 `Engine.createSupervisor()` / `getSupervisorProposals()` / `getSupervisorState()`。
- `createSessionAssessor(sessions, { sessionId, version })` 使用**独立 Session id**、Router 模型路由和唯一的 `record_supervision` 工具；没有工作工具、Router 工具、审批、设备、投递或配置工具。Session 通过公开 DSH Agent loop 运行，测试使用 mock 模型，真实模型只需配置 Router 路由。
- 每次评估记录 `assessorVersion` 与 `model`；提案 `version` 默认带当前角色配置 revision（`supervisor-r<revision>`）。监督器没有修改角色、提示词、模型或其它配置的入口。

### 2. 对比目标、Mandate、报告、工具和交付，而不是只看进程

`Supervisor.inspect()` 读取 `getSupervision({includeHistory:true})` 和 `getTicket`/`getTicketDirection`，每个 Ticket 的 snapshot 包含：

- 原始请求、Mandate id/scope、direction version；
- Assignment id/generation、当前报告和报告历史、工具事实摘要、交付消息状态；
- job/subagent 状态、unknown effect/job、attention/stop/setup 状态、暂停/正常等待事实。

进度 fingerprint 包含请求、Mandate、Assignment、报告/工具/交付、方向版本和 job/subagent 变化。只改变目标或 Mandate 也算进展，不会被误报为停滞。

分类：

| 情况 | 结果 |
| --- | --- |
| attention waiting、设备/环境等待、stop、暂停、ready、ended | `normal-wait`/`ready`/`ended`，不评估、不提案 |
| unknown effect/job | `unknown`；先调用既有 `reconcileRemoteWork`（stop 中则 `reconcileStop`），把对账命令与结果写入 observation，绝不直接提案或重放 |
| 同一 fingerprint 达到观察阈值且超过时间窗 | `no-progress`，生成暂停提案 |
| 同一工具事实 fingerprint 重复达到阈值 | `loop`，生成暂停提案 |
| 语义 Session 判断报告/工具/交付偏离目标 | `deviation`，生成纠偏提案 |

### 3. 提案是持久事实，重复观察去重

- `supervisor-proposal` 记录：finding、完整 snapshot、assessment、recommendation、impact、version、fingerprint、创建/决定时间、决定人、决定命令、动作及动作结果/错误。
- `supervisor-observation` 记录：fingerprint 历史、提案时间预算、最后一次结果和历史（默认 50 条）。
- 每个 Ticket 同时最多一个 `proposed` 提案；相同 fingerprint 不重复创建；提案预算默认 2 次/6 小时，耗尽后记录 `budget-exhausted`，不重复通知。
- `getSupervision()` 的每个 Ticket 附带 `supervisorProposals`（当前 proposed），公开查询 `getSupervisorProposals`/`getSupervisorState` 可回查；聊天界面的批准/拒绝入口留 T55。

### 4. 批准前不执行，批准后只走既有授权命令

- `Supervisor.decide({commandId, proposalId, decision, reason})` 先用 command fingerprint + CAS 原子 claim `proposed → deciding`；并发决定只有一个能 claim，其余得到 `PROPOSAL_CLOSED`。同一 commandId 用于不同提案或改变决定/原因得到 `IDENTITY_CONFLICT`。
- 批准 `pause`：调用既有 `Engine.stopTicket`，记录 stop 的 bounded 结果/错误；这不是可逆的“暂停”，impact 明确说明需要显式 resume。
- 批准 `correct`：调用新增的 `Engine.correctTicket`，在 Ticket 上增加一个受授权的 **direction input**（`supervisor-correction`），Worker 在下一回合读取；监督器不执行工具、不直接改 Mandate。
- 拒绝：只记录 rejected、决定人/原因，不调用任何动作。
- 同一 commandId 重放返回原决定；动作命令使用派生 command ID（`:stop`/`:direction`），重放安全。动作失败仍保留 approved 决定，但 `action.status: failed` 和错误可见，不伪报成功。

## 使用方式

```js
import { createSessionAssessor } from 'ds-superagent/supervisor-session'

const supervisor = engine.createSupervisor({
  assess: createSessionAssessor(sessions, { sessionId: 'supervisor-private', version: 'prompt-v1' }),
  stallMs: 30 * 60_000,
  stallObservations: 3,
  version: 'supervisor-r1',
})

const report = await supervisor.inspect()
await supervisor.decide({ commandId: 'decision-1', proposalId: report.proposals[0].id, decision: 'approve' })
```

`inspect()` 只读并写提案/观察；`decide` 才执行已批准的 stop 或 correction。调度频率由调用方决定；`Supervisor` 不自行启动后台循环。

## 边界

- **没有运行真实模型语义评估。** 当前只有确定性检查、注入的测试 assessment 和真实 DSH Agent loop 的 mock 模型 Session；没有 API key/模型端点，不能宣称真实模型判断质量。真实模型只影响 `deviation` 判断，确定性 no-progress/loop/正常等待策略仍由代码约束。
- **没有聊天界面的批准/拒绝按钮。** 公开 `getSupervision().supervisorProposals`、`getSupervisorProposals`、`getSupervisorState` 和 `decide` 已提供入口，具体 UI 交互留 T55。
- **“Attention 提案”是 `supervisor-proposal` 事实，不写入既有 Attention 行。** 这样不会把一个监督提案伪装成 Worker 问题或改变 Worker 的输入链；提案在监督视图可见，但外部通知/信道投递未实现。
- **暂停动作是 `stopTicket`，不是可逆 pause。** 需要显式 resume；impact 已写明。纠偏是一个 direction input，不改变原 Mandate，也不直接唤醒正在结束的 Worker；Worker 在下一回合读取。
- **unknown 对账调用既有命令。** 没有 native runtime 时对账会失败并记录 `reconciliation.error`，不会静默当作已解决。
- **单实例假设。** 同一 Instance 同时运行两个 Supervisor 没有额外协调锁；`supervisor-proposal` 查询扫描上限 1000 条，超出后会漏掉更旧记录；提案/观察预算是每 Ticket 的，不是全局配额。
- **没有语义配置修改。** 规则/提示词/角色/模型修改属于 T49；Supervisor 只提案 stop/correct。
- 没有发布；没有等待 CI 结论。

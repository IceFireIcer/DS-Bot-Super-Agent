# T36：选择本地、远端或自动目标并固定执行绑定

- Issue：[T36 / #64](https://github.com/IceFireIcer/DS-SuperAgent/issues/64)。
- 实施基线：T35 提交 `b8d569f`。
- 规格：v2.1 D06、D14、D17、D19；A27、A29、A36；用户故事 79–84。

## 已交付

- 新增版本化 `ExecutionPolicy`，初始 revision 0 为 `defaultTarget: local`、`requiredPermissions: ['read']`。`Engine.getExecutionPolicy()` 查询；`Engine.updateExecutionPolicy({ commandId, expectedRevision, policy })` 使用 CAS、稳定 command ID 和持久历史。`preferredEnvironmentId` 必须是当前 Instance 与该 actor 已授权的 Environment。默认值变化只影响之后固定 Environment 的 Assignment。
- `submit` 与 `acceptSource` 接受 Ticket 级 `target: local-only | remote-only | auto`，并把实际 target 与来源（default/ticket/explicit）持久在 Trigger。`auto` 在 Mandate 中保留 `auto`，固定后只更新 Intent 的实际 kind，不再把未解析的 auto 伪装成 local。
- Assignment 只通过一个绑定入口创建：解析 Target、保存 selection、在第二事务复核 Ticket/Assignment 后固定 `EnvironmentLocation`。follow-up relay 在没有 Assignment 时走同一入口；等待中的 remote-only/auto 不创建 Host-local Assignment，也不偷偷使用本地工具。`retryTicket` 在 `environment-waiting` 时拒绝，用户先调用 `Engine.retryExecutionTarget({ commandId, ticketId })`。
- `remote-only` 无合格设备时保持 `environment-waiting`；selection 记录等待原因、每个候选的 online、能力、目录、版本、fingerprint、capacity 和不可用原因。设备恢复后 `retryExecutionTarget` 按稳定 command ID 重放安全：已完成的命令直接返回当前结果，未完成命令最多重新执行同一幂等绑定。
- auto 候选先做 Instance/actor allowlist 与 target kind 静态筛选；通过后必须有真实 `probe`。probe 由 LocalEnvironment 的稳定目录身份或 RemoteEnvironment 的 status 提供，要求 online、root 与配置一致、version/fingerprint 已知、required capability 存在、capacity 不是 unknown 且未满。缺失 probe、未知证据、目录不符、能力不足或容量满都成为不可选原因，不合成默认证据。候选探测有单个 5 秒上限，原因文本有界。
- selection evidence 持久为 `execution-selection`，通过 `conversation(ticketId).executionSelection` 和 `Engine.getExecutionSelection(ticketId)` 展示。记录 target、policy revision、来源、Host ID、最终设备/目录/version/fingerprint 与全部候选原因。Assignment 固定后，后续默认策略变化不会迁移在途工作，工具调用也没有换设备的参数。
- 固定 Assignment 在真正运行前重新验证 root/version/fingerprint；同一路径目录被替换后拒绝继续，而不是仅凭 ID/root 字符串复用。所有选择/retry/查询都校验原 source instance 与原 actor；不同 source 不能读取或重定向别的 Ticket。
- Remote status 扩展 version、设备签名 fingerprint 与 job capacity；远程协议及 Host saved connection state 升为 v3。v1/v2 saved state 明确拒绝。

## 边界

- 自动检测设备重新上线不是常驻轮询；用户显式调用 `retryExecutionTarget`，或已排队的 follow-up relay 在退避重试时再次解析。`remote-only` 等待期间不回落 Host。
- selection 逐个候选探测，每个最多 5 秒；没有并行探测池。大量离线设备会增加一次解析的等待时间，但原因和选择仍是有界的。
- auto 的 command 能力来自设备 status 的授权/能力事实，不额外执行命令做副作用探测；真正执行仍由后续 Worker 工具和 ready evidence 验证。
- 本票不迁移在途 Assignment，也不实现双向 handoff、跨 Host 共享后端或主动 Watchdog；这些分别留在 T37/T44/T42/T43/T45。模型端点与执行 Environment 独立，T36 不改变模型路由。

# 旧核心退出与历史导入决议

对应：[验证旧核心退出与历史导入的切换协议](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/10)。本项为 AFK task，依据既有只读导入、唯一消费和不重做旧派活的规格完成最小实验；不新增产品实现。

采用 `prepared → quiescing/quiesced → active` 的持久切换协议：

- 新目录中以来源身份/内容摘要/批次 ID 和显式对象映射准备只读历史；校验完成之前不可发布。重复批次幂等，摘要变化报冲突，失败不改原资料或覆盖既有目标。
- 角色与可共享记忆按明示映射导入，历史 Session 保留可读，新执行用新 Session 及历史引用；不把旧 Main Bot 权限和运行状态直接继承进新核心。
- 旧 works/requests/questions、inflight、live agents 不形成新执行队列。未完成、已停止与结果未知工作保留待核查，人工决定并核验当前授权后才建立新 Ticket。
- 停用旧消费和重启入口，确认调度、作业、外发静止，最终复核快照、来源游标与旧回执。旧 home 的 state.lock 不构成新 epoch fencing；旧核心不识别新库锁时必须物理停止/隔离相关入口。
- 切换空窗输入持久缓冲。旧、新系统使用稳定全限定输入 ID 和可核验接受回执去重；旧已接受或归属不明的请求不重新派发。来源无可靠 ID/游标/回执时，隔离边界输入并人工核查，不用时间戳推测。
- 在协调事务发布当前核心、activation manifest 与新 epoch，只有当前入口可写接受回执/Effect 意图。重启及提交应答未知按原 ID 对账。
- 激活前可放弃或经核验恢复旧入口；激活后须先停止新入口并对账副作用再逆向交接，不直接回滚二进制并重放旧队列。人工停止与原授权不被切换解除。

14 组原创 SQLite 检查通过，含 2 组负对照、两个真实子进程在 COMMIT 前后退出，以及第二连接拒绝旧代。旧消费者桥接、静止证明是模型前提，尚非真实 DS Bot/DSH/Windows 迁移验收，也不证明外部 exactly-once。详见研究分支的 `super-agent-references/analysis/wayfinder/legacy-cutover.md`、脚本与结果。

本协议落实既有 D18/A25；完整产品导入、权限映射、历史格式、真实新旧进程退出及恢复将在实施票中验收。用户原有 DSH 数据始终只读，本轮完全使用虚构临时资料。

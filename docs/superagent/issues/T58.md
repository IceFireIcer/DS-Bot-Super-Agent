# [T58] 组合托管 Host、断连撤销、接管与第二设备

## What to build

在获授权的托管服务器上部署真实 Host，使用共享 PostgreSQL 业务库与 Session 后端、TLS/认证客户端、唯一 Watchdog 和隔离状态目录；从桌面客户端连接并配对第二设备，组合验证关闭/断连、撤销、Host 接管、Watchdog 恢复、设备离线停止与双向执行交接。场景使用 T56 的 production factory、T59/T60 的 `ds-superagent` profile 与聊天界面，以及 T57 的真实模型/信道环境，不重新实现各领域行为。

## Acceptance criteria

- [ ] 托管 Host 实际运行在远程服务器，不是同机 loopback 或 embedded PostgreSQL；记录部署版本、唯一活动 Host/lease epoch、TLS/认证入口、共享业务库与 Session 后端、资产/状态目录和 Watchdog 身份（敏感值脱敏）。
- [ ] 桌面客户端关闭或断连不停止 Host；工作继续，重连后按游标补读结果且无重复；撤销客户端权限在下一次请求生效，旧凭据不能继续读取或发命令。
- [ ] 杀死或替换 Host 后，显式接管或 Watchdog 取得新 epoch，旧 Host/Assignment 回调被隔离；原 Ticket 在核查后继续，stop、waiting-human 和 unknown 不被绕过。
- [ ] 真实第二设备完成命令/文件任务；设备断连、离线 stop、重连不自启、同范围静止确认和明确 resume 均有证据；本地↔远端双向交接保留未提交/未跟踪内容，无双执行。
- [ ] 连续场景复用 T56 factory、T59/T60 profile/UI 和 T57 的真实模型/GitHub/飞书环境，并分别报告连续/高效/主动/持久四目标证据；mock 或组件替身只作为补充，不替代托管/设备真实结果。
- [ ] 不修改 `app/ui/`、`ds-bot/src/client/` 或 `ds-bot/client.js`；所有本轮服务、Host、Watchdog、设备进程、临时目录和外部测试资源停止并清理。

## Delivery requirements

- 本票是组合与部署验收票，不重新实现 Engine、Session、设备、交接或 Watchdog 领域行为；发现缺口时回到对应行为票或拆新票，不在本票内无边界扩展。
- 托管环境、真实设备、真实模型和真实信道必须有授权记录和隔离边界；服务器地址、令牌、配对码和租户信息只通过环境变量或受保护配置使用，不写入仓库或日志。
- 测试数据与用户数据分离；不得指向用户自有 DSH、桌面应用数据、生产数据库或生产飞书群。所有服务、进程、临时目录和外部资源在验证后停止或明确保留原因。
- 记录部署前后版本、手动/自动恢复动作、失败窗口和未覆盖项；不得把组件测试、同机 embedded 数据库或 loopback 设备结果合并成托管 Host + 第二设备验收。
- 界面行为只验证现有 `ds-bot` 后端协议和现有桌面客户端绑定；不新增 UI、不替换 renderer，UI 文件零改动。

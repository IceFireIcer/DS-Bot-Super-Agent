# [T56] 将生产 Engine factory 注入现有 ds-bot Host

## Parent

[T55 验收四目标的完整产品协作场景](https://github.com/IceFireIcer/DS-SuperAgent/issues/83)

总体行为与依据：[Super-agent v2.1](https://github.com/IceFireIcer/DS-SuperAgent/issues/1)。

## What to build

在不创建替代界面、不修改 `app/ui/`、`ds-bot/src/client/` 或 `ds-bot/client.js` 的前提下，把公开 Super-agent Engine 的 production factory 装配到现有 `ds-bot` Host/profile。`/api/bot`、SSE、session/chat、question、delivery 和 resume 继续使用现有协议形状；factory 负责 Engine、Session、Storage、Effects 与 delivery adapter 的启动、停止和替换。

## Acceptance criteria

- [ ] 每个 Bot/Session 有唯一 factory 所有权；同一 Session 的并发请求收敛到同一 Engine，启动幂等，停止/重启按序释放，不泄漏 Engine、Session、Effects 或后台进程。
- [ ] `/api/bot` 的 prompt、SSE、chat、question/answer、delivery、resume 响应形状与现有客户端契约一致；现有 backend seam 测试保持通过，unsupported group/browser/view/attachment/steer 继续 fail-closed。
- [ ] 一个真实 Host 进程（不是仅进程内测试）通过 factory 完成 mock 模型的 prompt、stop、resume 和 delivery；重启后从已持久化 Session 恢复。
- [ ] 配置来源、启动失败、未配置和 fallback 行为明确：不静默回退旧核心，不以本地假 delivery 冒充成功；错误在现有 Host 状态或日志中可见。
- [ ] 不修改 UI 文件；`app/ui/`、`ds-bot/src/client/`、`ds-bot/client.js` 的 diff 为空。真实模型/信道、托管部署和第二设备组合留给 T57/T58。
- [ ] 单测、类型检查、lint、`ds-bot` smoke 与 factory 生命周期测试通过；记录实际命令、结果和未覆盖边界。

## Delivery requirements

- 本票只交付 production factory 装配和现有 Host 协议接入；真实模型、真实 GitHub/飞书、托管服务器和第二设备组合分别由 T57、T58 交付，不能在本票内用 fixture 或本地回环冒充。
- 只用 DSH 公开 API 和现有 `ds-bot` 后端协议；不新建 renderer、替代桌面表面或第二套前端。UI 文件零改动。
- 配置从现有 profile/环境读取，凭据不写入仓库、日志或测试；缺少配置时明确失败，不静默回退旧核心。
- 测试使用隔离数据、mock 模型和空闲端口；不在 `~/.dsh`、用户桌面数据或用户运行中的 DSH 上操作。本轮启动的 Host、Session、Effects 和进程必须停止。
- 完成必要的单测、类型检查、生成一致性、lint 和适用 host smoke；记录真实 Host 进程证据与未覆盖边界，不把进程内适配器测试当作生产装配完成。

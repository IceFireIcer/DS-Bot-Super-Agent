# [T18] 按消息用途可靠发送并呈现真实回执

<!-- dsbot-plan:v2.1:T18 -->

## Parent

[[Feature G04] 持久化与故障恢复](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/18)

总体行为与依据：[Super-agent v2.1](https://github.com/IceFireIcer/DS-Bot-Super-Agent/issues/1)。

## What to build

用户收到合法确认、回答、问题和结果；发送重试或不可达时能看到真实回执且不会刷屏。

## Acceptance criteria

- [ ] acknowledgement/answer/result/attention 分别核查依据、当前问题与回复目标；普通 progress 不发送，Worker 受控确认走同一通道。
- [ ] pending/sent/dropped 如实查询，临时关闭等待，永久不可达记录原因；不随意改投、广播或泄露其他信道内容。
- [ ] 原平台已收但应答丢失按幂等键/marker/查询对账，未知局部受阻并有界查证，不能宣称成功或盲目重发。
- [ ] 同任务尽量确认先于结果，错误不无限阻塞其他任务；重复问题去重，重试/通知预算和负对照可验证。

## Delivery requirements

- 每票交付一种可演示或可由公开命令/查询验证的行为；相应持久事实、接口、最小用户入口和测试随行为交付。基础票先扩展独立新核心入口，正式切换留到迁移票；不会在前期同时消费旧核心的生产输入。
- T01 是必要的最小装配与扩展前置，交付可查询的持久接单回执；T02 形成第一条真实 DSH mock 模型闭环，T03 增加实际本地工具执行。不会先建完数据库层、再建完整服务层、最后补全部界面。
- 每票按一个新上下文内的一项行为限定范围。验收只扩展本票行为及已有依赖，不要求提前完成后继票；跨阶段场景拆成各票的可验证部分，最终由 T55 汇合。发现实际范围超出时先拆票，不能用未实现后继作为完成理由。
- 前置仅列直接阻塞；发布时使用总规格 → 功能父票 → 实施子票的原生层级，T54/T55 直接属于总规格，使用 GitHub 原生 blocked-by，发布顺序为拓扑顺序。所有实施票使用 ready-for-agent，规格仅通过已授权的审计补充修订为 v2.1；拆票阶段不再修改或关闭父规格。
- D/A 编号引用父规格的实施决定与验收场景，用户故事编号引用其 User Stories。覆盖表示计划承担相应部分，不表示现有实现或运行验收已经通过。
- 公共完成条件适用于每票：只用 DSH 公开 API；不读取或写入用户自有 DSH 数据进行测试；使用 mock 模型及隔离数据、空闲端口，停止本轮服务；移植兼容许可代码时记录来源与 NOTICE；产品文案源语言为英文。
- 各票通过公开 Engine 行为及适用的来源/存储/Session/执行契约验证；完成必要的单测、类型检查、生成一致性、lint 和适用的 host smoke。界面行为同时提供真实界面证据；原生/真实模型/外部信道/第二设备验收分别报告。未经验证的工具组合明确拒绝。
- 初始公共存储合约支持显式异步 Tx、稳定 ID 和后端替换；每次 schema 或命令扩展同步维护已经实现的后端及契约，不能把后续行为遗留为仅 SQLite 可用。T42/T43 无需等全部业务票完成才开始。
- 网络账号、真实模型、第二设备和托管环境是对应验收的运行前提，在实施相应票时收集授权与配置。协议替身可用于开发，不能据此关闭要求真实环境证据的验收项。
- 超时、重试、容量及资源预算在对应票的声明负载下实测并记录，不能无限重试，也不能照搬文章或早期实验数字；T54 汇总比较，不能替代各票当时的预算验收。
- 每张实施票只有一个功能父票；父票完成需全功能验收，子票可引用其他功能的具体前置。不把整个功能父票作为子票阻塞方；跨功能 group 可能有双向引用，不能转成整组串行。

# [T59] 新增 ds-superagent profile 并接通现有聊天界面

<!-- dsbot-plan:v2.1:T59 -->

## Parent

[T55 验收四目标的完整产品协作场景](https://github.com/IceFireIcer/DS-SuperAgent/issues/83)

总体行为与依据：[Super-agent v2.1](https://github.com/IceFireIcer/DS-SuperAgent/issues/1)。

## What to build

在桌面应用中新增独立 DSH profile `ds-superagent`，与现有 `ds-bot` profile 并存。新 profile 只通过公开 bundle/profile 入口装配 DSH base/web、公开 Super-agent Engine、`ds-superagent/ds-bot-host` 和现有 `ds-bot` 聊天界面，并用 `executionAdapterRequired: true` 强制走新 Engine。

本票只证明“现有前端 → production Engine”的 seam：一个 1:1 聊天可以提交、确认、返回结果、停止、恢复，并在 Host 重启后继续。前端文件和旧 profile 保持零改动。

## Acceptance criteria

- [ ] 应用可以通过显式启动配置选择 `ds-superagent` profile；未设置时仍启动原有 `ds-bot` profile，两个 profile 的目录、数据库和 Session 数据互不覆盖。
- [ ] `ds-superagent` profile 使用公开 `profile-boot`/bundle 入口启动，不修改 DSH 安装，不 import DSH 内部深路径。
- [ ] 现有聊天界面通过 `botExecutionAdapter` 完成一条 mock 模型消息：提交后可见确认，Worker 完成后可见结果，证据和 Session 引用可展开。
- [ ] stop 在当前工作中生效并持久；显式 resume 继续同一 Ticket；Host 重启后同一 Session/Ticket 可继续，不重复建工作。
- [ ] 缺少数据库路径、模型 route 或 Host 服务时明确失败，不静默回退旧核心，不使用本地假 delivery。
- [ ] `app/ui/`、`ds-bot/src/client/` 和 `ds-bot/client.js` 的 diff 为空；`ds-bot` 现有测试与 `ds-superagent` 定向测试通过。
- [ ] 测试使用隔离 `DSH_HOME`、临时 SQLite、mock 模型和空闲端口；本轮启动的 Host、Session、Effects 和进程全部停止。

## Delivery requirements

- 本票只交付 profile 切换和现有 UI 到 Engine 的装配；不复制前端、不新建 renderer、不替换桌面壳。
- 只使用 DSH 公开 API 和现有 `ds-bot` 后端协议；不修改 `deepseek-harness`，不把 profile 补丁写进 DSH 安装。
- 新 profile 使用应用自有 `DSH_HOME` 下的独立目录；不读取或写入 `~/.dsh`、用户桌面数据或用户运行中的 DSH。
- 配置从 profile/环境读取；凭据不写入仓库、日志或测试输出。缺少配置时明确失败，不静默回退旧核心。
- 记录实际启动命令、profile 路径、数据库路径、Ticket/Session 身份、退出码和清理结果；未覆盖的真实模型、外部信道、托管和第二设备边界明确写出。
